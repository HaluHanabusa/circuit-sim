# 数値モデルの検証

このシミュレータの結果は設計判断に使われる。「動いた」ではなく「合っていると示せる」ことが完了の条件。

## 検証の段

上から順に、適用できるものをすべて行う。最低でも1〜3のうち1つと、6は必須。

| 段 | 何を確かめるか | 例 |
|---|---|---|
| 1 解析解 | 手で解ける場合と一致する | RC・RLCのステップ応答、降圧コンバータの定常値とリプル、不連続導通の変換比 |
| 2 保存則・整合 | 物理の決まりを破っていない | 節点の電流の和がゼロ、エネルギーの収支、切り替え点で状態量が連続 |
| 3 収束次数 | 刻みを半分にしたとき誤差が理論どおり減る | 台形則なら約1/4、後退オイラーなら約1/2 |
| 4 モデル間の一致 | 精度の違うモデルが、同じ条件で同じ答えに近づく | スイッチングモデルの周期平均と平均モデル |
| 5 極限と角 | 極端な条件で壊れない | 定数の桁が大きく違う、境界のデューティ、無負荷、解けない回路 |
| 6 再現性 | 同じ入力から同じ結果が出る | 2回実行して完全一致、乱数はシード固定 |
| 7 速度 | 遅くなっていない | 基準の回路でのステップ数あたりの時間を記録 |

## 許容差の決め方

- 先に決めてから測る。測った結果に合わせて決めない。
- 根拠を書く。例: 「台形則で1周期200分割なら理論誤差は約0.01%なので、1%は実装の誤りを見逃さない範囲で十分に緩い」。
- 相対誤差の分母は、信号の代表的な大きさ（入力電圧、ピーク電流など）にする。ゼロに近い値で割らない。
- 既存の基準: 解析解との差1%以内、モデル間の周期平均の差2%以内（`docs/plan/roadmap.md`）。

## テストの書き方

- 期待値は実装と独立に作る。実装と同じ関数や同じ式の写しで期待値を作らない。解析解はテストの中に式で書く。
- 失敗すべきときに失敗することを一度確かめる（定数を1割ずらした参照と比べて、大きな誤差が出るか）。
- 1つのテストは1つのことを確かめる。名前で何を確かめているか分かるようにする。
- 定常値を比べるときは、過渡が十分に収まった区間だけを使い、その区間の決め方を書く。
- 周期平均は、スイッチング周期の整数倍の区間で取る。

## 置き場所

- 単体と解析解の照合: `tests/`
- 作業単位の受け入れ試験（検証担当が追加）: `tests/acceptance/`
- 検証の記録（基準、実測値、測り方、合否）: `docs/verification/<ID>-<担当名>.md`（1回の検証ごとに新しいファイル。既存の記録は書き換えない）
- 速度の計測: `benchmarks/`

## よくある落とし穴

- 台形則は硬い成分（オフ抵抗を通るインダクタ電流など）を減衰させない。切り替え直後に数値振動が出たら、その直後だけ後退オイラーにする。
- 切り替えの時刻は時間刻みに丸められる。デューティの分解能は「1 / 1周期の分割数」。平均値の比較ではこの分を見込む。
- 電源や状態が不連続に変わる点では、状態量以外の変数を合わせ直す（`kernel.py` の整合処理）。
- 平均モデルとの比較は、連続導通のときだけ成り立つ式を不連続導通に当てはめない。
- 速度の基準は環境で変わる。合否ではなく記録として扱い、桁で悪化したときだけ問題にする。
