## 見つけた問題

### 1. 重大: 別のサイトのページから、開いている仕様を差し替えられる（宣言した依存の範囲で）

- 内容: サーバーは Origin も Sec-Fetch-Site も見ていない。いまの環境で防げているのは、入った FastAPI 0.163.1 が
  Content-Type の無い本文を JSON として読まない（`strict_content_type`、0.132.0 から既定で有効）ためだけ。
  `pyproject.toml` は `fastapi>=0.115` を許すので、0.115〜0.131 が入った環境（既存の環境に入れた場合など）では、
  利用者が開いただけの別のサイトのページが、開いている仕様を書き換えられる。保存していない印（dirty）も消えるので、
  Ctrl+C の確認（未決11）も働かなくなる。値を書き換えた仕様で設計判断をさせられうる。
- 再現（実際の Chrome で確認）:
  1. `pip install ./写し "fastapi==0.115.0"` で入れ、`circuit-sim --no-browser --port 18766`
  2. `curl -X POST -H 'Content-Type: application/json' -d '{"sample":"rlc_series"}' http://127.0.0.1:18766/api/open`
  3. 別の番号（`http://localhost:18799/`）に、次を実行するだけのページを置いて開く:
     `fetch("http://127.0.0.1:18766/api/open", {method: "POST", mode: "no-cors", body: new Blob([JSON.stringify({file: "evil.json", text: <Vin=999 V の仕様>})])})`
  4. `GET /api/session` の `doc.file` が `evil.json` に替わる（fastapi 0.163.1 では替わらない）
- 想定される原因と直し方の案: 状態を変える要求で Origin（無ければ Sec-Fetch-Site）を見て、127.0.0.1 / localhost の
  同じ番号以外を 403 にする。あわせて `fastapi>=0.132` に上げる。試験は
  `tests/acceptance/test_a0_server_safety.py::test_cross_site_protection_does_not_depend_on_the_installed_fastapi`（xfail）。

### 2. 基準不適合（AC-1-1）: 長いファイル名でヘッダーの②が欠ける

- 内容: ファイル名を 40 文字で中ほど省略した後、さらに②の最大幅 320 px で末尾を CSS で切っている。
  英語で 31 文字（`buck_converter_rev12_final.json`）、日本語で 37 文字（`motor_drive_inverter_rev3_review.json`）以上で、
  拡張子が消え（`buck_converter_design_review…mme…`）、テンプレート名も「直列…」「Series …」に欠ける。
  design-system 4.2「ファイル名だけは中ほどを省略し、拡張子を残す」、AC-1-1「欠けず」に反する。12 通りすべてで起きる。
- 再現: 1280×720 で、上の名前のファイル（中身は `examples/rlc_series.json`）を「ファイルを選ぶ…」で開く。
- 想定される原因: `Header.tsx` の `middleEllipsis(name, max = 40)` が文字数で省略し、幅を見ていない。
- 試験: `test_a0_browser_checks.py::test_long_file_name_keeps_extension_and_template_name`（xfail）。
  実装の試験（`test_eight_combinations_start_and_frame`）は `rlc_series.json` でしか測っていない。

### 3. 軽微: フォーカスが body に落ちる（3.4、AC-1-5）

- サンプルの行を Enter で開くと、行が消えてフォーカスが body に落ちる。3.4 は「開いた後、フォーカスが『実行』にある」。
  実行そのものは A1 だが、フォーカスの置き場所は A0 で確かめられる。
- お知らせの行で Delete を押して閉じると、フォーカスが body に落ちる。
- 再現: 起動直後の画面で Tab でサンプルの行へ → Enter → `document.activeElement` が body。
  枠を開いた状態で壊れた JSON を開く → お知らせの行にフォーカス → Delete → body。
- 試験: `test_focus_is_on_run_after_opening_a_sample_with_the_keyboard`、`test_focus_stays_visible_after_dismissing_a_notice`（xfail）。

### 4. 軽微: 数値と単位の間が改行される空白（AC-2-6、design-system 4.2）

- 辞書の `sample.rlc.desc`（日英）など、数値と単位の間が U+0020。英語の 1280×720（と 150%）では説明が2行に折れ、
  「1.59」と「kHz」が別の行に分かれる。3.2 の「右に1行の説明」とも違う。辞書は画面仕様の表から作っているので、
  表の側（ux-designer）か、辞書を作る道具（`strings_from_spec.py`）で U+00A0 にする必要がある。1行に収めるか
  （省略すると数値が欠けうる。4.2 は数値の省略を禁じている）は ux-designer の判断。
- 試験: `test_sample_description_keeps_number_with_unit`（xfail）。

### 5. 軽微: 直書きを検出する実装の試験の見逃し（基準6の試験の実効性）

- `tests/test_app_strings.py` に直書きを1つずつ仕込んだ結果、16 通り中 9 通りが通った:
  括弧・疑問符・コロンを含む JSX の英語の文（`<span>Error: cannot open</span>` など）、JSX の式の中の文字列
  （`{"Open"}`）、変数に入れた文字列、属性を式で書いた文字列（`aria-label={"Dismiss"}`）、短い一覧に無い色の名前
  （`crimson`）、システム色（`CanvasText`）、style の中の色（`color: "white"`）、SVG の `fill="black"`。
- いまのソースには、これらの形の直書きも無い（確認済み）。補う試験を追加した（静的: 15/16 を検出、残る
  「変数に入れた文字列」は、画面に出た文字の走査で検出することを、仕込んでビルドし直して確かめた）。

### 6. 軽微（design-system、ux-designer へ）: 暗の「赤」（wave-5）の1型のコントラストが 3:1 の境

- Machado 2009 の行列を線形 RGB に掛けた色のままで計算すると 2.988（基準 3）。変換後の色を 8 ビットに丸めると
  3.013 で、design-system 3.2 の表の値（3.01）はこちら。実装の試験（`test_app_design_tokens.py` の `simulate`）は
  「丸めないと暗の赤の1型が 2.99 になる」と注記して丸めている。どちらの計算も筋は通るが、余裕が 0.4% しかなく、
  計算の流儀で合否が変わる。A0 の画面には波形が無いので A0 の合否には影響しない。色を少し明るくするか、
  3.2 に「8 ビットに丸める」を書き足すかを ux-designer が決めるとよい。

### 観察（問題としない）

- 起動し直すたびに N-CONN-RESTART が1件ずつ増える（8 回で「注意 8」）。出来事のお知らせなので仕様には反しない。
- `/api/open` は 30 MB の本文も受け付ける（画面の側は 10 MB で止める）。このPCの中からだけなので問題としない。

## テストの実効性についての所見

- 安全: 実装の試験は Host の偽装だけを見ていて、別サイトの要求、範囲外の道、待ち受けの番地を見ていない。
  追加した試験は、0.0.0.0 で待ち受ける・Host を何でも許す・静的ファイルの範囲を広げる・FastAPI 0.115.0、の
  それぞれで落ちることを確かめた。
- 画面の8通り: 実装の試験の測り方（`tests/data/measure_layout.js`）は欠けを拾える作りだが、短いファイル名でしか
  測っていないので問題2を見逃した。
- 色のトークンとコントラスト: 実装の試験は表の値と CSS を照合し、式を自分で持っていて実効的。期待値を design-system
  から読み、CSS から作っていない点もよい。波形の b だけは丸めの流儀で通している（問題6）。
- 数値の部品: 実装の部品の試験（vitest）は check.py の中で実際に流れている（Node.js がある環境）。私の 87 件とも
  食い違いは無い。
- 画面のビルド結果とソースの一致: check.py の中で一時フォルダにビルドして比べている（再現性の確認を兼ねる）。

## 追加した試験（新しいファイルだけ。既存の試験・記録・製品のコードは変えていない）

- `tests/acceptance/test_a0_server_safety.py`（ブラウザ不要）: 待ち受けの番地、Host の偽装 6 通りと対照、
