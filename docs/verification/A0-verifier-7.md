### 3. 中（文書）: 設計書 8.5 の「コンソールで BROWSER にコマンドを指定した起動」の手順は、Windows では必ず失敗する（レビューの中3 と同じ。こちらでも独立に見つけて再現した）

- 内容: 手順のコマンド `set BROWSER=python -c "import sys,pathlib;pathlib.Path('opened.txt').write_text(sys.argv[1])" %s`
  は、Python の文の区切りに `;` を使う。Windows の `webbrowser` は BROWSER を `os.pathsep`（Windows では `;`）で
  区切って、いくつかの候補として読む（CPython 3.13.2 の `Lib/webbrowser.py` 557 行
  `userchoices = os.environ["BROWSER"].split(os.pathsep)`）。
- 再現（Linux で、CPython 3.13.2 の `webbrowser.py` を読み込み、`os.pathsep` を `;` にして、起動は控えるだけ）:
  BROWSER は `python -c "import sys,pathlib` と `pathlib.Path('opened.txt').write_text(sys.argv[1])" %s` の
  2 つに分かれる。1 つ目は（名前に空白を含む1つのプログラムとして）起動に失敗し、2 つ目は `shlex.split` が
  `ValueError: No closing quotation` を出す。`webbrowser.open` は例外で終わり、アプリ本体は「ブラウザを開け
  なかった」と案内する。opened.txt はできない。
- 影響: PO が手順どおりに確かめると、「コンソールで、BROWSER のコマンドが始まれなかった」と誤って記録する
  （8.3 の未確認の項目を、誤った結論で埋める）。製品の動きには関係しない。
- 直し方の案（直すのは実装者）: `;` を使わない形にする。例:
  `set BROWSER=python -c "__import__('pathlib').Path('opened.txt').write_text(__import__('sys').argv[1])" %s`
  （同じ再現で、1 つの候補のまま `['python', '-c', '…', '<場所>']` で起動される）。BROWSER が Windows では `;` で
  区切られることを書き添える。手順はコマンド プロンプトで打つもので、バッチファイルに書くなら `%s` は `%%s` に
  なることも書くとよい。
- 受け入れ試験: `test_a0_fix7_procs.py` の 4（手順のコマンドが場所を書くこと、と、`;` で分かれないこと。
  後者は xfail(strict)。直ると XPASS で落ちて知らせる）。**PO に 8.5 を手で確かめてもらう前に直すこと。**

### 4. 軽微（説明・文書）: 「止まっている親の子の番号は、使い回されない」に条件が書かれていない（レビューの軽微2 と同じ所）

- 所: `tests/app_procs.py` の `kill_posix_tree` の説明、設計書 8.4。
- 実測（上の (c-2)）: 親が SIGCHLD を SIG_IGN にしていると、止まっていても子は片付けられて番号が空く。SIGSTOP は
  送ってすぐには効かない（最大 234 µs）。いまの試験が起動するものには当たらないが、言い切りになっている。
- 直し方の案: 条件（親が SIGCHLD を無視していない、一時停止が効いた後、ほかの者が親を止めない）を書く。

### 5. 軽微（文書・説明）: PeekNamedPipe が「すぐ戻る」条件を、資料の事実のように書いている（レビューの軽微4 と同じ所）

- 所: 設計書 8.3 の対策の 1 つ目「調べる呼び出しは、同じパイプをほかに読んでいるものが無ければすぐ戻る（資料:
  Microsoft の文書 PeekNamedPipe）」、`cli.py` の `windows_pipe_ready` の説明の終わり「上の場合を除いてすぐ戻る」。
- Microsoft の文書が書くのは「1 つのスレッドのアプリケーションでは、いつもすぐ戻る」と、注記「複数のスレッドの
  アプリケーションで同期のハンドルに使うと、ほかの入出力と同じように待つことがある」まで。アプリ本体は複数の
  スレッドなので、「ほかに読んでいるものが無ければすぐ戻る」は、同期のハンドルの操作が1つずつになること（Raymond
  Chen の記事）からの推定。8.3 の「残る制限」の項目は、推定と未確認を分けて書けている。
- 直し方の案: 1 つ目の項目の「（資料: …）」を、文書の文言と推定に分ける。
