### 進み具合（基準3、修正1）

- **済んだ計算に対する先回り**: 配列を埋めるあいだ、進み具合は「済んだ格子点の値」から「次の確かめの点と、埋めている区間の終わりの早いほう」との中ほどまで進む。実測の先回りは最大 0.0031（`SETUP_BLOCK` 64、制御周期 2000 ステップ、30 万ステップ: 制御周期の半分 = 1000 ステップ分）。既定の設定では 0.0029 以下。

### CSV と注意のファイル（基準7、D-075、D-076、修正2）

コマンドラインを別のプロセスで呼び、できたファイルをバイト単位で読んだ（63 項目）。

- **形**: 行数 = 1 + サンプル数（302）。`#` の行なし。どの行も CR LF（裸の LF、裸の CR なし。最後の行も改行で終わる）。BOM なし。見出しは `t [s],v(out) [V],i(L1) [A]`。標準の `csv`、`numpy.loadtxt`（見出しを飛ばすだけ）、pandas の既定の読み方（全部の列が float64）で読め、値は倍精度のまま往復する。

  - その名前が**フォルダ**なら、消さない（中身も残る）。理由を 1 行で出して終了コード 2（注意の無い計算は「消せません」、注意のある計算は「書き出せません」）。CSV は書けている。
  - その名前が**シンボリックリンク**なら、リンクだけを消す（先のファイルもフォルダも残る。先の無いリンクも消す）。
  - **読み取り専用のファイル**（別の利用者で確かめた）: フォルダに書き込めれば、Linux では消える。フォルダに書き込めなければ、消せずに終了コード 2（1 行。「今回の CSV の注意ではないので、手で消してください」）。Windows では、読み取り専用のファイルは消せないはず（未確認）。
  - **道具が書いたものかどうかは見ない**: 利用者が自分で書いた同じ名前のファイルでも、消す（注意のある計算では、同じ名前を置き換えるのと同じ扱い）。
- **CSV の書き出しに失敗したとき**（場所が無い、名前が既にあるフォルダ、`""`・`.`・`..`・`/`、`/proc` の下、`/dev/full`、読み取り専用の既にある CSV）: どれも、理由を 1 行で標準エラーに出して終了コード 2。Python の例外の表示にならない。**古い注意のファイルには触らない**（消さない、書き換えない。食い違いは起きない）。計算できない仕様（値の不足）では、既にある CSV と注意のファイルはそのまま。
- **書いている途中の失敗**（ファイルの大きさを 4 KiB に制限して確かめた。空きが無くなったときの代わり）: 終了コード 2 で 1 行。前の CSV は、途中までの CSV（17702 → 4096 バイト）に置き換わり、前の注意のファイルは残る（軽4）。
- **`to_csv` の引数**: 引数は `(path, names=None, *, units=False, newline="\r\n")`。`newline` に `"\r"`、`""`、`"\n\r"`、`None`、`1`、`b"\n"`、`True` など 11 通りを渡すと、どれも `ARG_CSV_NEWLINE`（`ValueError` の一種。日英の文あり）で、既にあるファイルは壊れず、新しいファイルもできない。無い信号の名前は `RESULT_NO_SIGNAL`（`KeyError` の一種）で、ファイルに触る前に断る（`units` が真でも偽でも）。無くなった `notes=True` は `TypeError`。
- **端末の文字コード**: cp932 と ascii の端末で、日本語・µ・Ω・→・é を含むファイル名でも落ちず、ファイルは正しい名前でできる。UTF-8 でないバイト列のファイル名（Linux）でも同じ。端末に出る場所の文字は、表せないものが置き換わる（`µ` → `u`。E0 からの作り）。
- **D-075・D-076 との食い違い**: 無い。(1) 見出し 1 行とサンプルの行だけ、(2) 注意は `<CSV の名前>.notes.txt` に UTF-8・1 行 1 件・番号つき、無ければ書かない、書いたことを端末に出す、(3) CR LF、`to_csv` の改行の引数、D-076 の名前 2 つ。D-075 の (4)（利用者向けの文書）は R1 の仕事で、設計書 15.3 に書いてある。

### 極端な値とあふれ（基準12、修正3・4）

- **極端な値の掃引**（1回目と同じ 656 通り。テンプレートの項目を 1 つずつ 0、負、5e-324〜1.7e308、inf、nan に替える）を、直す前と後で流して、仕様ごとに突き合わせた。
  - Python の口: 656 通りとも、終わり方（計算できた 268、番号つきのエラー 223、pydantic の検証 140、番号の無い例外 25）と文が同じ。**番号の無い例外は増えていない**（25 通りは、1回目の軽6 と同じもの。E1g の前から）。

  - 警告の出る仕様: 23 → 20。
- **`python -W error` の本物のプロセス**: Vin = 1.7e308 V の RC と降圧の状態平均化は、終了コード 2 と 1 行（発散のエラー）。
- **残る警告が 1 つある**（軽5）: 降圧のスイッチングモデルで Vin = 1.7e308 V。計算の準備で、区間の中点の値を `0.5 * (u_start + u_end)` で作る所（`simulate.py` 1275 行）があふれて、警告が出る（`python -W error` では traceback で終了コード 1）。準備は、警告を止める範囲の外。Vin が倍精度の上限の半分（約 9e307 V）を超えるときだけ。8e307 V と 1e300 V では出ない。

### `np.errstate`（修正4）

- **呼び出し側の設定が必ず戻るか**: 終わり方 10 通り（普通に終わる（スイッチあり・なし）、発散（大きさ）、あふれ（スイッチあり・なし）、制御器の指令が NaN、制御器が例外を出す、中断（スイッチあり・なし）、`progress` が例外を出す）× 呼び出し側の設定 4 通り（numpy の既定、全部 raise、全部 ignore、call と print の混ざったもの。`np.seterrcall` も）の 40 通りで、`np.geterr()` と `np.geterrcall()` が、計算の前と同じ。numpy の警告は 1 つも出ない。終わり方は、設定によらず同じ（直す前は、全部 raise の設定で、あふれが `FloatingPointError` になった）。
- **止める範囲**: 呼び出し側が全部 raise のとき、制御器の `step()` の中の設定は `{divide: raise, over: ignore, under: raise, invalid: ignore}`。止めているのは、あふれ（over）と無効の演算（invalid）だけで、0 で割る（divide）と下あふれ（under）は呼び出し側のまま。実装者の主張のとおり。
- **制御器の中の本当の誤りが隠れないか**（numpy の数で計算する、自作の制御器。エンジンの口だけ）:

  | 制御器の中の誤り | 直す前 | 直した後 |
  |---|---|---|
  | 1/0 を指令にする | 警告 ＋ `CONTROLLER_COMMAND_NOT_FINITE` | 同じ |
  | 1/0 を計算して、指令には使わない | 警告（周期ごと） | 同じ |
  | 0/0 を指令にする | 警告 ＋ `CONTROLLER_COMMAND_NOT_FINITE` | 警告なし ＋ `CONTROLLER_COMMAND_NOT_FINITE` |
  | 0/0、√(−1) を計算して、指令には使わない | 警告（周期ごと） | **警告なし**（結果が返る） |
  | exp(1000) を計算して、上限で止める | 警告（周期ごと） | **警告なし**（結果が返る） |

  0 で割る警告は隠れない。無効の演算とあふれは、指令まで届けば番号つきのエラーになるが、届かなければ、直す前に出ていた警告が出なくなる（軽2）。テンプレートの制御器（`control/blocks.py` の PID）は numpy を使わない（`math` だけ）ので、関わらない。
- **計算の値**: 呼び出し側の設定（既定、raise、ignore）を変えても、結果はビット一致（受け入れ試験）。
- **出入りの時間**: 1 回 1.5 µs（この機械、負荷あり。設計書は約 0.7 µs）。1 回の計算に 1 回だけ。
