## 見つけた問題

### 1. 軽微（試験の部品）: `os.kill` の中から出る例外では、一時停止したものが残る（レビュー 8回目の軽微1 と同じ所。SIGKILL の途中の場合を足した）

- 所: `tests/app_procs.py` の `kill_posix_tree`。
  - root の SIGSTOP（199〜201 行）が `try` の外。子の SIGSTOP（214〜218 行）は、送った後で `stopped` に控える。
  - `finally` の SIGKILL の繰り返し（219〜224 行）の途中で例外が出ると、残りに SIGKILL が送られない。部品の説明は
    「後始末（finally の SIGKILL）の最中に、さらに例外（3 回目の Ctrl+C など）が入ったとき」と書くが、`finally` は
    例外の無いふつうの道でも通るので、**最初の 1 回の例外でも**起こる。
- 例外がそこで出る理由（実測）: CPython の `os.kill` は、合図を送った後に、待っている合図を処理する。Python 3.13.18
  で、自分に Ctrl+C を立ててから（`ctypes` の `raise(SIGINT)`。間に Python のフレームを挟まない）、印つきの自分の子に
  `os.kill(子, SIGSTOP)` を呼ぶと、3 回とも、子は状態 T になり、`os.kill` は KeyboardInterrupt を出した。後始末の
  最中の Ctrl+C は、`os.kill` の中から KeyboardInterrupt になりうる。
- 再現（本物の合図は送らない）: 存在しえない番号の木（root、子 A・B、B の子 C）と、控えるだけの `os.kill` で、
  呼び出しの位置ごとに例外を差し込んだ（`/tmp/a0-verify8/exp/window/run.py`）:

  | 例外の位置 | 8aea404 で一時停止のまま残るもの | 7ea8d62 |
  |---|---|---|
  | 1〜3 回目の一覧 | なし（7回目の中1 は直った） | 1〜4 個 |
  | 1〜4 回目の SIGSTOP を届けた後 | その 1 つ（root、A、B、C） | 1〜4 個 |
  | 1〜3 回目の SIGKILL を届けた後 | 残りの 3・2・1 個 | 同じ |
  | 4 回目（最後）の SIGKILL の後 | なし | なし |

- 影響（実測と見込み）: 隙は `os.kill` の呼び出しの数マイクロ秒で、後始末の最中に試験のプロセスへ Ctrl+C が届いた
  ときだけ。残ったものがどうなるかを、印つきの自分のプロセスだけで確かめた（`/tmp/a0-verify8/exp/orphan/`。試験の
  プロセスの身代わりは新しいセッションの先頭）:
  - 見張りが一時停止のまま、本体が止められた: 見張りは自分で終わる（見張りのまとまりが孤立し、カーネルが SIGHUP
    （見張りは無視）と SIGCONT を送る）
  - 新しいまとまりの本体が一時停止のまま、試験のプロセスが終わった: 命綱の見張りが止める
  - **ふつうの起動が一時停止のまま、試験のプロセス（セッションの先頭）が終わった: 2 秒後も状態 T で残る**
    （セッションの先頭が終わるときは、孤立の規則が働かない）。ハーネスが時間切れや中断でまとまりごと止めれば止まる。
    端末から確認を流したときは、確認が終わってまとまりが孤立したときに SIGHUP と SIGCONT で終わる見込み（確かめて
    いない）
- 受け入れ試験: `test_a0_fix8_procs_browser.py` の `test_an_interrupt_surfacing_from_os_kill_leaves_nothing_stopped`
  （7 通りが xfail(strict)。最後の SIGKILL の後の 1 通りは比べのために通る）。
- 直し方の案（直すのは実装者）: 控えてから送り、失敗したら外す（root も `try` の中へ。レビューの案と同じ）。
  `finally` の SIGKILL は、途中の例外を控えて全部に送ってから、控えた例外を出し直す。この形を写しに入れると、
  xfail の 7 通りが XPASS になり、ほかの試験は通る（下の「テストの実効性」の M7）。直さないなら、部品の説明の
  「さらに例外」を「最初の例外でも」に直し、SIGSTOP の直後の隙も「止められないもの」に書く。

| M2 一時停止が失敗した番号にも SIGKILL | 落ちる（最初は見分けられなかった。身代わりが、終わっていた孫を一覧から外していたため。一覧に載せて ESRCH を返す形に直した） |
| M3 親から先に SIGKILL | 落ちる |
| M4 一時停止のたびにすぐ SIGKILL | 落ちる |
| M5 root を一時停止する前に一覧 | 落ちる |
| M6 木の外（隣の番号）にも一時停止 | 落ちる（「木の外に送った」） |
| M7 問題1 を直す（控えてから送る、SIGKILL は全部に送ってから例外） | xfail(strict) の 7 通りが XPASS で落ちる。ほかは通る |

`test_a0_fix7_procs.py` の 2 の gate は、部品の写しを「試験のプロセスの子（木の外）にも一時停止を送る」形に壊し、
gate の先の本物の `os.kill` も控えるだけの身代わりにして流した（合図は 1 つも送らない。`/tmp/a0-verify8/mut/gate_check.py`）:
壊した写しでは「kill_tree(A) が、A の木の外に合図を送ろうとした（gate が止めた）」で落ち、控えには木の外のプロセスと
兄弟の木の親の番号が残った。壊さない写しでは、gate は何も止めず、合図が届かないので状態の確かめで落ちた（身代わり
にしたため。想定どおり）。

この確かめの道具の誤り: gate を抜けるときに `os.kill` を `REAL_KILL` に戻すので、`REAL_KILL` を身代わりにすると、
その後の pytest の中の `os.kill` がどれも身代わりになり、こちらの道具の後始末も送られなかった（本物の合図は出て
いない）。眠るだけのプロセスが 9 個残ったので、引数の印と環境変数の印の両方で確かめてから止めた。

8.5 の値の試験（1・2）は、7回目の値（`;` を含む）を対照として試験の中で流し、まねが効いていること（2 つに分かれる
こと）を確かめている。
