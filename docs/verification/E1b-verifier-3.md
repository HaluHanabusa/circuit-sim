## 参照（実装とも、実装担当の試験とも、前回の自分の経路とも別）

前回の自分の経路（位相の変化で細かくした格子の符号の変わり目）は、再現例の近い2つ（2437.59 と 2437.79 Hz）を拾えなかった
（595.6 Hz の1つだけ）。今回は2つの経路の和にした。

- 植物: 状態 [iL, vC] を拡大行列の expm で零次ホールドに。Δ = Ad − I は φ1(X) = (e^X − I)/X から求め、開ループは
  z − 1 = expm1(jθ) と Δ で組む（I + Δ を作ると、f_ctrl/f0 が 1e4 のとき Δ の桁が落ち、余裕が 1e-5° ずれた）。
- 交差 (a) 代数: z = 1 + w、単位円の上で s = |w|² = 4 sin²(θ/2)、w + w̄ = −s とすると |N|² − |D|² は s の4次の多項式。
  その (0, 4) の実根の近く ±0.1% を 4001 点で調べ、log|L| の符号が変わる点をすべて二分法で詰める。
  代数の根だけでは f_ctrl/f0 が 5000 倍を超えると粗く（|L| = 1.02 の点を交差と見た）、近くを調べる段が要った。
- 交差 (b) 格子: 等比の 2 万点を位相の変化 3° で細かくし、符号の変わる点を詰める。
- 余裕: 交差ごとに連続の位相（格子の unwrap に合わせる）と −1 からの角度の両方。閉ループは 6×6 の固有値（前回と同じ）。
- 自分の道具の誤りで出た「食い違い」（代数の根の粗さ、丸めで符号がずれた格子の端を中点で数えた、など）は、すべて原因を
  確かめて道具を直し、直した後で掃引を流し直した。上の数はすべて直した後のもの。

## 見つけた問題（すべて軽微。利用者に不安定なゲインや未達のゲインが渡る例は無い）

1. **numpy の数（np.int64、np.float32）を、正の有限値でも断る**（前の版からの後退）。再現:
   `buck_voltage_mode_pid(np.int64(24), 22e-6, 100e-6, 6.0, 100e3)` → invalid_argument「v_in は 0 より大きい有限値にする
   （現在 np.int64(24)）」。原因: `_check_arguments` の `isinstance(v, int | float)`（np.float64 は float の子なので通る）。
   前の版の `math.isfinite(v) and v > 0` は通していた。試験は xfail(strict)。
2. **丸めで目標をわずかに下回る候補を「目標まで 0.0° 足りない」と書く**。設計した点の余裕は二分法で目標に合わせるので、
   候補の計算で最大 2.6e-10° 下回ることがある。最良の候補の文 11,650 通りのうち 128 通り（negative_gain 126、unstable 2）が
   丸めだけの「0.0° 足りない」（ほかに、本当に 0.05° 未満だけ足りない 10 通りも「0.0°」と出る）。
   理由 unstable では本文の「位相余裕は目標を満たすが」と食い違う。再現（掃引で見つけた）:
   `buck_voltage_mode_pid(2.967370111576123, 7.338144645114917e-05, 2.439793958973858e-06, 0.21317375460902435,
   123266.3864601657, zero_damping=0.1437543236478271, filter_ratio=0.0, phase_margin_deg=24.361861916713153,
   zero_ratio=0.9590984284499318)` → 「位相余裕は目標を満たすが、…極の半径が 1.0187…。最良の候補: …位相余裕 24.4°
   （目標まで 0.0° 足りない）」。原因: 受け入れの判定は目標 − TARGET_TOL_DEG（1e-6°）、文言の判定は目標ちょうど。試験は xfail(strict)。
3. **f_cross_max をナイキストの手前に制限したことが、結果にも文にも出ない**。返すゲインは制限の値を指定したのと同じで、
   交差は利用者の上限より下なので、ゲインを誤解させることはない。ただ失敗の文には、指定した値（例 1e9 Hz）でなく制限後の
   上端（「7708〜9999 Hz」）が理由なしで出る。文に「（ナイキスト周波数の手前に制限した）」を足すのがよい。
4. **zero_ratio が極端に小さいと、安定の判定が丸めで決まる**。zero_ratio = 1e-9 では Ki ≈ 1e-14 で、積分の極が丸めの範囲で
   z = 1 に乗る: `buck_voltage_mode_pid(24, 22e-6, 100e-6, 6, 100e3, zero_ratio=1e-9)` は半径 0.9999999999999999 を「安定」として
   返し、`(24, 4.7e-6, 1e-3, 1000, 1e6, zero_ratio=1e-9)` は半径 1.0000000000000007 で unstable（どちらも参照の固有値も同じ値）。
   引数の確かめは (0, 1) を許すので届く。zero_ratio に下限を置くか、1 − 半径が固有値の丸めより大きいことを確かめるのがよい。
5. **実装担当の試験の説明が実装と違う**（文書）。`tests/test_e1b_tuning.py::test_close_crossings_in_one_grid_cell_are_not_missed`
   の説明に「交差を多項式の根から厳密に求め」とあるが、実装は囲い込み（`architecture.md` は多項式のやり方を試して捨てたと書く）。

所見（問題ではない）:
- 引数の範囲を狭めた: zero_ratio と zero_damping は (0, 1)。前回までは 1.5 などでも計算した。ζz = 1（重根の零点）も断る。
  説明（docstring）に範囲が書いてあり、断る文も分かりやすいが、利用者に見える範囲の変更なので決定記録に残すとよい。
- 前回の軽微2（画面仕様の付録A.4 に Rleg が無い）は、取り込んだ main（A4t）で直っている（743・807・809 行）。
- 理由 unstable に届く例が見つかった（上の 2 の例。余裕は目標どおりで、極の半径 1.0187）。前回は到達できない守りだった。
