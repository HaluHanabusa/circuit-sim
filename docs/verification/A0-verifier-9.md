1 回目の実行で事象が出ない、差し込んだ例外で finally が動かないことがある、など道具の側が当てにならなかった

## 見つけた問題

### 1. 軽微（試験の部品）: os.kill の中で、SIGKILL を送る前に例外が出ると、その 1 つが一時停止のまま残る

- 所: `tests/app_procs.py` の `kill_posix_tree` の finally（231〜237 行）。内側の `except BaseException` は、例外を
  「送った後に出た例外」と見て控え、次の番号へ進む。送る前に出た例外なら、その番号には SIGKILL が送られない。
- 部品の説明（32〜34 行、198〜202 行）は「os.kill の中から出る例外は、全部に送ってから出し直すので、これには当たら
  ない」と書くが、送る前に出る例外には当たらない（言い過ぎ）。
- 送る前に出る道（実測）: os.kill は、送る前に監査の事象 `os.kill` を出す。Python の監査フックがあると、その中で
  待っている Ctrl+C が KeyboardInterrupt になり、os.kill は送らずに例外を出す（`exp/audit/run.py`。印つきの自分の子は
  状態 S のまま）。いまの試験の実行では、pytest のプロセスに Python の監査フックは無い（受け入れ試験の部品
  `a0_fake_browser.py` のフックは、アプリ本体の子のプロセスで流す文字列 `GUARD_ENTRY` の中）。だから、いまの実行では
  起こりにくい。
- 再現（本物の合図は送らない）: `python -I /tmp/a0-verify9/exp/lines/before_kill.py /tmp/a0-verify9/copy/tests copy`
  の「n 回目の kill を送る前」の 4 行。b3c5b73 は、その 1 つだけが残る（直す前の 0df15ac は、残りの全部が残った）。
- 直し方の案（直すのは A1 で）: 内側の `except BaseException` の中で、その番号にもう一度 SIGKILL を送る（例外は
  無視する）。この形を写しに入れると、送る前の例外でも何も残らず、実装者の試験とこちらの受け入れ試験は通る
  （`mut/mutate.py` の F1、`exp/f1/`）。レビュー 9回目の軽微1 の案（`kill_posix_tree` の間だけ SIGINT を控えて、
  後で出す）なら、文の切れ目の残り（2-2）もまとめて閉じる。
- 受け入れ試験: `test_a0_fix9_kill_windows.py` の 2 は「残るのはその 1 つまで」を見る（直って 0 になっても通る。
  直す前の形のように、残りの全部が残る後退は落とす）。xfail(strict) にはしていない（軽微は統合を止めないため）。
