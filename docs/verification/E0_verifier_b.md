## 3. 許容差と根拠（測る前に決めた）

- **解析解との差 1%**（分母は入力電圧、電流はピーク電流）。`roadmap.md` の既定の基準。最も速い時定数を50分割以上にした2次精度の方法の理論誤差は0.1%以下で、定数を1割ずらした参照とは3%以上ずれることを試験の中で確かめている（`test_c1_check_detects_ten_percent_wrong_reference`）。実装の誤りを見逃さない範囲で十分に緩い。
- **収束次数: 誤差の比が 3.7〜4.3**（次数 1.89〜2.10）。1次なら2になるので区別できる。
- **t=0 の整合、電源の節点電圧: 相対 1e-9**。連立一次方程式を1回解くだけの値で、丸め誤差しか残らないはず。
- **再現性: 許容差なし**（ビット単位の一致）。
- **数値振動: 1次のRC回路のステップ応答が入力電圧の1%を超えて行き過ぎない**。1次回路は理論上行き過ぎないので、1%を超えたら方法が作った振動。
- 基準 4 と 8 の文面には「どの刻みの範囲で」が書かれていない。この記録では文面どおり（刻みの条件なし）に判定した。基準を「刻みが最速の時定数を解像している範囲で」に直すなら、基準4は合格になる。ただしその場合も問題1は残り、利用者への注意が要る。

## 4. 見つけた問題

### 重大

**問題1: 刻みが速い時定数を解像しないと、状態量が数値振動する。注意も出ない。**（基準 4、8）

- 再現（1次のRC、τ = 1 ms、h = 100τ）:
  ```python
  from circuit_sim import Netlist, simulate
  net = Netlist.model_validate({"components": [
      {"id": "V1", "type": "V", "nodes": ["in", "0"], "waveform": {"kind": "dc", "value": 1.0}},
      {"id": "R1", "type": "R", "nodes": ["in", "out"], "value": 1e3},
      {"id": "C1", "type": "C", "nodes": ["out", "0"], "value": 1e-6}]})
  print(simulate(net, 40.0, 0.1)["v(out)"][:5])   # [0, 1.96, 0.077, 1.89, 0.148]  真値は 0 → 1 へ単調
  ```
  途中のステップ（`"kind": "step", "final": 1.0, "t_step": 2.0`）でも同じ振動が出る。
- 再現（層Aの経路。過減衰の直列RLC）: `rlc_series`、Vin=10、R=1e3、L=1e-6、C=1e-6、`"simulation": {"t_end": 5e-3, "h": 1e-6}` を `python -m circuit_sim` に渡すと、終了コード0で `i(L1): 最大 0.0199501` と表示される。真のピークは 0.0100 A。刻みを 1e-8 にしても 0.0167 A。
- 境界: h > 2τ（τ は最も速い時定数）で符号が交互に変わり始める。h/τ = 3 で行き過ぎ20%、10 で67%、100 で96%。遅い変数（上の例の v(out)）は正しい。
- 想定される原因: `kernel.run` は不連続点で状態量以外を解き直すが、その後も台形則のまま進む。台形則は硬い成分を減衰させない（増幅率が −1 に近づく）。t=0 で電源が既に加わっている場合も同じ。設計（`architecture.md` 4章、`decisions.md` D-007）は「切り替え直後は後退オイラーで硬い成分を減衰させる」としているが、E0 の核には入っていない（`E1a-switching.md` の落とし穴にも同じ指摘がある）。
- 直し方の確認: 一時的な写しの上で、t=0 と不連続点の直後だけ後退オイラー（1ステップでも2ステップでも）にする試作をしたところ、この問題の試験3件が通り、ほかの受け入れ試験69件と実装者のテスト16件は通ったままだった（残りの xfail 4件は別の問題なのでそのまま）。2次精度も保たれる（誤差の比は、刻みを細かくすると4に近づく）。
- 対応する試験（xfail）: `test_c4_no_overshoot_after_midrun_step_with_coarse_step`、`test_c8_time_constants_six_orders_apart_fast_node_with_coarse_step`、`test_c8_extremely_coarse_step_does_not_overshoot_first_order_circuit`

**問題2: 層Aの `unit` が読まれない。**（基準の外。スキーマはE0の成果物）

- 再現: `rlc_series` の `plant` に `"L": {"value": 1, "unit": "mH"}`、`"C": {"value": 10, "unit": "uF"}` と書くと、L = 1 H、C = 10 F として計算され、エラーも注意も出ない（`expand(spec).netlist` で確認できる）。
- `unit` は必須項目で、`app-design.md` は「47 µH」のような工学表記での入力を想定している。設計書から抽出した値がそのまま入ると、結果が3〜6桁ずれる。
- 想定される原因: `templates/t0.py` の `_values()` が `value` だけを取り出している。
- 直し方の候補: 換算する。または、当面は期待する単位（V、ohm、H、F）以外を明確なエラーにする。どちらにするかは仕様の判断。
- 対応する試験（xfail）: `test_c6_unit_is_not_silently_ignored`

**問題3: 強い過減衰の仕様で、既定の刻みのステップ数が膨らみ、メモリ不足で落ちる。ステップ数の上限の確認も無い。**（基準 8）

- 再現: `rlc_series`、Vin=10、R=1e3、L=1e-6、C=1e-6（`simulation` は省略）で `expand()` すると t_end = 5 ms、h = 3.1e-11 s、1.6億ステップ（結果と入力の配列で約11 GB）。R=1e5、L=1e-6、C=1e-3 では 1.6e15 ステップになり、`python -m circuit_sim` は `numpy._core._exceptions._ArrayMemoryError: Unable to allocate 11.3 PiB` のトレースバックで終わる。
- 想定される原因: `_timing()` は刻みを最も速い極、計算時間を最も遅い極から決めるので、ステップ数は極の比（およそ 4ζ²）に比例する。ζ=50 で160万、ζ=500 で1.6億。`simulate()` はステップ数を確かめずに配列を確保する。
- 問題1と合わせると、この種の回路は「既定のままでは計算できず、刻みを粗くすると電流が誤る」。電流を1%以内で出すには利用者が h を約 0.3 ns にする必要があり、1500万ステップかかる（h = 1 ns、500万ステップ、26秒で、電流の誤差3.5%）。
- 対応する試験（xfail）: `test_c8_template_step_count_stays_practical_for_strongly_overdamped_rlc`、`test_c8_impossible_step_count_is_reported_clearly`

### 軽微

**問題4: キャパシタンス[F] とインダクタンス[H] の数値の比が約1e15を超えると、初期値が誤る。エラーなし。**
再現: 直列RLC、V=1、L=1e-12、C=1e3、R=√(L/C)。`out["v(in)"][0]` が 0.75（電圧源は 1 V）。L=1、C=1e-15 に初期値を与えた場合も v(a) が 0.7 でなく 0.85 になる。原因は `kernel.prepare` の `null_space((E / scale).T)`: F と H が混ざった行列に相対しきい値を当てるので、小さい方が0とみなされる。現実の回路（1 F と 1 nH で比 1e9）からは3桁以上離れているので軽微とした。直し方の候補: 微分を含まない式を値でなく構造で判定する。少なくとも、求めた初期値を方程式に戻して残差を確かめる。試験（xfail）: `test_c8_extreme_capacitance_to_inductance_ratio`

**問題5: 矛盾する初期値が黙って均される。**
並列のコンデンサ（1 µF に 1 V、2 µF に 3 V）は、電荷を保存した 2.333 V で始まる。物理的には妥当だが、与えた初期値と違う値で始めたことの注意が無い。

**問題6: 解けない回路のエラーが、原因の場所を示さない。直列のインダクタも断られる。**
メッセージは「浮いた部分、電圧源だけのループ、…などが無いか確認する」の一文で、どの素子・節点かが分からない。インダクタ2つの直列（間の節点にほかの素子が無い）は物理的に解けるが同じエラーになり、例示にも無い（コンデンサの並列は解ける）。`build_system()` 単体では検出されず、`simulate()` の中の `kernel.prepare` で検出される（時間ステップの前ではある）。

**問題7: 有限でない入力の検証が電源と初期値に無い。**
電源の値や `ic` に NaN / 無限大を入れると検証を通り、結果が NaN になる（R / L / C の値は検証している）。`t_end` や `t_step` が無限大だと `OverflowError`。層Aの Vin = NaN も通る。

**問題8: 計算時間の丸めが知らされない。**
`t_end` が `h` の整数倍でないと、最も近い格子点に黙って丸められる（t_end=1e-3、h=3e-4 で 0.9 ms まで。同梱の例も 10 ms でなく 9.9997 ms で終わる）。ステップ時刻の丸めは `notes` に出るのに、こちらは出ない。

**問題9: 最後の格子点でのステップが反映されない。**
`t_step` が最後の格子点に丸められると、`notes` は「格子点 0.006 に丸めた」と言うが、その点の値は切り替え前のまま（ほかの格子点では切り替え後の値が入る）。

**問題10: 正弦波の周期を刻みが解像しなくても注意が無い。**
周波数×刻み = 1 では電源が 0 のままになり、0.9 では 1/10 の周波数に折り返した波形がそのまま出る。

**問題11: 層Aの細かい点。**
`plant` の余分な項目（綴り違いなど）は黙って無視される。`missing` の一覧は展開で参照されない。`"value": true` が 1.0、`"value": "10"` が 10.0 として通る（pydantic の既定の変換）。

## 5. 実装者のテスト（`tests/test_t0.py`）の実効性

- **期待値の独立性**: 解析解はテストの中に式で書かれており、実装の関数を使っていない。過減衰の参照が `np.roots` を使う点はテンプレートと同じだが、テンプレート側は刻みの決定に使うだけなので、期待値は独立している。
- **参照をずらしたとき**: 参照側（期待値）の定数をずらす操作を15通り行い、13通りで落ちた（1割のずれ、切り替え時刻の1刻みのずれ、位相 0.1 rad のずれはすべて落ちる）。通ったのは時定数の2%のずれと位相 0.005 rad のずれの2通りで、許容差1%どおり。
- **許容差**: 1% は `roadmap.md` の既定で、結果に合わせて緩めた形跡は無い。実測の誤差は 0.003〜0.06% なので余裕は15〜300倍あり、数%未満の誤りはこの照合だけでは見つからない。収束次数のテストがそれを補っている。
- **変異試験**（製品コードの写しに不具合を1つずつ入れた。31通り）: 実装者のテストは22通りを検出、9通りを見逃した。見逃したもの:
  正弦波の位相を無視 / オフセットを無視 / ステップの `initial` を無視（2通り）/ 電源を刻みの始点だけで評価（時間とともに変わる電源で1次精度に落ちる）/ 基準節点の名前を "0" に固定 / 浮いたコンデンサの初期値の符号（n− 側）/ 不連続点で状態量を捨てる（テストが静止状態からのステップなので見えない）/ ステップ時刻の丸めの注意を出さない。
  追加した受け入れ試験は31通りすべてを検出する。
- **無いもの**: 再現性（基準7）の試験、硬い回路や粗い刻み、素子数の多い回路、「計算の前に」エラーになることの確認、途中のステップでの状態量の連続（初期状態が0でない場合）。
