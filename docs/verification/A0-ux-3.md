## 決めごと（オーケストレーターから頼まれた2点）

### 1. `N-PREFS-SAVE` の文言 → 直して採る

実装担当の案は、何が起きたか・どうするかが対になっていて、段階（注意）、種類（出来事、閉じられる）、自動では開かないこと、詳細に `HTTP 500: No space left on device` を入れることは、このままでよい。
ただし次の2つで、そのままでは採らない。

- 「次に起動したときは戻りません」は言い切りすぎ。設定ファイルに古い値があればその値で、無ければ（同じポート・同じブラウザなら）ブラウザの保存の値で開くので、戻ることもある。「残らないことがあります」にする。
  「戻りません」は「元に戻らない」とも読める。英語の "won't come back" も同じ。括弧の中は、たたんだ状態とお知らせの帯の開閉も含むので「など」を足す。
- 保存し直せても、お知らせが残る（改善1）。直したかどうかを確かめる手がかりが無い。保存できたら消し、そのことを文言に書く。

| キー | 日本語 | English |
|---|---|---|
| `notice.N-PREFS-SAVE.what` | 画面の好み（言語、テーマ、仕切りの位置など）を、設定ファイルに保存できませんでした。この画面ではいまの好みのまま使えますが、次に起動したときには残らないことがあります。 | Couldn't save your display preferences (language, theme, panel sizes, and so on) to the settings file. They still apply on this page, but may not be kept the next time circuit-sim starts. |
| `notice.N-PREFS-SAVE.fix` | 設定の場所（{path}）に書き込めるか（フォルダの権限、空き容量）を確かめてください。直した後に好みを1つ変えると保存し直し、保存できるとこのお知らせは消えます。 | Check that the settings folder ({path}) can be written to (permissions, free space). After fixing it, change any preference to save again. This notice goes away once they're saved. |

- 消えるとき: 次に保存できたとき（好みを変えて送れた、つなぎ直した後に送れた）。それまでに「閉じる」でも消せる（いまのまま）。
- A1 で付録B に入れるとき（私が行う）、行に「もう一度」（`common.retry`）を足し、押すと保存できていない好みを送り直すようにする。そのとき fix の2文目を「直した後に［もう一度］を押してください。保存できると、このお知らせは消えます。」/ "After fixing it, select Try again. This notice goes away once they're saved." に替える。A0 ではお知らせの行に押せるリンクの仕組みが無いので、足さない。
- 捨てた案: 「同じ名前のファイルが無いか」を足す（端末の `config.failed` と合わせる）。画面からは同じ名前のファイルの有無が分からず、空きと権限で足りるので足さない。

### 2. 起動直後の画面に、お知らせがあるときだけ帯を出す → 採る（条件つき）

仕様を開く前に起きた出来事（いまは `N-PREFS-SAVE` だけ）を知らせる場所は、帯がよい。ほかのお知らせと同じ場所・同じ形で、仕様を開いた後もそのまま続く。
8通りと 150% で、帯（たたんだ 33px、開いた 83px）は起動直後の列に重ならず、ページのスクロールも出ない。サンプルを開いても、お知らせは残る。

- 捨てた案: (a) 起動直後の画面の中（開けなかったエラーの位置）に出す。仕様を開いた後に帯へ移すことになり、置き場所が2つになる。(b) 仕様を開くまで出さない。失敗を隠す（原則1）。
- 条件: 最後の1件を閉じると帯ごと消えるので、閉じた後のフォーカスを「ファイルを選ぶ…」（3.2 の最初のフォーカス）に置く（改善2）。
- 画面仕様は A1 の仕様で私が直す: 1.3 の「空」に「仕様を開く前に起きた出来事のお知らせがあるときだけ、帯を出す（9章と同じ形）。最後の1件を閉じたら帯を消し、フォーカスは『ファイルを選ぶ…』へ」、3.2 の配置図に帯、9.3 の「空（0 件）」に「起動直後の画面では帯を出さない」。

## 新しく入ったものの見え方

**起動の流れ（ブラウザを開く）。** ブラウザに渡るのは `file:///<設定の場所>/open-<16桁>.html` だけで、番号は起動の引数に載らない。
Chrome で開くと、`file://` → `/?k=…`（中身の無いページ）→ `/` と移り、URL の欄に残るのは `/`。履歴に転送用の HTML と番号つきの URL は残らない（`history.length` は 2、戻ると空のページ）。
移る途中の地の色は、覚えたテーマのとおり（暗を覚えている → 暗、OS が暗でも明を覚えている → 明。`flow-dark-0.png`、`flow-light-osdark-0.png`）。リンクの文字が一瞬出ることも無い。
番号が使われると HTML は消え、止めると残りも消える。

**15 秒の案内。** ブラウザが開いたのに番号が使われないと、15 s 後に「ブラウザで作業画面が開かないときは、ブラウザで次の場所を開いてください: <URL>」/ "If the workspace didn't open in your browser, open this address in it: <URL>"。
使われたときは出ない。ブラウザを起動できないとき（`BROWSER=/bin/false`）は、すぐ「ブラウザを開けませんでした。…」。どちらも出る URL は使える番号つき。

**Enter で新しい URL。** 起動の行の後に「画面を開き直すときや、URL の期限が切れたときは、ここで Enter を押すと新しい URL を出します。」。
Enter のたびに「新しい URL（1回だけ、5 分以内に使えます）: <URL>」。入力が端末でないとき（`< /dev/null`）は「…circuit-sim を起動し直してください（新しい URL を出します）。」に替わり、Enter の案内は出ない。よい。

**使い終わった URL で開いたとき。** 別のブラウザの場（クッキーなし）で使い終わった URL を開くと、画面は合言葉の無い案内（`app.unauthorized`）、端末は
「使い終わったか期限が切れた URL で、画面が開かれました。ここで Enter を押すと、新しい URL を出します。」/ "The workspace was opened from a URL that was already used or has expired. Press Enter here for a new URL."。
Enter で出た URL を同じブラウザの新しいタブで開くと、元のタブも 2 秒ほどで起動直後の画面に戻る。2 s の間に3回開いても案内は1回で、5 s あけるともう1回出る。同じブラウザ（クッキーあり）で使い終わった URL を開いても、案内は出ずにそのまま使える（`term-ja-stale.txt`、`term-ja-reuse.txt`）。
画面の側の文言は前回の改善3（A1）のままで、番号が1回きりになった今は2文目を下のとおり替える。

**`N-PREFS-SAVE`。** 起動直後の画面でテーマを替えて保存できないと、帯がたたんだ状態で出て、件数「注意 1」と1行目が見え、読み上げにも伝わる。フォーカスは押した部品に残る（奪わない）。
5 s 待っても送り直さない（PUT は1回）。言語を替えると、お知らせの文も切り替わる。

**読み上げの文の訳し直し。** 言語を替えると、読み上げ用の領域の文も新しい言語になる（10.4 のとおり）。ただし改善3。

**Ctrl+C。** 保存していない変更があるときの1回目は止めずに知らせ、2回目で止まる（変更の後も前回どおり。`term-ja-dirty.txt`）。

## 申し送り（オーケストレーターへ。判定には入れない）

- **転送用の HTML を開けないブラウザがありうる（実機で確かめてほしい）。** Ubuntu の既定の Firefox（snap）や Flatpak のブラウザは、ホームの隠しフォルダ（`~/.config/…`）のファイルを読めないことがある
  （同じ形の転送用の HTML を使う Jupyter で報告がある。私の記憶によるもので、ここでは確かめていない）。そうなると、ブラウザにはエラーのページが出て、端末に案内が出るまで 15 s 待つ。行き止まりではないが、Linux の既定の環境で毎回そうなると、はじめての利用（3 分以内、説明を読まずに）を損なう。
  ここでは確かめられなかった（ヘッドレスの Chrome は読める）。Ubuntu の既定の環境で確かめ、開けないなら、ブラウザが読める場所に置くか、その環境では案内を早く出すかを、ui-engineer が決める。Windows・macOS の既定のブラウザでも一度は確かめる。
