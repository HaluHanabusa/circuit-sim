# H2: 開発ハーネスの残課題

依存: H1（完了） ／ 並行する作業単位が増える前に行う。担当は tooling-engineer。

## 範囲

再レビューの「中」（必ず直す）:

1. **ブランチの土台の付け替えで、main の他の成果が消える**: ゲートを通した後に `git reset --soft main && git commit`（または `git merge -s ours main`）をすると、ツリーIDは同じなのでゲートが有効なまま、main に入っていた他の成果を消す取り込みになる。check / review / verify / ux の記録にその時点の `git merge-base main HEAD` を控え、merge のときに違っていれば「古い」にする。

再レビューの「軽」:

2. 例外の場所（`tests/acceptance/`、`docs/verification/`）で後から足せるファイル名を `test_*.py` と `*.md` に絞る（`conftest.py` で受け入れ試験を全部外せるため）。
3. ヘッドレスの verify が基準ゼロ件（`criteria: []`）の合格を返したら、不合格にする。
4. 記録がある状態で必要なゲートが増えるだけの見出し変更（`needs_ux: true` の追加）は、記録を残す。
5. 取り込みの控えが残って本体が変わっていたときの案内に、戻す先のコミットを出す。
6. 仕様の見出しの `owner` に、役割の定義が無い担当（ハーネスの修正担当など）を書けるようにするか、役割を足すかを決める。

W1 から送られたもの:

8. 1か所ずつ壊す確認を、繰り返せる形にする。壊し方の一覧と実行の仕組みをリポジトリに置き、`scripts/cycle.py` の残り（W1 の時点で未実行565通り）と `scripts/doctor.py` を消化する。試験で落とす意味の無い壊し方は、理由を付けて除く。
9. H1 からある生き残り3種: ロックを共有に変えても試験が通る、`GIT_DIR` などを除く一覧から外しても通る、`git_paths` が git の失敗を無視する。
10. `benchmarks/bench_switching.py` が `µs` を出力し、cp932 の端末で落ちる。

W1 のレビューと検証で見つかり、統合を止めなかったもの（Windowsでの悪用には、作業ツリーや実行した場所にファイルを置ける者が要る）:

11. Windowsで、作業ツリー直下に置いた `node.cmd` が動くはず（npm 版の `claude.cmd` が `node` を名前だけで呼ぶため）。`git` と `taskkill` も名前だけで起動している。環境変数 `NoDefaultCurrentDirectoryInExePath` を足す、絶対パスで起動する、などで塞ぐ。
12. `find_command` は PATH の項目の場所だけを比べ、ファイルの実体を見ない。PATH 上のリンクが作業ツリーの中を指していると採ってしまう。
13. Windowsで、止める合図が届かない子孫プロセスが出力を持ち続けると、打ち切りの後に戻らない可能性がある（未確認）。設計書の「どのOSでも、待たずに戻る」は言い過ぎなので直す。
14. `doctor.py` は git を自前の探し方で探すが、`cycle.py` は名前で起動する。探し方をそろえる。

15. `doctor.py --headless` が失敗したとき、原因の種類（ログインしていない、利用枠の上限、モデルを使えない、など）を、本文を記録せずに分類して出す。いまは `result` の文面を見ないので、失敗の原因が分からず、利用者にもう一度コマンドを打ってもらう必要がある（POのPCで実際に起きた）。あわせて、`--headless` のときは確認（数分かかる）を省くのを既定にする。

16. `doctor.py --headless` は、ゲートで使う役割（実装の担当、code-reviewer、verifier、ux-designer）のそれぞれで `structured_output` が返ることを確かめる。役割の定義に `tools:` の一覧があったら、実行の前に警告する（D-030）。失敗の切り分けに使える `stop_reason` と `terminal_reason` も記録する。
17. レビューのゲートは、起動の側でも編集の道具を禁じる（いまは `--permission-mode acceptEdits` で、編集の禁止は役割の定義だけに頼っている）。

W2 の3回目のレビューと検証で見つかり、統合を止めなかったもの:

18. 終了の合図が続けて2回届くと、claude が止まらないことがある（端末を閉じると前面のジョブに SIGHUP が2回届く。pty の模擬で150回中4回）。記録は書かれず、誤った合格にはならない。`stop` の中で、raise の前に止めの合図をすべて無視に切り替える。30秒たっても戻らなかった1件の原因も調べる。
19. claude と同じ場所にある git 以外の道具（bash など）が、試験の遮断で PATH から消える（Linux で claude が /usr/bin にある場合）。外す場所を「claude 以外の中身へのリンクを並べた場所」に置き換え、外した場所と残した道具をセッションの始めに表示する。
20. 一時フォルダが実行不可だと見張り役も起動できず、理由の文が出ない。pytest-xdist で見張り役が起動されたときの表示。
21. 試験の遮断はセッション開始時の PATH にだけ掛かる。試験の中で PATH を組むときは `CIRCUIT_SIM_SAFE_PATH` を使う、と `docs/design/harness.md` と試験の書き方の決まりに書く。

優先: 9番のうち決まりに関わる2種（ロックを共有に変えても試験が通る、`git_paths` が git の失敗を無視する）と、1番（土台の付け替え）を先に片付ける。

**H2 が終わるまでの制限**: Windowsでは、`scripts/cycle.py run`（ヘッドレス実行）をゲートの記録に使わない（D-029）。`scripts/doctor.py --headless` での動作確認は行ってよい。

未確認のまま残っていること:

7. 本物のCLIでのヘッドレス実行（`scripts/cycle.py run`）。クラウドの作業環境では認証できない。CLIにログイン済みの環境で、小さな作業単位を使って確かめる。
