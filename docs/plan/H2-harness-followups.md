# H2: 開発ハーネスの残課題

依存: H1（完了） ／ 並行する作業単位が増える前に行う。担当は tooling-engineer。

## 範囲

再レビューの「中」（必ず直す）:

1. **ブランチの土台の付け替えで、main の他の成果が消える**: ゲートを通した後に `git reset --soft main && git commit`（または `git merge -s ours main`）をすると、ツリーIDは同じなのでゲートが有効なまま、main に入っていた他の成果を消す取り込みになる。check / review / verify / ux の記録にその時点の `git merge-base main HEAD` を控え、merge のときに違っていれば「古い」にする。

再レビューの「軽」:

2. 例外の場所（`tests/acceptance/`、`docs/verification/`）で後から足せるファイル名を `test_*.py` と `*.md` に絞る（`conftest.py` で受け入れ試験を全部外せるため）。
3. ヘッドレスの verify が基準ゼロ件（`criteria: []`）の合格を返したら、不合格にする。
4. 記録がある状態で必要なゲートが増えるだけの見出し変更（`needs_ux: true` の追加）は、記録を残す。
5. 取り込みの控えが残って本体が変わっていたときの案内に、戻す先のコミットを出す。
6. 仕様の見出しの `owner` に、役割の定義が無い担当（ハーネスの修正担当など）を書けるようにするか、役割を足すかを決める。

W1 から送られたもの:

8. 1か所ずつ壊す確認を、繰り返せる形にする。壊し方の一覧と実行の仕組みをリポジトリに置き、`scripts/cycle.py` の残り（W1 の時点で未実行565通り）と `scripts/doctor.py` を消化する。試験で落とす意味の無い壊し方は、理由を付けて除く。
9. H1 からある生き残り3種: ロックを共有に変えても試験が通る、`GIT_DIR` などを除く一覧から外しても通る、`git_paths` が git の失敗を無視する。
10. `benchmarks/bench_switching.py` が `µs` を出力し、cp932 の端末で落ちる。

未確認のまま残っていること:

7. 本物のCLIでのヘッドレス実行（`scripts/cycle.py run`）。クラウドの作業環境では認証できない。CLIにログイン済みの環境で、小さな作業単位を使って確かめる。
