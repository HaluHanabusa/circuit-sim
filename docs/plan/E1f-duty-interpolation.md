# E1f: デューティの分解能（ゲートの切り替えを刻みの途中で扱う）

担当: solver-engineer ／ 依存: E1b ／ 次: E2（ゲイン最適化）

## 目的

ゲートの切り替え時刻を時間刻みの格子に丸めているため、デューティの分解能が「1 / 1周期の分割数」に限られる。目標が格子のすぐ近くだと出力が最大1.1%振れる（D-021、D-036）。E2 の評価を乱さないよう、切り替えを刻みの途中で扱う。

## 範囲

- ゲートの切り替えが刻みの途中にあるとき、その刻みを切り替えの前後に分けて進める（回路状態ごとに、分けた刻みの行列を用意して使い回す。端数を細かく量子化するか、正確な端数で求めるかは担当が決め、精度と記憶量を報告する）。
- ダイオードの切り替え（状態で決まるもの）は、従来どおり格子で扱ってよい。
- 丸めの余りの持ち越し（E1a の C）は、この仕組みで不要になるなら外す（外したことを報告）。
- 核の最内ループの決まりを守る。

## 受け入れ基準

| # | 基準 | 合格の条件 |

| 1 | 分解能 | 受け入れ試験に残っている `xfail(strict)`（E1c の範囲9、`test_c16`）が通る。検証担当Bの最悪点（目標 11.99225 V）を含め、目標を格子の近くで細かく振って、出力の周期平均の振れが指令値の 0.2% 以内（E2 の整定の許容帯 ±1% の 1/5。D-063）。E1a の回路に加え、E1b の同期整流の降圧コンバータ（閉ループ、同梱の例のゲインと検証担当の試験用の制御の両方）でも、指令値を細かく振って確かめる（`accuracy-and-resolution.md` 6章） |
| 2 | 精度 | 切り替えが格子に乗る場合、結果が今と一致する（差は丸め誤差の範囲）。刻みを半分にしたとき誤差が約1/4（2次精度）が保たれる |

| 4 | 後退が無いこと | E1a、E1b、E1c の基準が引き続き合格。`python scripts/check.py` が通る |

## E1g から引き継いだ軽微（D-058。E1g のレビュー 2・3回目と検証 2回目）

エンジンとコマンドラインの側。この作業単位の中で直す（数値の結果を変えないもの）。

1. CSV の名前が長い（246 バイト以上）と、注意の無い計算で、書き出しに成功したのに「書き出せません」・終了コード 2 になる（`circuit_sim/__main__.py` の `Path.exists()` が ENAMETOOLONG を投げる）。`os.path.lexists` と `unlink(missing_ok=True)` にする。
2. 書いている途中で失敗すると、前の CSV が途中までの CSV に置き換わる。文面にファイル名が出ない（E0 からの動き）。同じフォルダの一時ファイルに書いて `os.replace` する。`CLI_WRITE_FAILED` に書こうとした場所を差し込む。
3. スイッチのある回路で電源が約 9e307 を超えると、準備の `0.5 * (u_start + u_end)`（`simulate.py`）があふれ、numpy の警告が1つ残る（`-W error` では traceback）。
4. `np.errstate` が、自作の制御器の `step()` と `progress`・`cancel` の中の本当の誤りの警告も止める。範囲を時間ステップの核の呼び出しに絞るか、`control/interface.py` の `Controller` の説明に書く。
5. 番号の無い文が届く残りの経路: argparse の説明 2 つ（辞書の外の直書き）、`AVERAGE_MODEL_USED` の日本語に「状態平均化法による」が無い（D-063 の (5)）。`tuning/initial.py` と pydantic の文、1e-300 以下・1e300 以上の値での数値ライブラリの例外は E2a で扱う。
6. スイッチング状態が 16 を超える回路で、後処理の `np.unique` が区切られない（500 万ステップ超で 0.2 秒を超える見込み）。
7. 指令の変わり目と、時刻で決まる電源のステップが同じ格子点に重なると、指令の電源も「変わった後」で記録される（エンジンの口だけ）。`control/interface.py` の説明に例外として書く。
8. 設計書: `basic-design.md` 15.3 に、E1g の持ち越し（この一覧と A1 への注意）を書く。`np.errstate` の出入りの時間（約 0.7 µs と書いてあるが、検証の機械では 1.5 µs）を目安と書く。
9. 時間の上限を持つ実装者の試験 `buck_slow_control` は、進み具合の跳びの後退を見つけにくい（時間によらない試験が守っている）。「0.99 以上の最初の知らせが、所要時間の 9 割より前に来ない」を値の決まりに足す。
10. 受け入れ試験の軽微（検証役が直す）: `test_e1g_review_targets.py` 56 行の説明の数、`test_e1g_recheck_csv_notes.py` の `write_fails_midway` の名前、記録の「直す前で 11 件落ちる」の揺れ（9〜11 件）、`test_e1g_recheck_progress_errstate.py` の `Trace` が核の引数の位置に頼っていること。
