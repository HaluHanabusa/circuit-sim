## いまの範囲: 絞った v0.1（D-071、2026-11-16）

目的は「学びと実績から収益へ」。まず、小さく完成させて、動くことを確かめる。

- **中身**: 降圧コンバータ（同期整流、電圧モード）1つ。設計目標を入れる → 初期ゲイン（解析式）→ スイッチングモデルで計算 → 評価（達成 / 未達 / 判定できない、未達の量）→ 画面と報告。
- **順番**: E1g（進行中）→ A0 の統合（PO の PC での Windows の確認待ち）→ E1f → E2a → A0d → A1 → A2 の一部（設計目標の入力と結果の表示）→ R1。H2 は並行（修正は済み。統合の手続きだけ）。
- **画面**: 方向は B 案（D-072）。設計書の第2版（デザインの基準と画面仕様。受け入れ基準 147 件）はブランチ `A0r` にあり、A0d で実装と一緒に入れる（D-073）。A0d の仕様の下書きは `A0r` の `docs/plan/A0d-ui-redesign-implementation.md`。
- **v0.1 の後**: VR1（教育用の VR ワールド。検証済みの計算結果を焼き込んで、電流の流れとスイッチの切り替えを立体で見せる。前段として、机上の画面の回路図の上で電流の流れを見せる）。前提は、全素子の電流とスイッチの状態の書き出し。
- **凍結（捨てない。v0.1 の反応を見て決める）**: I0〜I2 と A3（読み取りと AI）、A4、E1d、E1e、E1h、E1i、E2b、E3、D-068 の拡張（自由な回路、素子の水準、電動機）、`direction-proposal.md` の P1〜P5。

下の表の「状態」は、この範囲に入らないものも元のまま残してある。

## 順番の考え方

- エンジン（E）とアプリ（A）は並行で進める。触るファイルが重ならないため。
- v0.1 の時点でAIは不要。仕様JSONを手で書けば動く。AIが要るのは v0.3 から。
- 速度の改善は段階を決めない。測って遅いと分かった時点で入れる。
- 拡張（X）は v0.4 の後。それまでは「モーターの負荷を差し替え式にする」などの備えだけ守る。
