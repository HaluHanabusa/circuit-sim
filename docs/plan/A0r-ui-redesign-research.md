# A0r: 画面の見た目の練り直し（調査と方向の案）

担当: ux-designer ／ 次: PO が方向を選ぶ → 画面仕様とデザインの基準の改訂 → 実装（A0d）→ A1

## 背景

PO が Windows の実機で A0 の画面を確かめた（2026-11-16）。指摘は次のとおり。
- 全体的にデザインがよくない
- 字が小さく見づらい
- エディタの役割も持つので、もっと見やすくするべき

A0 の UX 確認は、画面仕様どおりかで合格を出した。仕様そのものの水準が足りていなかった。

見えている原因は3つ。
- 文字が小さい: 基準 13px、補足 12px、目盛り 11px。
- 日本語の字体: 字体の指定の先頭が欧文の Segoe UI なので、日本語は Windows が代わりの字体を選ぶ。そのため細く小さく出る。
- 1920 幅の大部分が空いたまま、強弱が無い。

## 範囲

1. **調査**: UI と UX に力を入れている今の製品とデザインシステムを調べ、何を、なぜそうしているかを、出典つきでまとめる。
   - 作業の道具・エディタ: コードエディタ、デザインツール、IDE の新しい UI、ノートやドキュメントの道具。
   - エンジニアリングの道具: 回路・シミュレーション・CAD のうち、Web やデスクトップで評価の高いもの。
   - デザインシステム: 文字の大きさの段階、密度、間隔、色。
   - 日本語の UI の文字組: Windows での字体の選び方、太さ、大きさ、行の高さ。システムの字体を使う場合と、字体を同梱する場合の得失。同梱する場合はライセンス（決まり7。OFL を使うなら決定記録が要る）とサイズ。
   - 他社の固有のデザインを写さない。調べるのは考え方と数値の傾向。
2. **方向の案**: 2〜3案を、名前の付いた別々の軸で作る（例: 「読みやすさ優先」と「密度と明瞭さ」）。
   - それぞれの理由と、失うものを書く。
   - 見本は、同じ画面を案ごとに描く。降圧コンバータのサンプルを開いて、結果が出た状態と、起動直後の状態。
   - PO が Windows のブラウザで開いて見比べる形にする（デザインのキャンバス）。
3. **PO が選んだ後**（同じ作業単位の続き）: `docs/design/design-system.md` と `docs/design/screens-v0.1.md` を、選んだ方向で改訂する。

## 受け入れ基準

1. `docs/design/research-ui-v2.md` に調査の結果がある。出典（URL）つきで、数値の傾向（基準の文字の大きさ、行の高さ、部品の高さ、間隔）と、このアプリへの当てはめ方が書かれている。
2. 方向の案が2〜3つ、名前の付いた別々の軸で、PO が実物の字体で見比べられる形で示されている。
3. PO が選んだ方向で、デザインの基準と画面仕様が改訂されている。文字の大きさ、字体の指定、部品の高さ、空いた領域の使い方、空の状態の見せ方を含む。
4. UX のゲートの見方に、次を足す。
   - 実物の大きさ（1920×1080、表示倍率 100%）と Windows の字体で見ること。
   - 今の水準の製品と比べること。
5. `python scripts/check.py` が通る。
