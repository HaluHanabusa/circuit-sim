## 1. 結論

### 1.1 勧める構成

読み取りを4つの段に分け、段ごとに担い手を決める。

```
資料（PDF / Word / Excel / テキスト / メーカーのモデル / ネットリスト）
  │ ① 開く（コード、決定的）: 文字・表のセル・線の座標を、位置ラベルつきで取り出す。読めないページは一覧に出す
  ▼
位置ラベルつきの共通テキスト（セル単位）＋ 図の領域
  │ ② 候補を取り出す
  │    スクリプト: メーカーのモデル、Excel の定数表、ネットリスト、きれいな表、ベクターのグラフ
  │    生成 AI   : 本文の記述（値、換算の約束、設計目標、制御の方式）、スクリプトが「あいまい」と返した表や行
  ▼
値の候補（値、単位、条件、出典の位置、だれが取り出したか）
  │ ③ 照合と検査（コード、決定的。だれが取り出した値にも同じものを掛ける）
  │    出典の位置にその値があるか / 単位と次元 / 範囲 / 素子の式との整合 / 複数の出典の突き合わせ
  ▼
層A の候補（照合の状態つき）  ─►  ④ 人が確かめる（UC-11）  ─►  計算
```

| 対象 | 主 | 補助 | 生成 AI | 理由 |
|---|---|---|---|---|
| メーカーのモデル（SPICE の `.model` / `.subckt`、PLECS の XML） | スクリプト（構文解析） | — | 使わない | 形式が決まっていて、同じ入力から同じ結果が出る。作り話が起きない。市販の道具もこの道を主にしている（10章） |
| Excel の定数表、テキスト、ネットリスト、回路図エディタのファイル | スクリプト | 生成 AI（見出しの無い表など、規則で読めないものだけ） | ほぼ使わない | セル番地や行番号がそのまま出典になる |
| データシートの表（定格、電気的特性） | スクリプト（表の取り出し＋規則） | 生成 AI（あいまいな行だけ）。必ずコードで照合 | 補助 | 試しで、きれいな表は 37/37。崩れた表は 8/11 で付け違いが1件。あいまいを検出して AI と人に回す形が要る（5章） |
| データシートのグラフ（Coss–Vds など） | ベクターの図はスクリプト（座標を直接読む） | ラスターの図は、人が画面で点を打つ。AI に画像を読ませるのは PO の判断の後 | 当面使わない | 試しで誤差 0.5% 以内。ラスターに使える学習済みモデルは、ライセンスの判定がすべて ×（3章） |
| 設計書の本文（Word / PDF）: 定数、設計目標、制御の方式 | 生成 AI（共通テキストから） | スクリプト（「記号 = 値 単位」の形の拾い出し）。必ずコードで照合 | 主 | 文章の読み取りは規則では書ききれない。ただし AI だけの研究の水準は完全一致 0.86 程度で（4章）、照合が前提 |
| 回路の構成 | 文字で書かれた資料（ネットリスト、回路図エディタのファイル）はスクリプト。それ以外は、人が書くか、出発点の例から選ぶ | 本文の記述から AI が下書きを出すことは、PO の判断の後（P-h）。出すなら、コードが回路として検証し、図にして人が確かめる | 当面使わない | 素子1つの誤りで別の回路になる。電動機の検討も、AI が出すのは素子の値までにすることを勧めている |
| 回路図の画像、スキャン PDF、銘板の写真 | 対象外（「読めなかったもの」として出す。D-002 のまま） | — | 使わない | 画像を端末の外に出す判断と、ライセンスの通る OCR が無いこと |
| 電動機（銘板、試験の記録、等価回路定数） | 値と、換算の約束（線間か相か、実効値か波高値か、など）の読み取りは、上の表・本文と同じ。試験の記録から等価回路定数を求めるのは式（スクリプト） | — | 読み取りの補助だけ | 定数の算定は決定的な計算（決まり1）。約束が資料に無ければ、既定で埋めずに人に聞く |

### 1.2 生成 AI を使う範囲と、使わない範囲

- **使う**: (1) 本文の記述から、値・換算の約束・設計目標・制御の方式の候補を出す。(2) スクリプトが「あいまい」と返した表や行を読む。
- **PO の判断の後に使うかどうかを決める**: (3) 本文から、回路の構成の下書きを出す（P-h）。(4) 図の画像を読む（P-a）。(5) 結果の説明（P-5）。
- **使わない**: メーカーのモデルの読み取り、Excel とネットリスト、きれいな表、ベクターのグラフ、単位の換算、等価回路定数の算定、照合と検査、計算の経路のすべて。
- **AI が無くても動くもの**: 上の「使わない」の全部。素子の設定の自動化のうち、メーカーのモデルとデータシートの表・グラフ（文字のある PDF）は、オフラインで、端末の外に何も出さずに動く。

### 1.3 既存のものと自作（11章の要約）

- 土台（PDF の解読、Word と Excel の読み取り、XML、構文解析の道具、言語モデルそのもの）は、すべて既存で足りる。使う既存のライブラリは Python の部分だけで約 7〜8 万行。
- 自作は、その上の「領域の知識」（素子の項目の辞書、条件の扱い、表のあいまいの判定）と「照合と検査」「評価」。見積もりは 6〜9 千行で、行数では読み取りの領域の 1 割ほど、作る手間ではほぼ全部がここに掛かる。
- 設計書やデータシートから、素子の設定を自動で作って照合つきで渡す製品は、調べた範囲では見つからなかった（10章）。

### 1.4 ライセンスの判定の要約（3章）

- **○ だけで組める**: pdfminer.six（PDF の文字と線）、openpyxl（Excel）、mammoth または標準ライブラリ（Word）、lark / pyparsing（構文解析）、sexpdata、pypdf、標準ライブラリ。表の取り出しは、pdfplumber（MIT）の表の部分を取り込んで使う（Pillow と pypdfium2 を入れなくても動くことを確かめた）。
- **△ まで許すと加わる**: pdfplumber を普通に入れる形（Pillow と pypdfium2 が付く）、python-docx（lxml）、ページを画像にする処理。
- **×**: PyMuPDF、Camelot、Docling、PaddleOCR、RapidOCR、EasyOCR、img2table、unstructured、MinerU、Marker、markitdown、pikepdf、Poppler、onnxruntime、Table Transformer、WebPlotDigitizer、LineFormer、DePlot、PySpice、spicelib、ngspice、quantulum3。主な理由は、OpenCV のホイールが FFmpeg（LGPL-2.1）を同梱していること、Shapely の GEOS（LGPL-2.1）、MPL-2.0 の部品（certifi、tqdm、Eigen）。

## 2. 読み取る対象の整理

### 2.1 設計書（Word、PDF、Excel、テキスト）

| 読むもの | 現れ方 | 出典の位置の形 |
|---|---|---|
| 定数（L、C、負荷、周波数など） | Excel の定数表、Word の表、本文の「L = 47 µH とする」 | Excel: シート名とセル番地。Word: 節の見出し、段落の番号、表の番号と行・列。PDF: ページ、表、行・列 |
| 設計目標（オーバーシュート、整定時間、位相余裕など） | 本文、仕様の表 | 同上 |
| 制御の方式（電圧モード、電流モード、PI / PID、制御周期） | 本文 | 節と段落 |
| 回路の構成（どの素子がどうつながるか） | 本文の記述、回路図の画像、添付のネットリスト | 本文は節と段落。画像は対象外 |

気づいた点（試し）:
- Word のファイルにはページの考えが無い（ページは表示のときに決まる）。出典は「節の見出し＋段落の番号」「表の番号＋行・列」で持つ。
- Excel の数式のセルは、ファイルに計算結果が保存されていなければ値が無い。そのときは「読めなかったもの」に入れる。
- 互換文字の単位（D-037、U-9）: NFKC の正規化で `㎌` は `μF`、`㎑` は `kHz`、全角の `ｍＨ` は `mH` になり、大文字と小文字は保たれる。ただし本文に掛けると全角の括弧なども変わるので、**単位と数値の部分にだけ掛け、元の表記を出典に残す**形を勧める。エンジンの決まり（D-018）は変えない。

### 2.2 データシート（PDF）

仮置きの一覧。素子のモデルが使う項目は、`devices-and-solver.md` に合わせ直す。

| 区分 | 項目の例 | 現れ方 | 読み方 |
|---|---|---|---|
| 絶対最大定格 | VDSS、ID（温度ごと）、VGSS（正負）、Tj（範囲） | 表。値が「−8 / +22」「−55 to +175」の形になることがある | スクリプト |
| 電気的特性 | RDS(on)（VGS・ID・Tj の条件つき）、VGS(th)、VCE(sat)、Ciss / Coss / Crss、Qg / Qgs / Qgd、td(on) / tr / td(off) / tf、内部ゲート抵抗 | 表（Min / Typ / Max、条件の列）。項目や条件のセルが複数の行にまたがる | スクリプト。あいまいな行は AI |

データシートの読み取りで難しいのは、値そのものより**条件**（どの温度、どのゲート電圧、どの品番の値か）で、誤りの多くは「正しい値を、別の条件や別の項目に付ける」形で起きる（5章）。値は必ず条件と対で持つ。

扱いの前提: **同梱も再配布もしない。利用者が自分で入手したファイルを、端末の中で読むだけ**。読んだ結果（係数や表）をプロジェクトのファイルに保存してよいか、モデルを別の形式に読み替えることが各社の規約で許されるかは、公開の前に確かめる（9章）。

読み取りの限界:
- 係数だけの `.model`（ダイオードの IS / RS / CJO / VJ / M / TT、MOSFET の VTO / KP など）と、定数の R / L / C は、そのまま素子の値にできる。
- 式で書かれた素子は、式を読めても、こちらの素子のモデルに合う形にするには特性を計算して当てはめる必要がある。当面は「読めたが対応していない部分」として報告する。

### 2.4 電動機

読むべき値の一覧は、`/home/claude/academic/academic-extension.md` の 8章（誘導機、PMSM、同期機、DC 機、インバータと制御、機械系）を正とする。読み取りの側から見た要点は次のとおり。

| 資料 | 読むもの | その先 |

電動機で特に効くのは、値に付く**換算の約束**（線間か相か、実効値か波高値か、電気角か機械角か、V/krpm か V/(rad/s) か、Y か Δ か、単位法の基準、温度）。同 8章は、約束が設計書で確かめられなければ、値が読めても「約束が不明」として人に聞く、としている。読み取りでは、**約束も値と同じく、出典つきで読む対象**にする（6.1、6.3）。既定の約束で埋めない。

試験の記録から定数を求めるときの仮定（漏れリアクタンスの分け方など）は、「仮定」の印を付けて、利用者が認めるまで残す（同 8.7）。この印も、6.3 の状態に入れる。

### 2.5 回路図の画像

## 3. 候補の一覧とライセンスの判定

### 3.1 判定で分かったこと（先に）

1. **メタデータの表示だけでは判定できない。** OpenCV のホイールは「Apache 2.0」と名乗るが、同梱の第三者ライセンスの文書に「FFmpeg をすべてのパッケージに同梱する」とあり、LGPL-2.1 の全文が付いている。Camelot、Docling、PaddleOCR、RapidOCR、EasyOCR、img2table は、どれも OpenCV を必須の依存に持つ。
2. **文書の解析の学習済みモデルの一式は、厳格な基準ではほぼ全滅する。** OpenCV のほか、Shapely（GEOS が LGPL-2.1）、certifi（MPL-2.0）、tqdm（MPL-2.0 AND MIT）、python-bidi と crc32c（LGPL）、onnxruntime（第三者の一覧に Eigen の MPL 2.0）が、依存の木に入る。
3. **担当の外だが、判定の基準に関わること。** 手元の numpy 2.5.3 と scipy 1.18.1（Linux のホイール）のライセンスの文書には、同梱物として libquadmath が LGPL-2.1-or-later と書かれている。3段階の基準を文字どおりに当てると × に当たる。Windows のホイールは確かめていない。オーケストレーターに引き渡す（12章）。
4. **既存の検査を広げる必要がある。** 依存のライセンスの試験（`tests/test_app_licenses.py`）がメタデータだけを見ているなら、1〜3 は見抜けない。ホイールの中のライセンスの文書まで読む検査にする（tooling-engineer、release-manager）。

### 5.2 グラフの数値化（`extract_curve.py`）

- ベクターの図（両対数、3本の曲線）から、曲線の座標を PDF から直接取り、主目盛りの線と「10 の何乗」の文字を対にして軸を校正し、曲線の名前は近くの文字から決めた。学習済みモデルも AI も使わない。
- 7点 × 3本 = 21 点で、**最大の相対誤差 0.47%**（軸の校正の残差は 1e-4 桁以下）。
- 表の値（Coss 98 pF、Ciss 1650 pF）と、同じ条件のグラフの値（97.1 pF、1602 pF）を突き合わせられる。差は 1% と 3%。複数の出典の突き合わせ（6章）の許容をどう決めるかの材料になる。
- 限界: 図がラスターの画像なら使えない。実在のデータシートで、図がベクターである割合は確かめていない（未確認。利用者の手元の資料で測る必要がある）。線形の軸、凡例で名前を示す図、複数の条件の曲線は試していない。

### 5.3 出典の照合（`verify_sources.py`）

手で書いた模擬の「AI の答え」11件（誤りを7種類仕込んだ）を、コードが PDF から取り出した行と照合した。

| 仕込んだもの | 判定 |
|---|---|
| 正しい値 | 照合済み |
| 正しい値（単位を換算して答えた: 1650 pF を 1.65 nF） | 照合済み（換算して一致、と添える） |
| 作り話（文書に無い値） | 検出: 出典の位置に値が無い。文書のどこにも無い |
| 単位の取り違え（pF を nF） | 検出: 数字はあるが単位が違う |
| 桁の取り違え（45 mΩ を 45 Ω） | 検出: 同上 |
| 条件の取り違え（125 °C の値を 25 °C として） | 検出: 値はあるが条件が違う |
| 出典の場所の誤り | 検出: 別の場所にはある、と場所を示す |
| 行の付け違い（隣の行の値） | 検出 |
| **列の取り違え（Max の値を Typ として。行は正しい）** | **見逃し**（行までの照合では通ってしまう） |
| 図から読んだ値 | 「照合できない」と表示 |
| 正直な null | 不足として人に回す |

- 列の取り違えを見抜くには、**位置ラベルをセル単位（行と列）にして、列の見出しまで照合する**必要がある。I1 の設計に入れる。
- 素子の式との整合: Crss を 9.5 nF と取り違えた組は、次元の検査は通るが、Cgs = Ciss − Crss と Cds = Coss − Crss が負になるので検出できた。

### 5.4 SPICE のモデル（`parse_spice.py`）と、Excel・Word（`office_labels.py`）

- 自作の模擬の SPICE モデル（3つのサブサーキット）を、約 100 行の構文解析で読んだ。継続行、接尾語（`MEG`、`m`、`n`、`p`）を正しく読み、「そのまま使える素子だけ」「式で書かれた素子を含む」「暗号化されていて読めない」に分けられた。実在のモデルの方言（PSpice、LTspice）は試していない。
- Excel はセル番地、Word は節・段落・表の行と列を、位置ラベルにできた。互換文字の正規化は 2.1 のとおり。

## 6. 検証と、誤りに気づける仕組み

### 6.1 誤りの種類と、守り

| 誤りの種類 | 起こすもの | 守り |
|---|---|---|
| 作り話（文書に無い値） | AI | 出典の位置（セル）に、同じ数字と単位があるかをコードが確かめる。無ければ値として入れない |
| 桁・単位の取り違え | AI、規則 | 単位まで含めた照合、次元の検査、範囲の検査、素子の式との整合 |
| 条件の取り違え（温度、ゲート電圧、電流） | AI、規則 | 値を条件と対で持ち、出典の行の条件と照合する |
| 換算の約束の取り違え（線間と相、実効値と波高値、電気角と機械角、V/krpm と V/(rad/s)、Y と Δ） | AI、規則、人 | 約束を、値とは別の読み取りの対象にして、出典を付ける。資料に書かれていなければ「約束が不明」とし、既定の約束で埋めない |
| 行・列・品番の付け違い | 規則、AI | セル単位の位置ラベル、行の記号と列の見出しの照合、あいまいの検出 |
| 図から読んだ値 | AI | 文字では照合できない。「照合できない」の印を付け、ベクターならスクリプトの値と突き合わせ、最後は人 |
| 読めないページ、暗号化、式の素子 | — | 黙って飛ばさず、「読めなかったもの」「対応していない部分」の一覧に出す |
| 文書どうしの食い違い（本文と表、表とグラフ、設計書とデータシート） | — | 片方に決めず、両方を出典つきで見せる（U-8） |
| AI が想定と違う経路で答えた | AI | 照合の相手は、コードが作った共通テキストだけ。AI の引用文は使わない |

### 6.2 検査の層（どの値にも、だれが取り出したかに関わらず掛ける）

1. **出典の位置の照合**: 値、単位、条件、項目の記号、列の見出しを、共通テキストのそのセルと比べる。単位を換算して一致する場合は「換算して一致」とし、文書の表記を残す。
2. **単位と次元**: 項目ごとに決まった次元（RDS(on) は Ω、容量は F、電荷は C、時間は s）と合うか。`units.py` の厳格な読み方（D-018）を使う。
3. **範囲**: 項目ごとの、ありうる範囲の外なら注意を出す（エラーにはしない）。範囲の表は素子の担当と決める。
4. **素子の式との整合**: Cgd = Crss、Cgs = Ciss − Crss、Cds = Coss − Crss が正か。Qg ≥ Qgs + Qgd か。Min ≤ Typ ≤ Max か。定格と特性が矛盾しないか。式の一覧は素子の担当と決める。
5. **複数の出典の突き合わせ**: 表とグラフ、データシートとメーカーのモデル、スクリプトと AI。一致すれば確からしさが上がり、食い違えば両方を見せる。
6. **人の確認**（UC-11）: 値の行から、資料の該当箇所を開いて見比べる。

### 6.3 確認の画面に渡す情報の形（ui-engineer、ux-designer へ）

値ごとに次を持つ。いまの `Quantity`（値、単位、出典の文字列）に足す形の案で、層A の版と欄の名前は E1g と合わせて決める。

| 欄 | 中身 |
|---|---|
| 値、単位 | SI 接頭語つきの、文書の表記に近い形 |
| 条件 | 値に付く条件（Tj = 25 °C、VGS = 18 V、ID = 20 A など） |
| 換算の約束 | 線間か相か、実効値か波高値か、など。約束ごとに出典を持つ。書かれていなければ「不明」 |
| 出典 | ファイル、種類（PDF / Word / Excel / テキスト / SPICE / XML / 手入力 / 既定値）、位置（ページ・表・行・列と座標、シートとセル、節と段落、行番号）、文書の表記そのまま |
| 取り出した者 | スクリプト / AI（プロバイダとモデルの名前）/ 手入力 |
| 照合の状態 | 照合済み / 換算して一致 / 照合できない（図など）/ 食い違い / あいまい / 約束が不明 / 仮定（利用者が認めるまで残す） |
| 検査の結果 | 次元、範囲、素子の式の注意 |
| 確認済み | 人が確かめたか |
| ほかの候補 | 食い違う値と、その出典 |

別に、「読めなかったもの」（ページ、図、暗号化）、「対応していない部分」（式で書かれた素子）、「不足」（記載が無い）の一覧を返す。

### 6.4 評価の方法と合格の水準

- **資料**: 自作の模擬資料を、生成の台本で作る（試しの `make_mock.py` を育てる）。書式の違い（罫線の有無、結合セル、脚注、2段組み、品番ごとの列、日英、単位の書き方）を組み合わせ、正解を一緒に出す。設計書（Word、Excel）、SPICE のモデル、XML も自作する。リポジトリに実在のデータシートは置かない。
- **実在の資料での確かめ**: 開発者の手元だけで行い、結果の数字だけを記録する。資料の一覧（URL）を置くかどうかは 9章の P-g。
- **測るもの**（値を単位に数える）:
  - 記載のある値の正解率（値、単位、条件、出典の位置のすべてが合う）
  - 出した値の正しさ（出した値のうち、正しいものの割合）
  - 付け違いの率（文書にある値を、別の項目や条件に付けた）
  - 作り話の率（文書に無い値を出した）。**記載の無い項目を、評価の資料にわざと入れて測る**。作り話は、値が無いところで起きるため
  - null の正しさ（記載の無い値を、null のまま返した割合）
  - 「読めなかったもの」の検出（読めないページが一覧に出た割合）
- **件数**: いまの I2 の基準は「自作サンプル 10 件」。1件 15 値なら 150 値で、誤りが 0 件でも、言えるのは「誤りの率は 2% 以下（95% の確からしさ）」まで。1% 以下と言うには 300 値、0.5% 以下なら 600 値が要る。生成の台本で 30 件・450 値以上と、記載の無い項目 100 以上を勧める。
- **合格の水準の案**:

| 経路 | 水準 |
|---|---|
| スクリプト（モデルのファイル、Excel、ネットリスト） | 「読み取った」と返した値は誤り 0、付け違い 0。読めないものは読めないと返す |
| スクリプト（PDF の表、ベクターのグラフ） | 「読み取った」と返した値は誤り 0、付け違い 0（あいまいは、あいまいと返す）。記載のある値の回収率は測って記録する（目安 80% 以上）。グラフは、曲線の値の誤差 2% 以内 |
| AI を含む全体（I2 の基準を引き継ぐ） | 記載のある値の正解率 95% 以上。**照合を通って値として入ったものに、作り話 0**。あわせて、照合の前の AI の答えの作り話の率を記録する |
| 照合と検査 | 仕込んだ誤り（6.1 の種類ごと）をすべて検出する。照合できない値に、必ず印が付く |

- **試験と本物の AI**: 試験は記録した応答で行う（決まり11）。本物の AI での評価は、試験の外の手順として人が流し、プロバイダ、モデル、日付と一緒に結果を記録する。モデルが替わったら流し直す。

## 7. 勧める構成

### 7.1 対象ごとの主と補助

1.1 の表のとおり。考え方は3つ。

1. **形式の決まった資料から先に読む。** メーカーのモデル、Excel、ネットリストは、AI を使わず、作り話が起きない。素子の設定の自動化のうち、確実に価値が出るのはここ。
2. **PDF の表とグラフは、スクリプトで読めるところまで読み、読めないところを「読めない」と言えるようにする。** あいまいな部分だけを AI に回すと、端末の外に出す量も減る。
3. **AI の答えは、値ではなく「候補」として扱う。** 照合を通ったものだけが値になる。

### 7.2 決まり3 の改め方（提案）

いまの決まり3: 「仕様は2層。AI が出力するのは層A（`Spec`）だけ。値は `null` を許し、出典（`source`）を持つ。層B（`Netlist`）はコードが展開する」。

自由な回路の記述に合わせて、次のように改めることを提案する。

> 3. 仕様は2層。層A は人と AI が書ける形で、回路の記述（素子と接続）、素子の値、制御、設計目標を持つ。層B はエンジンが読む形で、コードだけが作る。
>    - AI が出すのは、層A の「候補」だけ。AI は層B を書かない。
>    - 値は `null` を許し、出典（位置）、取り出した者（スクリプト / AI / 手入力）、照合の状態を持つ。
>    - AI の候補は、コードが出典の位置と照合して、通ったものだけを値として入れる。通らないものは、値として入れず、確認が要る候補として人に見せる。
>    - 回路の記述の候補は、コードが回路として検証し（解けるか、浮いた部分が無いか）、図にして人が確かめてから使う。
>    - 形式の決まった資料（メーカーのモデル、表計算、ネットリスト）は、AI を通さずにスクリプトで読む。

変えないもの: 決まり1（計算の経路は決定的）、決まり4（推測で埋めない）、「AI に元のファイルを読ませない」。変わるもの: 層A が回路の記述を持つようになる。そのぶん、照合と人の確認を決まりの中に書く。

**AI に回路の記述の候補まで出させるかどうかは、分けて決める**（P-h）。電動機の検討（`academic-extension.md` 9.3）は、AI が出すのは素子の値（出典つき）までにし、回路のつなぎ方は人が書くか出発点の例から選ぶことを勧めている。この検討も、当面はそれに合わせることを勧める。理由は3つ: 値は出典の位置と照合できるが、回路のつなぎ方は本文の1か所と照合できない。誤った回路でも計算は通る。文字で書かれた資料（ネットリストなど）があれば、スクリプトで確実に読める。上の文面の4つ目の項目（回路の記述の候補）は、PO が認めた場合の決まりとして書いた。認めない場合は、その項目を「AI は回路の記述を出さない」に替える。

### 7.3 プロバイダ層

- 公開するのは `extract` と `explain` の2つのまま。`extract` に渡すのは、共通テキストのうち AI に回す部分と、答えの形（スキーマ）。
- AI に道具を持たせない（ファイルを読ませない、検索させない）。渡した文字だけから答えさせる。
- 応答のキャッシュの鍵は、共通テキスト、スキーマ、プロンプトの版、プロバイダとモデルの名前のハッシュ。
- 図の画像を渡す口は、P-a の判断の後に足す。

### 7.4 ○ だけで組む案と、△ まで許す案

| 部分 | ○ だけの案 | △ まで許す案 | 違い |
|---|---|---|---|
| PDF の文字、線、曲線 | pdfminer.six（○※） | 同じ | — |
| PDF の表の検出 | pdfplumber の表と文字の部分を、ライセンスの表示を付けて取り込む（約 3,400 行。画像の部分は取り込まない） | pdfplumber を普通の依存として入れる（Pillow と pypdfium2 が付く） | ○ の案は、取り込んだ部分を自分で追いかける手間が出る |
| ページを画像にする（確認の画面で該当箇所を見せる、図を切り出す） | しない。画面は、ブラウザ側で PDF を表示して位置を示すか、該当の行の文字を見せる（画面の部品のライセンスは ui-engineer が確かめる） | pypdfium2 で画像にする | ○ の案では、図の切り出し（AI に画像を渡す、人が点を打つ下絵）をサーバー側で作れない |

どちらの案でも、勧める構成（1.1）は組める。**差が出るのは、ページを画像にする処理だけ**。まず ○ だけの案で始め、確認の画面の設計（A3）で画像が要ると分かった時点で、Pillow と pypdfium2 を PO に諮るのがよい。

× を PO が個別に認めた場合に広がるのは、スキャン PDF と画像の表（Docling、Table Transformer、Tesseract）。値の正しさの保証が無く、照合もできない（照合の相手になる文字が無い）ので、認められても優先度は低い。

| I2c | （PO の判断の後）回路の構成の下書き（P-h）、図の画像を AI に渡す口（P-a）、端末の中のモデルのプロバイダ（P-c）、説明文（P-5） | あり | P-a、P-c、P-h | — |
| A3 | 確認の画面: 値、条件、出典、照合の状態、不足、読めなかったもの、食い違い。図の上で点を打つ補助は A3b | — | 6.3 の形 | いまの A3 の基準に、照合の状態が見えることを足す |

順番の考え方: **AI より先に、評価の土台と照合を作る**（I0、I2a）。照合が無いまま AI をつなぐと、誤りを測る手段が無い。AI の無い経路（I0、I1a〜I1c）だけで、素子の設定の自動化の主な部分が動く。v0.3「読める」は I0 + I1a + I1b + I1c + A3 で成り立ち、I2b は後から足せる。

### 8.2 最初の一歩

**I0**。AI も、PO の判断も、ほかの検討の結果も要らない。試しの台本（表の取り出し、照合）が出発点になる。ここで測った回収率が、AI にどれだけ回す必要があるかの根拠になる。

あわせて、利用者（PO）の手元の実在のデータシートとメーカーのモデルで、図がベクターである割合、表の書式、モデルの方言を、手元だけで確かめる（資料は持ち出さない）。

## 9. PO が決める必要のある点

## 10. 既存の製品、サービス、研究

設計書やデータシートから、回路のモデルや素子の設定を自動で作るものがあるかを調べた。

| もの | できること | 自動の度合い |
|---|---|---|
| MathWorks Simscape Electrical（R2026b） | データシートのグラフを、専用のアプリで**人が点を打って**数値にする。メーカーの XML（日立、Infineon、Wolfspeed）を取り込む関数がある | グラフは手作業。XML の取り込みは自動 |
| PLECS | メーカーが配る熱モデル（XML）を読む。モデルが無い素子のために、データシートのグラフの情報の取り込みを助けるウィザードがある（細かい動きは確かめられなかった） | メーカーのモデルが主。グラフは補助つきの手作業と見られる（未確認） |
| onsemi の道具 | 自社の SPICE モデルから、利用者の条件に合わせた PLECS 用のモデルを作る | 自社の素子だけ |
| Keysight のモデル生成の道具 | 測定データから、SiC / GaN / IGBT のモデルを作る | データシートが入力とは書かれていない |
| Flux の AI | データシートの PDF から、回路図の記号、ピン、フットプリントを作る | 自動。ただし対象は記号とフットプリントで、シミュレーションのモデルではない |
| datasheet2spice（公開の道具） | データシートの値を人が JSON に書き、グラフは数値化の道具の CSV を取り込んで、SPICE のモデルを作る | 入力は手作業 |
| 研究（D2S-FLOW、2025年） | 言語モデルでデータシートから係数を取り出し、SPICE のモデルを作る。完全一致 0.86 | 研究の段階 |

分かること:
- 市販の道具は、**メーカーが配るモデルの取り込みと、人による数値化**の組み合わせ。PDF から自動で素子の設定を作って、照合つきで渡すものは、調べた範囲では見つからなかった。
- 「メーカーのモデルを読む」は差別化にならない（どこもやっている）が、無いと見劣りする。
- 差別化になりうるのは、「データシートの表とグラフを自動で読み、出典と照合の状態を値ごとに見せ、設計目標からゲインまでつなぐ」こと。作るものは、読み取りそのものより、**誤りに気づける形で渡す部分**。
- 調べ方の限界: 検索と公式のページ数件。各社の最新の機能を網羅してはいない。

## 11. 既存のものと自作の割合の見積もり

| 機能 | 既存のもの | 自作する部分 | 割合の目安（既存 : 自作） |
|---|---|---|---|
| ファイルを開く（PDF の解読、Word、Excel、XML、文字の正規化） | pdfminer.six、openpyxl、mammoth、標準ライブラリ | 位置ラベルの付け方、読めないページの判定 | 95 : 5 |
| 表の構造の取り出し | pdfplumber の表の検出 | 見出しから列を決める規則、結合の引き継ぎ、あいまいの検出 | 60 : 40 |
| 値の解釈（項目の記号と別名、条件、Min / Typ / Max、単位） | 既存の `units.py`、正規表現 | 素子の項目の辞書と規則 | 20 : 80 |
| グラフの数値化（ベクター） | 座標の取り出し | 軸の校正、曲線の同定、表との突き合わせ | 40 : 60 |
| グラフの数値化（ラスター） | 使えるものが無い | 人が点を打つ画面（A3b） | 0 : 100 |
| メーカーのモデルの読み取り | lark / pyparsing、標準の XML | 方言の文法、素子のモデルへの対応づけ | 30 : 70 |
| 回路の資料の読み取り | sexpdata、構文解析の土台 | 接続の組み立て、層A への対応づけ | 30 : 70 |
| AI による抽出 | 言語モデルそのもの、出力の形を縛る仕組み、pydantic | プロバイダ層、スキーマ、プロンプト、キャッシュ | 70 : 30 |
| 照合と検査 | ほぼ無い | 全部 | 10 : 90 |
| 評価の仕組み | pytest、模擬資料を作る道具 | 生成の台本、正解、採点 | 30 : 70 |

- **行数で見た見積もり**: 自作は 6〜9 千行（試験を除く。試しの台本 930 行が、表、グラフ、照合、SPICE の骨格に当たる）。使う既存のライブラリは、Python の部分だけで約 7〜8 万行（pdfminer.six 2.1 万、pdfplumber 0.45 万、openpyxl 2.9 万、pyparsing 1.3 万。Word に python-docx を使うなら 1.6 万が加わる。手元で数えた。PDF や XML を解読する C の部品と、言語モデルは含まない）。**自作は行数で 1 割ほど**。○ だけの案では、取り込む pdfplumber の約 3,400 行が「既存だが自分で追いかける」分として加わる。
- **手間で見た見積もり**: 既存の部分は入れるだけなので、作る手間のほぼ全部が自作の部分に掛かる。
- **D-069 (3) への答え（読み取りの領域について）**: この領域は「既存のライブラリの上の薄い層」にはならない。土台は既存で足りるが、素子の設定に仕立てる規則と、照合と、評価は、既存のものに無い。ここが、既存の製品に無い部分（10章）とも重なる。

## 12. 既知の制限、未確認、ほかの担当に頼みたいこと

**この検討の制限**
- 試しは自作の資料だけ。実在のデータシート、実在のメーカーのモデルでは確かめていない。
- AI の正しさは測っていない（本物の AI を呼んでいない）。数字は研究の報告による。
- 半導体素子の読むべき項目は仮置き（`devices-and-solver.md` が未着）。電動機は `academic-extension.md` の 8章に合わせた。

**未確認の一覧**
- メーカーの利用条件の本文（Infineon、ROHM、Microchip。ページが大きすぎて読めなかった）。PLECS の XML の中身の仕様。LTspice の `.asc` の公式の仕様。
- Poppler のライセンスの公式の文面、Gemma の利用条件（どちらもページを読めなかった）。
- cryptography と pydantic_core が静的に含む部品の内訳。lxml の Windows のホイールの同梱物。OS ごとのホイールの Windows 用の中身。
- 実在のデータシートで、図がベクターである割合。
- Tesseract が、数値と単位をどこまで正しく読むか。端末の中の小さな言語モデルの正しさ。

**ほかの担当へ**
- オーケストレーター: numpy と scipy の Linux のホイールに、libquadmath（LGPL-2.1-or-later）が同梱と書かれている。3段階の基準では × に当たる（3.1 の 3）。OpenCV を × とする判定と筋をそろえる必要がある。MPL-2.0 の certifi と tqdm は、通信をするライブラリの多くが引く。
- tooling-engineer、release-manager: 依存のライセンスの検査を、ホイールの中のライセンスの文書まで読む形にしてほしい（OpenCV の例は、メタデータでは見抜けない）。
- solver-engineer、control-engineer: 素子のモデルが使う項目と条件、素子の式との整合の一覧、範囲の表、等価回路定数の算定の式。メーカーのモデルのどの係数を、素子のモデルのどの値に当てるか。
- ui-engineer、ux-designer: 6.3 の情報の形。確認の画面で該当箇所を見せる方法（ページを画像にするか、ブラウザで表示するか）が、P-e に関わる。図の上で点を打つ補助（A3b）。
- E1g の担当: 層A の `source` を、文字列のまま残すか、位置と状態を持つ形に広げるか。
