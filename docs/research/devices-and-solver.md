## 0. 要点

1. **素子は約40種を、3つの水準（理想 / 区分線形 / 非線形）で整理した**（3章）。理想と区分線形の素子（順電圧つきのダイオードと IGBT、結合インダクタ、理想変圧器、従属電源、サイリスタ類、飽和つきのオペアンプ、損失の表、熱回路）は、いまの区分線形の枠で書ける。寄生容量つきの MOSFET・IGBT の「切り替えの過渡」は、非線形の解法が要る。
2. **既存のもので、この領域（素子と解法）をまかなえるものは見つからなかった**（2章）。
   - 素子の水準の SPICE 系のエンジンは、ngspice、Xyce、Qucs-S、Gnucap のどれも **×**。ngspice は本体が修正 BSD だが、`.param` を処理する numparam（LGPLv2 以降）が、実行ファイルにも共有ライブラリにも無条件で結合される（公式のソースの構成ファイルで確かめた）。外して組む選択肢は無い。Python の口（PySpice、InSpice、spicelib）は GPL。
   - 緩いライセンスの SPICE 系は SpiceSharp（MIT、C#）だけ見つかった。最新版が 2024-10 で、.NET の処理系が要る（判定は △）。この検討では動かせていない（未測定）。
   - 緩いライセンスの、区分線形のパワエレ向けのエンジンは見つからなかった（PLECS・PSIM は商用、GeckoCIRCUITS は GPL）。
   - **○ だけで組める案は無い。** 数値計算の土台の NumPy・SciPy が、Windows で △、Linux・macOS で ×（道具の比較 7.2）だからで、この領域に限った話ではない。
   - 使えるのは「部品」と「式」: SUNDIALS（BSD-3、ソースから組めば ○）、ngspice の素子モデルのソースコード（修正 BSD の部分）と Modelica 標準ライブラリ（BSD-3）の式の移植、メーカーのアプリケーションノートの式。
3. **解法は、2つの水準を持つ案 (d) を勧める**（4章）。系統の水準（system level）は、いまの区分線形・固定刻みのエンジンをそのまま使い、線形と区分線形の素子を足す。素子の水準（device level）は、非線形の解法（ニュートン法と可変の時間刻み）を別の核として作り、ダブルパルス試験のような短い窓だけを計算する。決まり6 の「モデルの種類（詳細度）」に4つ目として足す形になる。
4. **実測で分かったこと**（4章、付録A）。
   - いまのエンジンの速さは、ngspice に対する優位ではない: 同じ降圧コンバータ 10 ms で、いまのエンジン 0.63〜0.81 秒、ngspice-42 は同じ細かさで 0.57 秒、刻みを任せると 0.093 秒。いまの核は、書き換えずに Numba で包むと 0.10 秒（8.1 倍、結果はビット一致）。
   - 区分線形の枠に線形の寄生容量を足しても、損失のエネルギーは収支として合うが（細かい刻みとの差 +6.5%）、切り替えの波形は物理と合わない（ターンオンの電流の尖頭値がオン抵抗で決まり 216 A、立ち上がり 4.6 ns）。解像するにはステップ数が 250 倍要る。
   - 寄生容量つきの MOSFET のダブルパルス試験を、3つの解法（SUNDIALS の IDA、ngspice、最小限の自作）で解くと、7つの指標が 1% 以内で一致した。自作は約 140 行（素子の式を除く）で、Numba に載せると 0.9〜2.5 秒（ngspice は 0.03〜0.22 秒）。
   - SPICE 型の解法は設定で壊れる: ngspice は 7 通りの設定のうち 3 通りで止まるか終わらず、IDA は許容誤差 1e-4 で指標が最大 5.9 倍ずれた。素子の式の側に発散止めが要る。
5. **最初の一歩は「ダブルパルス試験の計算」**（7章の E4a）: 素子の水準の核と、MOSFET（寄生容量つき）とダイオードのモデル。いまのエンジンと別のモジュールなので、v0.1 と E2 の計算の速さと決定性に触れない。
6. **この領域で既存のものが占める割合は、工数で 2〜3 割**（8章）。大半は自作になる。エンジンは差別化の部分ではないが、D-069 のもとで使える既存のエンジンが無いので、作るしかない。

## 2. 既存のものの候補と判定（D-069）

### 2.1 判定の決まり

道具の比較 7.1 と同じ。**○**: 本体・同梱物・実行時の依存のすべてが MIT、BSD-2/3、Apache-2.0、ISC、PSF、zlib、パブリックドメイン相当。**△**: コピーレフトではないが、一覧に無いライセンスが混ざる（何が混ざるかを書く）。**×**: GPL / AGPL / LGPL / MPL などのコピーレフト、非商用限定、条件が不明、確かめられなかったもの。

確かめ方（2026-11-16）: 公式のリポジトリの LICENSE を取得して読んだ（[L1]）。Python のパッケージは PyPI の登録情報（[P1]）と、ホイールの中身（scikit-sundae、circulax、pathsim、motulator は実物を取得して開いた）。ngspice は、公式のソース一式（版 47）の `COPYING`、`configure.ac`、`src/Makefile.am` を読んだ（[G1]、[G2]）。NumPy と SciPy の判定は、道具の比較 7.2 に従う（この検討でも、Linux のホイールに libgfortran と libquadmath が入っていることを、手元の環境の `LICENSE.txt` で確かめた）。

### 2.2 ngspice は、使う部分が緩いライセンスだけで閉じるか

公式の `COPYING`（版 47、2026 年）の要点（[G1]）。

| 部分 | ライセンス | 外せるか（[G2]） |
|---|---|---|
| 既定（下の一覧に無いソース、試験、例） | 修正 BSD（Modified BSD。3条項） | — |
| `src/frontend/numparam`（`.param`、サブ回路の引数の展開） | LGPLv2 以降 | **外せない。** `configure.ac` に切る選択肢が無く、`src/Makefile.am` が `libnumparam.la` を、実行ファイル（ngspice）、`libspice`、共有ライブラリ（`libngspice`）のすべてに無条件で結合する |
| `src/maths/KLU`（疎行列の解法） | LGPLv2 | 既定で入る。`--disable-klu` で外せる |
| `src/osdi`（Verilog-A のモデルを読む口） | MPLv2.0 | 既定で入る。`--disable-osdi` で外せる |
| `src/xspice/icm/table`（表のコードモデル） | GPLv2 以降 | 別のファイル（コードモデル）なので、配らなければ入らない |
| `src/tclspice.c` | LGPLv2 | Tcl の口を使わなければ入らない |
| `src/xspice`（上を除く）、`src/spicelib/devices/ndev` | パブリックドメイン | — |
| `src/maths/sparse` | MIT | — |
| 説明書 | CC-BY-SA 4.0 | — |

結論。

- **ngspice を組み込む（同梱する、共有ライブラリを読み込む）のは ×。** KLU、OSDI、表のコードモデルを外しても、numparam（LGPL）が残る。numparam を外すにはソースを書き換えることになり、それは既存のものの利用ではなく、派生版の自作と保守になる。
- **素子モデルのソースコードは、修正 BSD の側にある。** `src/spicelib/devices/` の `dio`（ダイオード）、`mos1`（レベル1）、`vdmos`（パワー MOSFET）、`bjt`、補助の `devsup.c` は、`COPYING` の例外の一覧に無い（各ファイルの著作権表示はカリフォルニア大学と ngspice の作者）。**式とコードを、著作権の表示を残して移植する（取り込む）ことはできる。** 判定は ○（取り込んだコードは自分で保守する）。
- Python の口は、PySpice（GPLv3）、InSpice（GPL-3.0 以降）、spicelib（GPL-3.0）のどれも ×（[P1]）。共有ライブラリの公式の口（`sharedspice.h`）は C の関数なので、ctypes で直接呼ぶ口は約 80 行で書けた（付録A の `ngshared.py`。この検討で動かすためだけに書いた）。
- 説明書の HTML 版は版 46（2026-03-31）。公式の FAQ も「ngspice のライセンスは修正 BSD」と書くが（[G6]）、部分ごとの例外は `COPYING` にしか無い。

### 3.8 入れないものと、その理由

| 素子 | 理由 |
|---|---|
| 伝送線路（無損失、有損失） | 設計目標からゲインを決める流れに要らない。配線は集中定数の L と C で表す。可変刻みでは遅延の履歴の扱い（畳み込み）が要り、解法が重くなる。ケーブルの反射によるモーター端のサージは、要望が出たら改めて検討する |
| ヒステリシスを持つ磁性体 | 履歴に依存し、検証が難しい。鉄損は抵抗か損失の式で扱う |
| 集積回路向けの MOSFET モデル（レベル2・3、BSIM など） | パワー素子のデータシートからパラメータが決まらない |
| 物理に基づく IGBT のモデル、SiC・GaN の専用モデル | 出典に当たれていない（未確認）。#22・#23・#29 の枠で近似し、足りない所を実測と比べてから決める |
| 式で書く非線形の従属電源（#13） | 式の評価を最内ループに持ち込むことになり、決まり2 と合わない。必要な非線形は、素子の種類として登録する（5.4） |
| メーカーの SPICE モデルの読み込み | ライセンスが各社の条件（×）で、暗号化も多い。データシートの数値と曲線から、3章の式のパラメータを決める |
| 小信号の AC 解析、雑音解析 | 線形化は E2a で扱う。雑音は対象外 |
| デジタル素子、混合信号 | 制御は制御ブロックの側で扱う |

| 状態を回路が決める素子の一般化 | サイリスタ（ラッチ）、飽和するオペアンプ、コンパレータ | ダイオードの「試して、違反したら反転」の仕組みに、素子の種類ごとの判定を足す |
| 状態ごとに E を変える | 飽和するインダクタ（折れ線の ψ–i） | `prepare` は対応している（F-3）。区分の切り替えで磁束を連続に保つ整合の式と、折れ線の切片（定数の項）が要る。設計が要る |
| 事象ごとの集計 | 損失の表 | 核の記録（切り替えの前の値を記録する決まり。D-019）から後で計算できる |

**限界。**

1. **なめらかな非線形**（電圧で変わる容量、MOSFET の飽和領域の定電流の特性）は、折れ線で近似すると状態の数が増え、1刻みの中で何度も状態が変わる。ゲート電圧でチャネルの電流が決まる動き（ミラー期間）は、理想スイッチでは表せない。
2. **寄生容量が作る速い過渡と固定刻み**（硬い系）。オン抵抗 × 寄生容量の時定数は ps〜ns で、既定の刻み（50 ns）の 1/10〜1/10⁵。切り替えの直後の後退オイラー法と数値減衰が、この成分を1刻みで消す。

**実測（付録A の A-4）。** 降圧コンバータ（24 V、100 kHz）の S と D に、並列の容量 10 nF ずつ（見やすくするため大きめ）を足した。

| 見たもの | 粗い刻み（50 ns。1周期 200 分割） | 細かい刻み（0.2 ns。1周期 5万分割） |
|---|---|---|
| ステップ数と計算時間（20 周期） | 4,000、0.02 秒 | 1,000,000、3.9 秒（250 倍） |
| 寄生容量による損失の増え方（入力と出力の収支から）。理論は ½·(C_S + C_D)·V²·f = 0.576 W ＋動作点が動く分 | +0.679 W | +0.638 W |
| そのうち、素子の i²·r を波形から積分して出る分 | +0.121 W（19%） | +0.611 W（96%） |
| ターンオンの S の電流の最大（負荷電流は約 2 A） | 10.8 A | 215.8 A（= 電圧 ÷ オン抵抗） |
| スイッチ節点の立ち上がり（10→90%） | 1刻みの中 | 4.6 ns（オン抵抗 × 容量で決まる） |

読み取れること。

- **損失のエネルギーは、粗い刻みでも収支として合う**（後退オイラー法が電荷を保つ。細かい刻みとの差は +6.5%）。ただし、素子ごとの波形には出ない（19%）。損失は、収支か表（#37）で求めることになる。
- **切り替えの波形は、刻みを細かくしても物理と合わない。** 電流の尖頭値と立ち上がりは、オン抵抗と容量だけで決まる。実物では、ゲートの駆動とチャネルの電流で決まる（#22〜#24）。サージ、dv/dt、di/dt は読めない。
- 解像するにはステップ数が 250 倍。10 ms の計算は 5,000 万ステップになり、上限（2,000 万）を超える。
- 系統の動きへの影響は出る（スイッチ節点の電圧の傾きで実効のデューティ比が変わり、負荷の電力が 24.2 W から 25.0〜25.2 W に増えた）。これは粗い刻みでも合う（出力電圧の差 36 mV）。

| 観点 | 評価 |
|---|---|
| 精度 | 理想と区分線形の素子は、いまと同じ（台形則の2次。解析解と照合できる）。寄生容量の損失は収支で合う。切り替えの波形は合わない |
| 速度 | いまのまま（1ステップ 3〜4 µs。Numba で 0.5 µs） |
| 実装の大きさ | 中（素子ごとに小〜中） |
| 決まり1・2・5・7 | すべて合う。依存は増えない |
| 検証 | 解析解（順電圧つきの整流の平均、結合インダクタの変圧比、位相制御の平均電圧、フォスター形のステップ応答）、収束次数、保存則 |

### 4.2 案 (b) 非線形の解法を足す（SPICE と同じ種類）

読み取れること。

1. **3つの独立な解法が、1% 以内で同じ答えに近づく**（モデル間の一致）。MOSFET の静特性は、ngspice の VDMOS とこちらの式で 32 点の相対差が 4e-7 以下。
2. **アプリケーションノートの式との照合。** しきい値に届くまでの時間は、式 3.136 ns に対して計算 3.162 ns（+0.9%）。電圧の立ち下がりは、ミラー期間の式 R_G·Q_gd/(U_Dr − U_plateau) = 4.56 ns に対して計算 6.12 ns（+34%）。この式は、チャネルの電流が出力容量とダイオードの容量も放電すること、配線のインダクタンスを見ないので、目安に留まる。ターンオフの電圧の最大は、瞬時に遮断したときの上限 V + I·√(L_σ/C_oss) = 589 V の内側の 477 V。
3. **設定で壊れる。**
   - IDA は、許容誤差 1e-4 では指標が最大 2.3〜5.9 倍ずれた。1e-6 まで締めると合う。汎用の解法の既定の設定を、そのまま信じられない。
   - ngspice-42 は、同じ回路で、試した 7 通りの設定のうち 4 通りが通り、3 通りが通らなかった: reltol 1e-6 と、reltol 1e-4 で最大刻み 0.1 ns の2つは 60 秒で終わらず、reltol 1e-5 に電流と電圧の絶対許容誤差を締めた組は「Timestep too small」で止まった。
   - 素子の式を変えた別の試しでも止まった: ダイオードに拡散電荷（TT = 5 ns）を入れると既定の設定で止まり、非線形の容量を式（電荷の式）で与える書き方は「singular matrix」の警告の後に止まった。
   - 最初の IDA の試しは、ダイオードの指数が反復の途中で 1.5e10 A になり発散した。**素子の式の側に発散止め（電流が大きい範囲を直線で延ばす）を入れ、ダイオードに直列抵抗を持たせると、3つとも通った。** SPICE はこれを反復ごとの電圧の制限でやる。
4. **費用。** 素子の水準は、5 µs（切り替え 4 回）の計算に、数千〜数十万ステップ。系統の水準は、同じ 5 µs を 100 ステップで通る。1周期あたりのステップ数で 2〜3 桁重い。
5. **自作の大きさと速さ。** 最小限の自作は約 140 行（素子の式を除く）で、rtol 1e-3 でも基準と 1.2% 以内。配列と数値だけで書いて Numba に載せると 43〜50 倍速くなり、同じ程度の精度の ngspice の 4〜13 倍の時間になった。ヤコビアンを差分（1反復に残差 11 回）で作り、誤差の見積もりが保守的（ngspice の 5〜11 倍のステップ数）なので、縮める余地はある（未測定）。
6. **決定性。** 3つとも、同じ入力・同じ実行ファイルで 2〜3 回が完全一致。ただし自作の Python 版と Numba 版は、ステップ数が 1 つ違った（76,907 と 76,908。指数や対数の関数の実装が違うため）。**実行の経路（Python か Numba か）を1つに決めないと、同じ結果にならない。**

| 観点 | 評価 |
|---|---|
| 精度 | 素子の式の範囲で、許容誤差に応じて合う。式そのものの限界は残る（メーカーの SPICE モデルでも、抵抗負荷のターンオンの損失を約 19% 低く見積もった例がある [R2]） |
| 速度 | 1周期あたりで系統の水準の 2〜3 桁上。短い窓なら 1〜数秒（Numba） |
| 実装の大きさ | 大（解法の核、直流の動作点、収束の助け、素子の式、分かりやすいエラー）。E1a と E1c を合わせた程度と見る |
| 決まり1 | 守れる（反復の回数と順番を固定し、単一スレッドで、実行の経路を1つにする） |
| 決まり2 | 守れる。素子の種類ごとに、パラメータ・端子の番号・状態を配列で持ち、種類ごとの評価の関数を核に置く（辞書やオブジェクトを持ち込まない）。試しの Numba 版はこの書き方 |
| 決まり5 | 検証の型が要る（4.5） |
| 決まり7 | 自作なら依存は増えない |

### 4.4 案 (d) 2つの水準を持つ（勧め）

決まり6 の「モデルの種類（詳細度）」を延ばす。

| モデルの種類 | 回路 | 解法 | 使いどころ |
|---|---|---|---|
| 理想（予定） | トルク源と一次遅れ | — | 機構と組む |
| 状態平均化 | レグを従属電圧源に | いまのエンジン（刻みは粗い） | ゲイン最適化の評価 |
| スイッチング（**系統の水準**） | 理想スイッチ、区分線形の素子、損失の表、熱回路 | いまのエンジン（固定刻み、行列の使い回し） | 最終の確認、リプル、損失と温度 |
| **素子の水準**（新しい） | 寄生容量つきの MOSFET・IGBT、ゲートの駆動、配線のインダクタンス | 非線形の解法（4.2 の形） | スイッチングの過渡、サージ、dv/dt、E_on・E_off |

**2つの水準のつなぎ方。**

1. **素子の水準は、短い窓だけを計算する。** 最初はダブルパルス試験の回路（決まった形。テンプレートの1つ）。入力は、素子のパラメータ（データシートから）、直流電圧、電流、ゲート抵抗、配線のインダクタンス。出力は、波形と、E_on、E_off、立ち上がりと立ち下がりの時間、電圧と電流の最大。
2. **系統の水準へは、損失の表として渡す。** 素子の水準を、電圧・電流の組で掃引して E(v, i) の表を作る。系統の水準は、切り替えのたびに表を引く（#37）。データシートに損失の曲線がある素子は、それを使い、素子の水準の結果と並べて見せる（食い違いは、モデルの限界として読める）。
3. **系統の水準からは、動作点を渡す。** 系統の水準の結果から、切り替えの直前の電圧と直後の電流を取り出し、その条件で素子の水準を走らせる（「この切り替えを拡大して見る」）。

**なぜ1つの SPICE 型のエンジンにまとめないか。**

- ゲイン最適化（E2）は、評価を何百回も回す。素子の水準は1周期あたり 2〜3 桁重い（4.2）。
- 系統の水準の作り（制御周期ごとの同期、量子化、デューティ比の扱い、注意の文）は検証が済んでいる。非線形の解法は、設定と素子の式で止まることがある（4.2）。止まらない経路を、最適化の土台に残す。
- 速さは同程度で、置き換える理由が無い（2.4）。

**限界（正直に）。**

- 寄生容量と制御の相互作用を、長い時間で1つの計算として見ることはできない（たとえば、スイッチングの過渡が電流の検出に乗る様子）。素子の水準で数周期を計算することはできるが、秒の桁は現実的でない。
- 素子の水準の精度は、素子の式とパラメータで決まる。データシートの値からの同定には幅がある。

| 観点 | 評価 |
|---|---|
| 精度 | 系統の水準はいまと同じ。素子の水準は 4.2 |
| 速度 | 系統の水準はいまのまま（E2 の前提を保つ）。素子の水準は、1つの動作点で 1〜数秒（Numba。4.2） |
| 実装の大きさ | (a) の追加（中）＋ (b) の核（大）。ただし (b) を「決まった形の回路」から始められるので、最初の一歩は中 |
| 決まり1・2・5・7 | 4.1 と 4.2 のとおり |
| 検証 | 4.5 |

### 4.5 検証の方法（決まり5、`model-validation`）

| 型 | 系統の水準に足す素子 | 素子の水準 |
|---|---|---|
| 解析解 | 順電圧つきの半波整流の平均、変圧比と励磁電流、結合インダクタの等価の漏れ、位相制御整流の平均電圧 (V_m/π)·(1 + cos α)、フォスター形のステップ応答、従属電源の利得 | RC のゲートの充電（しきい値までの時間。4.2 で +0.9%）、LC のリンギングの周波数と減衰、ダイオードの直流特性、容量の式の積分（電荷）の閉じた形、ターンオフの電圧の上限 |
| 保存則 | 損失の収支（入力 − 出力 − 蓄えの増分 = 損失の表の合計） | 1回の切り替えのエネルギーの収支（∫v·i dt と、容量とインダクタの蓄えの変化） |

| モデル間の一致 | 素子を線形にした回路で、いまのエンジンと一致 | 独立に書いた2つの解法の一致（4.2）。線形の回路では、系統の水準のエンジンと一致。ngspice の参照の波形（PO が認めた場合） |

| 再現性 | 2回実行して完全一致 | 同じ（実行の経路を1つに固定する。4.2 の 6） |
| 速度 | `benchmarks/` に記録 | 同じ |

## 5. 自由な回路の記述と、エンジンの口

層B（`Netlist`）は、いまも一般のネットリストで、エンジンは層A を知らない。利用者が自由に回路を書くと、テンプレートが保証していたこと（解ける、刻みが合う、名前がそろう）を、エンジンが受け持つことになる。回路図エディタと層A の扱い（決まり3 の改訂）は、別の担当の検討に従う。

### 5.1 解けない回路の検出と案内

| 状況 | いま | 足すこと |
|---|---|---|
| 基準節点から浮いた部分、電圧源だけのループ、電圧源とコンデンサの直結、電流源とインダクタの直列、インダクタだけの切断集合 | 計算の前に検出し、決まらない変数と手がかりを文に添える（F-6）。インダクタだけの切断集合を解くのは E1d | グラフだけで分かるもの（浮いた部分、電圧源のループ）を、行列を組む前に、素子の名前つきで出す。スイッチング状態ごとの検出は、いまは状態に出会ったときなので、**計算の前に、起こりうる状態で確かめる**口を足す（状態の数が多いときは、ゲート信号の組み合わせで絞る） |
| 還流経路の無いインダクタ | 計算の後の注意（インダクタ電流の遮断） | 自由な回路では頻出する。計算の前に、「この状態で、このインダクタの電流の経路がオフの素子だけになる」と警告する |
| 素子の水準で、直流の動作点が決まらない、反復が収束しない | — | どの節点、どの素子で止まったかと、直し方（浮いた節点に高い抵抗、初期値の指定、素子の直列抵抗）を添える。ngspice の「Timestep too small … trouble with node」の水準では足りない |
| 数値の範囲 | 素子ごとの検査（正の有限値、r_on < r_off） | 素子の水準では、D-062 に沿って範囲を宣言する |

### 5.2 初期値

- いま: L と C の `ic`。矛盾は注意に出る。
- 足すこと: (1) **直流の動作点から始める**（スイッチング状態を1つ決め、コンデンサを開放、インダクタを短絡として解く。系統の水準では線形の連立方程式1回）。(2) 素子の内部状態の初期値を渡す口（電動機の R-10、熱回路の温度）。(3) 周期定常状態から始める方法（1周期の写像の不動点）は、あると便利だが後。

### 5.3 節点と素子の名前

- いまの決まり（`v(節点)`、`i(素子ID)`、`gate()`、`cmd()`、`on()`）を保つ。
- 足すこと: サブ回路の中の名前は「インスタンス名.内部名」（例 `v(X1.sw)`）。区切りの文字と、使えない文字を決める。全部の素子で `i()` を返す（F-9）。電力 `p(素子ID)`、素子の内部の量（`tj(Q1)`、損失の集計、電動機の R-9）を、同じ決まりで足す。派生する信号の仕組みは、D-049 が E3 で決めるとしたものと1つにする。

### 5.4 素子の定義の足し方

いまの `Component` は、1つのクラスに `type` の固定の文字と、素子ごとの任意の欄（`r_on`、`gate`、`waveform`）が同居している。約40種には延ばせない。

- **素子の種類ごとの定義**（pydantic の判別つきの合併型）にする。種類ごとに、端子の名前と数（2端子に限らない）、パラメータと範囲、どの水準を持つかを宣言する。
- **登録簿**を持つ。種類ごとに、(i) 系統の水準への展開（基本の素子の組に展開するか、スタンプと状態の判定を持つか）、(ii) 素子の水準の式（配列で評価する関数）を登録する。核は、種類ごとの配列（パラメータ、端子の番号、状態）だけを受け取る（決まり2）。
- **水準の対応**を素子が持つ。たとえば MOSFET は、系統の水準では「S ＋ 逆並列の D（＋損失の表）」に、素子の水準では #22・#23 に展開する。同じネットリストを、2つの水準で計算できる。
- 層B の版を上げる（層A と同じ互換の作り。`basic-design.md` 12.4）。

### 5.5 サブ回路

- 定義（端子、中の素子、引数）とインスタンスを層B に持ち、エンジンの入口で平らに展開する（核の外）。名前は 5.3。
- レグ部品（`HalfBridgeLeg`）は、いまはテンプレートの側の Python の部品。サブ回路と登録簿ができたら、「モデルの種類で展開が変わるサブ回路」として層B に移せる。

### 5.6 大きさと刻みの限界（自由な回路で表に出るもの）

- 行列は密で、1ステップは未知数の2乗に比例する。未知数 14〜38 で `prepare` が 0.87〜2.4 ms、1ステップが 2.2〜2.8 µs（電動機の検討 3.2 の実測）。未知数が数百になる回路は、疎行列の形が要る（未測定）。
- スイッチとダイオードは 62 個まで（F-7）。
- 周波数の違う非同期のキャリアは、1つの固定の格子に載らない（F-8）。E1f（刻みの途中の切り替え）の後でも、制御周期の区切りは格子に要る。系統の水準を事象で進める可変刻みにする案は、行列の使い回しと E2 の前提を変えるので、いまは勧めない。要求仕様 X-9 は、「系統の水準は固定刻み。素子の水準だけ可変刻み」と改める形を提案する。

## 6. 電動機の検討からの要求への答え

電動機の検討 4章の R-1〜R-11 に答える。結論: **電動機は系統の水準に置き、端子を一定の RL ＋電圧源にする形（その検討の (a2)）で進められる。行列の使い回しを保てる。** 素子の水準の解法ができれば、角度で変わるインダクタンスと飽和を式のまま解く道も開くが、電動機のために急ぐ理由は無い。

| # | 要求 | 答え |
|---|---|---|
| R-1 | 端子のインダクタンスが角度で変わる素子（突極機） | (i) 一定のインダクタンス＋変わる分を電源で模擬、を系統の水準の標準にする（R-2 の口で実現）。(iii) 毎ステップの組み立て直しは、**素子の水準の核がそのまま持つ**（ニュートン法は毎反復、行列を組んで解く）。未知数 20〜40 の密行列なら1反復は数十 µs の見込み（未測定）で、abc の L(θ) のモデル（その検討の (b)）を研究用に走らせる経路になる。(ii) 低ランクの更新は、検証の手間に見合わないので採らない |
| R-2 | 素子の内部状態を時間刻みごとに進める口 | 核に「素子の種類ごとの更新」を足す。種類ごとに、パラメータ・状態・端子の未知数の番号を配列で持ち、1ステップの中で (1) 状態から電源の値を作る、(2) 回路を1ステップ進める、(3) 端子の値で状態を進める、を配列の演算で行う（決まり2 を守る。Python の関数を呼び戻さない）。速度に比例する項の扱い（分割法か、外挿か、制御周期ごとの行列の作り直しか）は、2次精度とエネルギーの収支を数値で確かめて決める（未測定）。熱回路（#38）と損失の集計（#37）も、同じ口に載る |
| R-3 | 磁気飽和 | 系統の水準: 素子の中で数変数のニュートン法（配列と数値だけなので核に置ける）か、折れ線の磁化曲線を状態の表で扱う（#7。F-3 の一般化）。端子のインダクタンスを一定に保つ前者を勧める。素子の水準: 式のまま |
| R-4 | 機械系との連成 | 内部の機械系は R-2 の口の状態として、電気と同じ刻みで進める。外部の物理エンジンとの交換は、制御周期の整数倍で、核から戻る区切りに合わせる（いまの制御器と同じ作り）。エネルギーの食い違いは R-11 の量から出す。解法の変更は要らない |
| R-5 | 長い計算 | 記録の間引き（信号を選ぶ、k ステップごと、または区間ごとの最小・最大・平均）を核の記録に足す。上限（2,000 万ステップ、2 GiB）は記録の量で決まっているので、間引けば計算そのものは延ばせる。速さは Numba で 0.5 µs/ステップ（1 秒 = 2,000 万ステップで約 10 秒の見込み。未測定） |
| R-6 | E1d（インダクタだけの切断集合） | 前提として残る。この検討で変わらない |
| R-7 | 線形の従属電源とジャイレータ | #11。系統の水準に足す（7章 E4c） |
| R-8 | 一定の結合インダクタ（3×3 まで） | #4。E の非対角で、行列の使い回しは崩れない（7章 E4c） |
| R-9 | 素子の内部の量を信号として出す | 5.3 の名前の決まりで、結果と制御器の検出の両方に出す |
| R-10 | 定常から始める初期値 | 5.2 の (2) |
| R-11 | エネルギーの収支を確かめる量 | `p()` と損失の集計（5.3、#37）を、検証の段2（保存則）に使う。4.1 の実測のとおり、素子ごとの i²·r の積分は切り替えの損失を取りこぼすので、**収支は入力・出力・蓄えの差で取る** |

仮想インピーダンスなど制御で作る素子（その検討 6章）は、制御ブロックの側の話で、解法への新しい要求は無いと読んだ。

| ○ だけ | 成り立たない | NumPy と SciPy が △ / × |
| △ まで（上の表） | 2〜3 割 | 勧める案 |
| △ まで＋ SpiceSharp が E4s を通る | 3〜4 割 | 素子の水準の核が既存になる。素子の式（C#）と、つなぎは自作 |
| ngspice を使えるとした場合（D-069 では不可） | 5〜6 割 | 素子の水準の核と素子の式の多くが既存になる。IGBT、系統の水準、自由な回路の口は自作のまま |

**結論: この領域は、大半が既存のものの組み合わせでは済まない。** 成熟した SPICE のエンジンはライセンスで使えず、緩いライセンスの区分線形のエンジンは無い。道具の比較 10.1 の「回路の計算エンジンは既存で 10〜15%」と同じ向きで、こちらは移植できる式と数値の土台を多めに数えた分だけ高い。

差別化との関係。エンジンそのものは差別化にならない（LTspice、PLECS が強い所）。それでも作るのは、差別化の部分（設計目標 → ゲイン → 検証、データシートからの設定）が、決定的で、止まらず、ライセンスを自分で決められるエンジンを要るため。その意味で、**エンジンの範囲は広げすぎないほうがよい**: 系統の水準は区分線形のまま素子を足し、素子の水準は短い窓（ダブルパルス試験）から始める。任意の回路を SPICE の水準で長く計算することは、目指さない。
