## 1. 誰の、どんな用事か

**利用者**: パワーエレクトロニクスやモーター制御の設計者。設計書（仕様と回路定数）は手元にあるが、シミュレーションモデルを組み、ゲインを調整し、結果を資料にまとめる作業に時間を取られている。回路シミュレータとオシロスコープに慣れていて、数値の正しさと出典に厳しい。

**済ませたい用事**:

1. 設計書の内容で回路がどう動くか、すぐ見たい。
2. 設計目標（オーバーシュート、整定時間、安定余裕）を満たすゲインが欲しい。満たせないなら、何がどれだけ足りないか知りたい。
3. 結果を、根拠つきで人に渡せる形で残したい。

## 2. 中心になる流れ

```
① 取り込む ─► ② 確かめる ─► ③ 動かす ─► ④ 決める ─► ⑤ 残す
 設計書を     値・出典・       計算して     設計目標から  レポートと
 開く         不足を確認       波形を見る   ゲインを出す  仕様の保存
```

- どの段階からでも始められる。v0.1 は、範囲を降圧コンバータ1つに絞って（D-071）、②、③ と、④ のうち「設計目標を入れ、ゲインを入れ（手で、または解析式の初期ゲイン）、スイッチングモデルで確かめて、設計目標ごとの達成・未達を読む」まで。① と、④ のゲインの最適化、⑤ は凍結（v0.1 の反応を見て決める）。
- 前の段階に戻って値を直すと、後ろの結果は「古い」と表示され、再計算を促す。古い結果は、どの値で計算したものかと、いまの値との違いを添えて見せる。

## 3. 画面の構成

1つの作業画面で完結させる。段階ごとにページを切り替えない。

```
┌──────────────────────────────────────────────────────────────────────────────────────┐
│ アプリ名  開いている仕様  開く・保存   実行と状態、判定の札   密度 言語 テーマ          │
├──────────────────┬──────────────────────────────────┬────────────────────────────────┤
│ 仕様             │ 回路図（テンプレートの固定図）    │ 評価                           │
│  値  単位  出典  │                                  │  設計目標ごとの 目標 / 実測     │
│  設計目標        ├──────────────────────────────────┤  達成 / 未達 / 判定できない     │
│  不足の表示      │ スコープ（波形）                  ├────────────────────────────────┤
│                  │                                  │ 信号と読み取り（カーソルの値）  │
├──────────────────┴──────────────────────────────────┴────────────────────────────────┤
│ お知らせ（不足、注意、エラーと直し方）                                                │
└──────────────────────────────────────────────────────────────────────────────────────┘
```

幅 1600px 以上で3列。それより狭いときは2列にし、右の列の中身を波形の下に移す（`screens-v0.1.md` 1.2）。

| 領域 | 役割 | 入るリリース |
|---|---|---|
| ヘッダー | 開いている仕様、開く・保存、実行と進み具合、総合の判定の札、密度・言語・テーマ。段階の表示（①〜⑤の現在地）は、使える段階が増えてから | v0.1 |
| 仕様パネル | 値、単位、出典、設計目標を一覧し、その場で直す | v0.1（値・単位・出典・設計目標の表示と編集）、凍結（出典を設計書の位置につなぐ、確認済みの印） |
| 回路図 | テンプレートごとの固定図に値を重ねて表示。素子を選ぶと仕様パネルの行が強調される。測定点から波形の表示を切り替える | v0.1 |
| スコープ | 波形の表示、拡大縮小、カーソル、重ね書き、前回との比較、CSV書き出し | v0.1 |
| 評価 | 設計目標ごとの目標と実測、達成・未達・判定できない、未達の量、安定余裕 | v0.1（スイッチングモデルの結果の評価）。ゲインの最適化は凍結 |
| 信号と読み取り | 信号の表示と段、カーソルの値と差 | v0.1 |
| お知らせ | 不足、注意、エラー。必ず「どう直すか」を添える | v0.1 |
| 取り込み | 設計書を開き、読み取り結果と読めなかった箇所を見る | 凍結 |
| レポート | 仕様、波形、ゲイン、達成状況、根拠を1つにまとめて書き出す | 凍結 |

**まだ使えないものを先に置かない。** そのリリースで使えない領域や段階は、薄く表示したり「準備中」と書いたりせず、画面に出さない。どこに入るかの見通しは `screens-v0.1.md` 13章。段階の表示は、使える段階が2つ以上になってから出す。

## 4. 設計の原則

洗練の基準。画面仕様とレビューはこれに照らす。迷ったら「間違いに気づける ＞ 速く用事が済む ＞ 見た目の整い」の順で決める。

1. **数値には必ず単位。** 工学表記（47 µH、100 kHz）で読めて、同じ表記で入力できる。入力をどう読んだかを、その場で見せる（m と M の取り違えに、打った瞬間に気づける）。ファイルに書かれた単位は必ず読み、換算したらそう知らせる。丸めて表示するときは、丸めたと分かるようにする。
2. **すべての値に出典。** 設計書の位置、手入力、解析式、既定値、自動のどれかを必ず示す。書かれていないなら「記載なし」と示す。
3. **推測で埋めない。** 足りない値は足りないと見せ、次に何をすればよいかを示す。
4. **達成と未達を隠さない。** 色だけに頼らず、言葉と数値で示す。未達は「どの設計目標が、どれだけ」まで書く。判定できない（測った値と設計目標の差が、判定の幅より小さい）を、達成に寄せて見せない。
5. **待たせない。** 操作への反応は0.1秒以内。計算は進み具合を見せ、いつでも止められる。計算中も画面は使える。始められない計算（値の不足、大きすぎる計算）は、実行する前に、理由と直す場所を示す。
6. **戻せる、比べられる。** 値を変える前の結果を残し、波形を重ねて比べられる。いま見ている結果が、どの値で計算したものかを常に示す。
7. **波形が主役。** スコープは最も広い場所を取り、拡大縮小とカーソルが滑らかに動く。読み取る数値は、画面用に間引いた点ではなく、計算結果の値そのもの。波形をそのまま信じてよいかに関わること（古い結果、計算からの注意）は、波形のすぐそばに出す。
8. **設計者の言葉を使う。** オーバーシュート、整定時間、位相余裕。ソフトウェア都合の言葉を出さない。
9. **エラーは原因と直し方を対で。** 「回路が解けません」で終わらせない。プログラムの内部の文は主文に出さない。
10. **慣習に従う。** 既存の回路シミュレータとオシロスコープの操作に合わせ、独自の操作を発明しない。主要な操作はキーボードでもできる。
11. **色に意味を持たせるのは波形と状態だけ。** 枠や操作の部品は無彩色で作る。状態は記号と言葉を必ず添え、波形は名前と線の種類でも見分けられるようにする。
12. **読める大きさと、強弱。** 日本語を含む文字は 14px 以上。何が主で何が従かを、大きさ・太さ・面の色・線の強さで付ける。広い面を空のまま残さない（`design-system.md` 4.4、5.4）。

## 5. 品質の基準

| 項目 | 基準 |
|---|---|
| はじめての利用 | インストール後、同梱のサンプルで波形を見るまで3分以内。説明を読まずにたどり着ける |
| スコープの反応 | 2000万点の信号を2本表示した状態で、拡大・縮小・移動の操作から、間引き直した波形に置き換わるまで0.1秒以内（同じ操作を30回以上くり返した95パーセンタイル） |
| 計算中 | 進み具合が見え、中断できる。中断しても画面が固まらない。中断から1秒以内に操作できる状態に戻る |
| 状態の網羅 | どの画面にも、読み込み中・空・正常・エラーの見え方がある。空の状態は、骨格と、次にすることを1つ見せる |
| 文字の大きさ | 基準の大きさ（1920×1080、表示倍率 100%）で、日本語を含む文字は 14px 以上、ほかは 12px 以上。大きさは5つだけ |
| 強弱と空き | 領域の見出しと境が、文字を読まなくても分かる。同じ色だけの最大の矩形が、実行した後で 10% 以下、開いた直後で 15% 以下、起動直後で 20% 以下（`design-system.md` 11.3） |
| 実物での確認 | UX の確認は、Windows の実機で撮った 1920×1080 の画像で行い、今の水準の製品と比べる（`design-system.md` 11章。D-055） |
| 密度、言語、テーマ | 標準と詰める、日本語と英語、明るいテーマと暗いテーマで崩れない。切り替えても作業の状態が変わらない |
| キーボード | 開く、値を直す、実行、カーソルで読む、比較、書き出し、保存までを、キーボードだけでできる |
| 見分けやすさ | 文字のコントラストは 4.5:1 以上、部品の輪郭と波形の線は 3:1 以上。波形の色は、色覚の型によらず全部の組が見分けられる（根拠は `design-system.md` 3章） |
| 作業を失わない | アプリ本体が動いている間は、ブラウザを再読み込みしても、仕様・編集内容・結果が元に戻る |
| オフライン | ネットワークが無くても、AI連携以外はすべて動く |
| データの扱い | 利用者のデータを外に送らない。AIに送る内容は送る前に画面で示す |

## 6. 技術

- 利用者のPCでローカルサーバー（FastAPI）を起動し、ブラウザで操作する。`circuit-sim` コマンドで起動し、ブラウザが開く。
- 画面は React + TypeScript（Vite）。ビルド結果をPythonパッケージに同梱する。
- 波形は uPlot を自前の Scope 部品で包む。間引きはサーバー側で行う。
- アイコンとスクリプトはすべて同梱し、外部から読み込まない。字体は、端末に入っている字体だけを使い、同梱しない（A0r で決めた。日本語の字体を名前で指定する。`design-system.md` 4.1）。
- プロジェクト（仕様、結果、設定）は利用者が選んだフォルダにファイルで保存する。独自の隠し場所に溜めない。v0.1 は、仕様JSONとCSVをブラウザのダウンロードとして保存する（フォルダへの保存は、プロジェクトの保存で設計する。凍結）。密度・言語・テーマ・仕切りの位置のような画面の好みは、画面の好みとして覚える（ブラウザと、端末の中の設定ファイル。D-050）。

## 7. v0.1 の範囲

D-071 で絞った。降圧コンバータ（同期整流、電圧モードの PID 制御）1つで、設計目標を入れる → ゲインを入れる → スイッチングモデルで計算する → 評価（達成 / 未達 / 判定できない、未達の量）まで。

- A0: 骨組み（サーバー、画面の枠、デザインの基準、日英の切り替え、起動コマンド）
- A0d: 新しい見た目（B 案。D-072）の実装
- A1: 仕様JSONを開く → 値を確かめる → 実行 → スコープで波形を見る
- A2 の一部: 設計目標の入力と、評価の表示
- 同梱サンプルは降圧コンバータ1つ（設計目標つき）

設計書の取り込み、AI、回路図エディタ、ゲインの最適化、ほかのテンプレートは凍結（`screens-v0.1.md` 0.1、13章）。
画面ごとの詳細は `screens-v0.1.md`、見た目の基準は `design-system.md`。
