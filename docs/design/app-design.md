# アプリ設計（v0）

最終更新: 2026-11-14 ／ 責任者: ux-designer（画面ごとの詳細は `screens-*.md`）

## 1. 誰の、どんな用事か

**利用者**: パワーエレクトロニクスやモーター制御の設計者。設計書（仕様と回路定数）は手元にあるが、シミュレーションモデルを組み、ゲインを調整し、結果を資料にまとめる作業に時間を取られている。回路シミュレータとオシロスコープに慣れていて、数値の正しさと出どころに厳しい。

**済ませたい用事**:

1. 設計書の内容で回路がどう動くか、すぐ見たい。
2. 目標（オーバーシュート、整定時間、安定余裕）を満たすゲインが欲しい。満たせないなら、何がどれだけ足りないか知りたい。
3. 結果を、根拠つきで人に渡せる形で残したい。

## 2. 中心になる流れ

```
① 取り込む ─► ② 確かめる ─► ③ 動かす ─► ④ 決める ─► ⑤ 残す
 設計書を     値・出どころ・   計算して     目標値から    レポートと
 開く         不足を確認       波形を見る   ゲインを出す  仕様の保存
```

- どの段階からでも始められる。v0.1 は ③ だけ（仕様JSONを開いて動かす）。
- 前の段階に戻って値を直すと、後ろの結果は「古い」と表示され、再計算を促す。

## 3. 画面の構成

1つの作業画面で完結させる。段階ごとにページを切り替えない。

```
┌──────────────────────────────────────────────────────────────┐
│ プロジェクト名   ①─②─③─④─⑤（現在地）        言語  テーマ │
├──────────────┬───────────────────────────────┬───────────────┤
│ 仕様         │ 回路図（テンプレートの固定図）│ 目標値と結果  │
│  値  単位    │                               │  目標 / 実測  │
│  出どころ    ├───────────────────────────────┤  達成 / 未達  │
│  不足の表示  │ スコープ（波形）              │  ゲイン       │
│              │                               │  安定余裕     │
├──────────────┴───────────────────────────────┴───────────────┤
│ お知らせ（不足、注意、エラーと直し方）                       │
└──────────────────────────────────────────────────────────────┘
```

| 領域 | 役割 | 入るリリース |
|---|---|---|
| 仕様パネル | 値、単位、出どころを一覧し、その場で直す | v0.1（表示と編集）、v0.3（出どころ） |
| 回路図 | テンプレートごとの固定図に値を重ねて表示。値を選ぶと仕様パネルの行が光る | v0.1 |
| スコープ | 波形の表示、拡大縮小、カーソル、重ね書き、前回との比較 | v0.1 |
| 目標値と結果 | 目標の入力、実測値、達成状況、ゲイン、安定余裕 | v0.2 |
| お知らせ | 不足、注意、エラー。必ず「どう直すか」を添える | v0.1 |
| 取り込み | 設計書を開き、読み取り結果と読めなかった箇所を見る | v0.3 |
| レポート | 仕様、波形、ゲイン、達成状況、根拠を1つにまとめて書き出す | v0.2 |

## 4. 設計の原則

洗練の基準。画面仕様とレビューはこれに照らす。

1. **数値には必ず単位。** 工学表記（47 µH、100 kHz）で読めて、同じ表記で入力できる。
2. **すべての値に出どころ。** 設計書の位置、手入力、既定値のどれかを必ず示す。
3. **推測で埋めない。** 足りない値は足りないと見せ、次に何をすればよいかを示す。
4. **達成と未達を隠さない。** 色だけに頼らず、言葉と数値で示す。未達は「どの目標が、どれだけ」まで書く。
5. **待たせない。** 操作への反応は0.1秒以内。計算は進み具合を見せ、いつでも止められる。
6. **戻せる、比べられる。** 値を変える前の結果を残し、波形を重ねて比べられる。
7. **波形が主役。** スコープは最も広い場所を取り、拡大縮小とカーソルが滑らかに動く。
8. **設計者の言葉を使う。** オーバーシュート、整定時間、位相余裕。ソフトウェア都合の言葉を出さない。
9. **エラーは原因と直し方を対で。** 「回路が解けません」で終わらせない。
10. **慣習に従う。** 既存の回路シミュレータとオシロスコープの操作に合わせ、独自の操作を発明しない。主要な操作はキーボードでもできる。

## 5. 品質の基準

| 項目 | 基準 |
|---|---|
| はじめての利用 | インストール後、同梱のサンプルで波形を見るまで3分以内。説明を読まずにたどり着ける |
| スコープの反応 | 2000万点の信号で、拡大・縮小・移動の表示更新が0.1秒以内 |
| 計算中 | 進み具合が見え、中断できる。中断しても画面が固まらない |
| 状態の網羅 | どの画面にも、読み込み中・空・正常・エラーの見え方がある |
| 言語とテーマ | 日本語と英語、明るいテーマと暗いテーマで崩れない |
| オフライン | ネットワークが無くても、AI連携以外はすべて動く |
| データの扱い | 利用者のデータを外に送らない。AIに送る内容は送る前に画面で示す |

## 6. 技術

- 利用者のPCでローカルサーバー（FastAPI）を起動し、ブラウザで操作する。`circuit-sim` コマンドで起動し、ブラウザが開く。
- 画面は React + TypeScript（Vite）。ビルド結果をPythonパッケージに同梱する。
- 波形は uPlot を自前の Scope 部品で包む。間引きはサーバー側で行う。
- プロジェクト（仕様、結果、設定）は利用者が選んだフォルダにファイルで保存する。独自の隠し場所に溜めない。

## 7. v0.1 の範囲

- A0: 骨組み（サーバー、画面の枠、デザインの基準、日英の切り替え、起動コマンド）
- A1: 仕様JSONを開く → 値を確かめる → 実行 → スコープで波形を見る。同梱サンプル（RLC、降圧コンバータ）
