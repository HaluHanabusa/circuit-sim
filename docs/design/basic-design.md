### 1.3 ほかの文書との関係

文書の全体と、どれが何の正かは `README.md` にある。

- `requirements.md` が「何を作るか」（ユースケース UC-nn、機能要求 FR-nn、非機能要求 NFR-nn）を決め、この文書は「どう作るか」を書く。

### 2.2 プロセスと通信

| プロセス | 起動 | 寿命 | 状態 |
|---|---|---|---|
| 計算のコマンドライン | `python -m circuit_sim 仕様.json [--csv 出力.csv]` | 1回の計算で終わる | 実装済み |
| アプリ本体（ローカルサーバー） | `circuit-sim`（`python -m circuit_sim.app` も同じ） | Ctrl+C で止めるまで。作業の状態（開いている仕様）はメモリにだけ持つ | 統合前（A0） |
| ブラウザ | 起動コマンドが既定のブラウザを開く（`--no-browser` なら開かない） | 利用者が閉じるまで | 統合前（A0） |
| AI の CLI | アプリ本体がヘッドレスで呼ぶ（D-008） | 1回の依頼ごと | 予定（I2） |

- 通信はブラウザとアプリ本体の間の HTTP だけ。待ち受けは `127.0.0.1` に限る（`cli.py` の `HOST`）。ポートの既定は 28470。使われていれば 28471〜28479、どれも使えなければ OS が選ぶポート（D-050）。前回のポートを最初に試す（前回の起動の記録 `last-run.json`）。前回のプロセスがもう無いのに使用中なら、5 秒まで結び直してみる。止めるときは、接続を普通に閉じる（D-061）。
- 本文は JSON。認証はクッキー（11章）。TLS は使わない（PC の中だけの通信）。
- 画面は 2 秒ごとに `/api/health` を確かめ、応答を 2 秒待つ。5 秒以内に切断に気づく（画面仕様 12章 D8）。
- 計算をアプリ本体のどこで走らせるか（スレッド、別プロセス）は、A0 には無い。予定（A1）で決める。

## 4. モジュール構成と責務

### 4.1 モジュールごとの責務と、公開する関数と型

製品のコードは `circuit_sim/`（下の表。場所はこのパッケージからの相対）。ほかに、画面のソース `frontend/`（統合前（A0））、仕様 JSON の例 `examples/`、速度の計測 `benchmarks/`、開発の道具 `scripts/`、試験 `tests/`（`tests/acceptance/` は検証担当の受け入れ試験）、文書 `docs/` がある。`ingest/` と `ai/` は予定（I1、I2）で、まだ無い。

| モジュール | 責務 | 公開する主なもの | 状態 |
|---|---|---|---|
| `__init__.py`、`__main__.py` | 公開する名前をまとめる。計算のコマンドライン | `main` | 実装済み |
| `ir.py` | 層A と層B の形と、形だけで分かる検証（素子の値が正、節点の重複、基準節点） | `Spec`、`Quantity`、`SimulationSettings`、`Netlist`、`Component`、`DC`、`Step`、`Sine`、`SCHEMA_VERSION` | 実装済み。`Command`、`SUPPORTED_SCHEMA_VERSIONS` は統合前（E1b） |
| `units.py` | 単位の文字列を（次元、10 の指数）に分け、SI に換算する | `parse_unit`、`to_si`、`UnitError` | 実装済み |

### 4.2 依存の向き

```
app ──► templates（TEMPLATES）、ir（Spec）                          統合前（A0）
templates ──► units、ir。統合前（E1b）で simulate（Expanded.run()）と control（制御ブロック）が加わる
tuning（initial）──► numpy と scipy だけ（エンジンを呼ばない）        統合前（E1b）
simulate ──► kernel、mna、ir、control（Controller と Pwm の型）
kernel ──► mna（CircuitError だけ）
mna ──► ir
units、ir ──► ほかのモジュールに依存しない
```

守る決まり。

1. **エンジン（`simulate`、`kernel`、`mna`、`ir`）は上の層（`templates`、`tuning`、`app`）を知らない。** エンジンが `control` から使うのは、制御器の口と PWM の型だけ。
2. **核（`kernel.py`）の最内ループは配列と数値だけ**（決まり2）。回路の解釈、制御器の呼び出し、指令の考え方は核の外に置く。核が外に戻るのは、用意していないスイッチング状態に出会ったとき、ダイオードの導通が決まらないとき、制御器を呼ぶ区切り（と計算の終わり）だけ。
3. **単位は層A を読む側だけが扱う**（D-018）。エンジンは SI の値だけを受け取る。
4. **AI はエンジンを呼ばない。AI が出力するのは層A だけ**（決まり1、3）。予定（I2）。
5. **文言はエンジンに持たせない**（決まり8）。信号の説明や項目の名前は画面の辞書が持つ。いまの注意とエラーは日本語の文で、番号への置き換えは予定（E1g）。
6. **判定はエンジンが行い、画面とサーバーが同じ判定を別に持たない**（単位の換算、範囲、ステップ数の上限、刻みの粗さ。`screens-v0.1.md` 12章）。

## 5. データ設計

### 5.1 層A（`Spec`）

AI と人が書く層。テンプレート名、パラメータ、設計目標を持つ。知らない欄はエラーにする（`extra="forbid"`）。

| 欄 | 型 | 中身 | 版 0.1（実装済み） | 版 0.2（統合前（E1b）） |
|---|---|---|---|---|
| `schema_version` | 文字列 | 仕様の版 | `"0.1"` だけ | `"0.1"` と `"0.2"`。省くと中身から決める |
| `template` | 文字列 | テンプレート名 | `rc_lowpass`、`rlc_series` | 加えて `buck_voltage_mode` |
| `plant` | 名前 → `Quantity` | 回路の値 | 同じ | 同じ |
| `control` | 名前 → 値 | 制御の値 | 型を決めていない（任意の値） | 名前 → `Quantity` |
| `targets` | 名前 → 数値 | 設計目標 | 欄だけある。読むコードは無い。扱いは E1g で決める（範囲12）。使うのは予定（E2） | 同じ |
| `simulation.t_end`、`simulation.h` | 正の数値、または省略 | 終了時刻と時間刻み。省くとテンプレートが決める | 同じ | 同じ |
| `simulation.fidelity` | `"switching"`、`"average"`、または省略 | モデル。省くとテンプレートの既定 | 欄が無い | あり |
| `missing` | 文字列の並び | 足りない値の名前 | 欄だけある。読むコードは無い。扱いは E1g で決める（範囲12） | 同じ |

`Quantity` は1つの値。

| 欄 | 型 | 決まり |
|---|---|---|
| `value` | 数値または `null` | `null` は「設計書に無かった」。推測で埋めない（決まり4）。無限大と NaN は受け付けない |
| `unit` | 文字列（必須） | 5.6。値が `null` でも要る |
| `source` | 文字列または `null` | 出典（いまの画面とコードの表記: 出どころ）。設計書の位置（`p.3 表2`）、`手入力` など。いまのコードは中身を解釈しない。`手入力` と `manual` を同じに扱う処理は予定（E1g。D-040） |

**不足の扱い。** 足りない値は、テンプレートが実際の値から判断する。必須の項目が無い、または `null` なら、足りない名前をまとめて `MissingValueError` にする。`missing` の欄には頼らない（画面も実際の値から判断する。`screens-v0.1.md` 4.2）。

**版の互換（D-039、D-046）。統合前（E1b）。**

- 読める版は `SUPPORTED_SCHEMA_VERSIONS`（`("0.1", "0.2")`）。新しく書く版は `SCHEMA_VERSION`（`"0.2"`）。サーバーは、版の一覧を呼ぶたびに読む（A0 は、この名前が無ければ `SCHEMA_VERSION` だけを読める版とする）。
- 版 0.1 の `control` の数値は、単位 `""`、出典 `記載なし` の `Quantity` にして読む。値は項目の SI 単位（接頭語なし。V、Hz、無次元）とみなし、注意を出す。
- `schema_version` を省いたファイルは、`control` に数値や `null` があれば 0.1、無ければ 0.2 と決める（`Spec.version_inferred` が真になる）。
- 読めない版は、サーバーが N-OPEN-VERSION で断る（統合前（A0））。

### 5.2 層B（`Netlist`）

エンジンが読む層。層A からコードが展開する。SI の値だけを持つ。欄は、基準節点の名前 `ground`（既定 `"0"`）と、素子の並び `components`（1つ以上）。

`Component` は2端子素子。`nodes` は（n+、n−）で、電流の正の向きは素子の中を n+ から n− へ（SPICE と同じ）。

| `type` | 素子 | 値 | 備考 |
|---|---|---|---|
| `R`、`L`、`C` | 抵抗、インダクタ、コンデンサ | `value`（正の有限値） | `L` と `C` は初期値 `ic`（L は電流、C は n+ 側を正とした電圧） |
| `V`、`I` | 電圧源、電流源 | `waveform` | 下の波形 |
| `S` | 制御スイッチ（理想スイッチ） | `r_on`（既定 1 mΩ）、`r_off`（既定 1 MΩ）、`gate` | `gate` はゲート信号の名前。信号そのものは計算の入口に渡す |
| `D` | ダイオード（順方向電圧 0） | `r_on`、`r_off`（既定は同じ） | アノードが n+ |

| 波形 `kind` | 値 | 状態 |
|---|---|---|
| `dc` | 一定値 | 実装済み |
| `step` | `t_step` で `initial` から `final` へ。時刻は時間刻みの格子に丸める | 実装済み |
| `sine` | `offset + amplitude·sin(2π·frequency·t + phase)` | 実装済み |
| `command` | 従属電圧源（指令で値が決まる電源）。値 = `gain` × 指令（`lower`〜`upper` で止める）。制御周期の先頭で変わり、次まで一定 | 統合前（E1b） |

形の検証（`ir.py`）: 素子 ID の重複、両端が同じ節点、基準節点につながる素子が無い、素子が1つしかつながらない節点、`r_on ≥ r_off`、ゲートの無いスイッチ。回路として解けるかどうかは、計算の前に 6.2 の整合の計算で確かめる。スイッチとダイオードは合わせて 62 個まで（`mna.MAX_DEVICES`）。

### 5.3 展開の結果（`Expanded`）

テンプレートが返す、計算に渡すものの組。

| 欄 | 中身 | 状態 |
|---|---|---|
| `netlist`、`t_end`、`h`、`probes`、`notes` | 層B、終了時刻、時間刻み、要約と CSV に出す信号の名前、展開で出た注意（単位の換算、既定の刻みの調整、省いた項目の扱いなど） | 実装済み |
| `gates`、`controllers`、`fidelity`、`run()` | 計算に渡す PWM と制御器、使ったモデル。`run()` はそれらを `simulate()` に渡して計算する | 統合前（E1b） |
| `signals` | 表示する信号の情報（`SignalInfo`: 名前、単位、既定で表示するか、種類、節点・素子・正の向き） | 統合前（E1b）。全部の回路に広げるのは予定（E1g） |

### 5.4 結果（`Result`）

| 欄 | 中身 |
|---|---|
| `t` | 時刻（ステップ数 + 1 点。等間隔） |
| `x`、`unknowns` | 回路の変数の波形と名前。節点電圧と、電圧源・インダクタの枝電流 |
| `signals` | 区間ごとの信号。スイッチを含む計算で入る |
| `notes` | 計算からの注意（日本語の文の並び） |
| `stats` | 統計。`states`（用意したスイッチング状態の数）、`state_changes`（不連続点として扱ったステップ）、`retries`（捨てた試行）、`rescues_at_start`（D-035）。統合前（E1b）で `command_changes` が加わる |
| `netlist`、`h`、`devices`、`sample_state` | 計算した層B、時間刻み、スイッチとダイオードの ID、各時刻のスイッチング状態 |

**信号の名前の決まり。** `Result["名前"]` で配列を取り出す。

| 名前 | 中身 | 値の時刻 |
|---|---|---|
| `v(節点)` | 節点電圧（基準節点に対して） | その時刻の値 |
| `i(素子ID)` | 電圧源とインダクタの枝電流（n+ から n− が正）。抵抗、スイッチ、ダイオードの電流は `Result.i(素子ID)` で計算して返す | その時刻の値 |
| `gate(名前)` | ゲート信号（1 = オン） | その時刻から次の時刻までの区間の値 |
| `cmd(名前)` | 制御器の指令（操作量） | 同上 |
| `on(素子ID)` | スイッチ、ダイオードの導通（1 = オン） | 同上 |

**記録の決まり（D-019）。** スイッチやダイオードが切り替わる格子点には、切り替わる前の値を記録する。電源がステップする格子点には、変わった後の値を記録する。区間の信号の最後の点は、最後の区間の値を繰り返す。指令で値が決まる電源の変わり目を「直前の値」にそろえるのは予定（E1g。D-048）。

**表示する信号と内部の信号。** 結果の名前には、画面に出さない内部の信号（`on(S1)`、状態平均化モデルの `v(sw_avg)` など）が混ざる。全部の名前を「表示する」と「内部」に漏れなく分けて返すのは予定（E1g。`screens-v0.1.md` 14章の未決17）。

### 5.6 単位の扱い（D-018、D-037）

- 層A の単位は必ず読む。読める形は「SI 接頭語 + 単位記号」。大文字と小文字を区別する（`m` はミリ、`M` はメガ）。
- 接頭語: `f p n u m k M G`。マイクロは `u`、`µ`（U+00B5）、`μ`（U+03BC）の3通り。
- 単位記号: `V`、`A`、`ohm` / `Ohm` / `Ω`、`H`、`F`、`Hz`、`s`、`W`。
- 接頭語を付けない単位（統合前（E1b））: `1/V`（比例ゲイン）、`1/(V·s)`（積分ゲイン）、`s/V`（微分ゲイン）、`1`（無次元）、`%`（無次元の 1/100）。空の文字列は読まない（書き忘れと区別できない）。
- 次元が項目と違う単位、読めない単位は `UnitError`。`"SI"` のような照合できない文字列も受け付けない。
- 互換文字（`㎌`、`㏀`、全角の `ｍＨ`）は読まずにエラーにする。正規化するかは、設計書の取り込み（I1）で改めて決める（D-037）。
- 換算したときは、何を何に換算したかを注意に出す（例: `L: 47 uH を 4.7e-05 H に換算した`）。
- 負の指数の換算は割り算で行う（10 の負のべきは2進数で正確に表せないため）。

## 6. 処理方式

### 6.1 計算の流れ

```
仕様 JSON
  │ ① 読み込みと形の検証              ir.Spec（pydantic）           形の誤り → ValidationError
  ▼
層A（Spec）
  │ ② テンプレートの展開              templates.expand(spec)
  │    値の不足の確かめ                                              → MissingValueError
  │    単位の読み取りと換算            units.to_si                   → UnitError
  │    範囲の確かめ、既定の t_end と h                               → ValueError
  ▼
Expanded（層B Netlist、t_end、h、ゲート信号、制御器、注意）
  │ ③ 計算の入口                      simulate(...) / Expanded.run()
  │    ステップ数と記憶量の上限                                      → StepLimitError
  │    回路方程式の組み立て            mna.build_system
  │    行列の用意、解けない回路の検出  kernel.prepare                → CircuitError
  │    整合の取れた初期値
  │ ④ 時間ステップ                    kernel.run / kernel.run_switched
  │    制御周期ごとに核から戻り、制御器を呼ぶ
  │ ⑤ 注意の判定（刻みの粗さ、電流の遮断など）
  ▼
Result（時刻、信号、注意、統計）──► 要約の表示、CSV、（予定）画面のスコープ
```

計算の経路に AI は入らない。乱数も使わない。同じ入力からは同じ結果になる（決まり1）。

### 6.2 数値計算の方式

**方程式。** 修正節点解析（D-007）で、回路を `E x' + G x = B u` の形にする。`x` は節点電圧（基準節点を除く）と、電圧源・インダクタの枝電流。`u` は電源の値。抵抗は `G` に、コンデンサは `E` に、インダクタは枝の式 `v+ − v− − L·di/dt = 0` として入る。スイッチとダイオードは、オンとオフで値が変わる抵抗（`r_on` / `r_off`）として扱う区分線形モデルで、`G` には含めず、スイッチング状態ごとに足す（`state_conductance`）。

**積分。** 固定の時間刻み `h` の台形則。

```
(E/h + G/2)·x[k+1] = (E/h − G/2)·x[k] + B·(u[k] + u[k+1])/2      →  x[k+1] = P·x[k] + Q·ū[k]
```

`P` と `Q` は、スイッチング状態ごとに一度だけ LU 分解で作る（密行列）。1ステップは行列とベクトルの積だけになる。

**整合の取れた初期値。** 状態変数（状態量。コンデンサ電圧、インダクタ電流）は初期値 `ic` を保ち、残りの変数は、方程式のうち微分を含まない部分から決める（`consistent_maps`）。ここで解が一意に決まらない回路（基準節点から浮いた部分、電圧源だけのループ、電圧源とコンデンサの直結、電流源とインダクタの直列、インダクタどうしの直列など）を、計算の前に `CircuitError` にする。決まらない変数と、直し方の手がかりを文に添える。与えた `ic` と回路のつなぎ方が矛盾するときは、実際に始めた値を注意に出す。

**不連続点の扱い（D-007、D-019）。** 計算の先頭、電源のステップ、スイッチやダイオードの切り替えでは、状態変数を連続に保ち、残りの変数を合わせ直す。

**減衰のための後退オイラー法のステップ（コードの表記: 減衰ステップ）。** 台形則は、時間刻みより速い成分（オフ抵抗を通るインダクタ電流など）を減衰させず、符号を変えながら残す。そこで不連続点の直後だけ、1ステップを 1024 個の後退オイラー法に分割したステップで進める（途中の電源の値は両端の直線補間。行列のべき乗で1つの行列にまとめるので、1ステップの費用は通常のステップとほぼ同じ）。速い成分は消え、遅い成分はほぼ厳密に進む。

| 場面 | 進め方 |
|---|---|
| スイッチの無い回路 | 台形則。刻みが最も速い時定数の半分を超えるとき（`abs(λ)·h > 0.5`）だけ、計算の先頭と電源のステップの直後に減衰ステップを2回（D-035）。それ以下なら台形則だけで、2次精度をそのまま保つ |
| スイッチを含む回路の先頭、電源の不連続点 | そこから減衰ステップを2回 |
| スイッチング状態が変わるステップ | そのステップは分割しない後退オイラー法で進め（ダイオードの導通の判定が1つに決まる）、続く2ステップを減衰ステップにする |
| それ以外 | 台形則 |

減衰ステップの数は `simulate(..., damping_steps=)` で変えられる（既定 2。0 で入れない）。

**スイッチング状態ごとの行列の使い回し。** スイッチング状態は整数の符号で表す（下位ビットがスイッチ、上位がダイオード。1 = オン）。出会った状態だけ行列を用意して表に足す（`_StateTable`）。核は、用意していない状態に出会うと外に戻り（`NEED_STATE`）、外が行列を足して同じステップからやり直す。同期整流の降圧コンバータの例で用意する状態は2つ（統合前（E1b）の例で `stats["states"]` を確かめた）。

**時間刻みと終了時刻の既定。**

| テンプレート | 時間刻み | 終了時刻 |
|---|---|---|
| `rc_lowpass`、`rlc_series` | 最も速い極の周期の 1/200 | 最も遅い減衰の時定数の5倍。ステップ数が2万を超えるときは、時間刻みか終了時刻を調整して注意に出す |
| `buck_voltage_mode`（統合前（E1b）） | スイッチング周期の 1/200（状態平均化モデルは 1/10） | LC の共振周期の20倍（負荷ステップや指令値のステップがあれば、最後のステップの時刻に足す）を、制御周期の整数倍に切り上げ |

キャリアの周期と制御周期は、時間刻みの整数倍でなければエラーにする。終了時刻が刻みの整数倍でなければ、近い整数ステップで終えて注意に出す。

**上限。** ステップ数は 2000 万まで、配列（結果と作業用）は 2 GiB まで。超える計算は、配列を確保する前に `StepLimitError` で断る（理由と直し方を添える）。Python から呼ぶときは `max_steps` で上げられる。

### 6.3 スイッチ、ダイオード、PWM、離散時間の制御器

**ダイオード。** 理想ダイオード（順方向電圧 0）。いまのスイッチング状態で1ステップ試し、ステップの終わりで、オンのダイオードの電圧が負、またはオフのダイオードの電圧が 1 nV を超えていたら、反転してやり直す。最初の4回は違反したものを同時に、その後は1つずつ反転する。max(20, 4 × ダイオードの数) 回で落ち着かなければ、時刻と状態が分かるエラーにする。t = 0 だけは、違反が丸め誤差の幅に収まる状態を採る救済がある（D-035）。

**PWM（`Pwm`）。** キャリアはのこぎり波（周期の先頭でオン。`Pwm` 単体の既定）か三角波（オンの区間が周期の中央。レグ部品の既定。D-044）。

- 切り替えの時刻は時間刻みの格子に丸める。1周期を N ステップ（既定 200）に分けるので、1周期のデューティの分解能は 1/N。丸めの余りは次の周期に持ち越す（D-021）。
- デューティはキャリアの周期の先頭で取り込み、その周期のあいだ変えない。
- 相補のゲート（`complement`）は、上のゲートがオフの区間だけオンになる。デッドタイムは 0 だけ（0 以外はエラー）。統合前（E1b）。

**制御器のタイミング。** 制御器は離散時間。制御周期 Ts ごとに核から戻り、次の順で動く（`control/interface.py`、`simulate.py`）。

1. 時刻 k·Ts の検出値（測定値。結果に記録される値と同じ。その時刻の切り替えの直前の値）を `step()` に渡す。
2. 返った指令は、次の制御周期の先頭（(k+1)·Ts）から1周期のあいだ使う（演算遅れ 1 制御周期）。
3. 最初の制御周期には、`reset()` が返した指令を使う。

```
時刻             0              Ts             2Ts            3Ts
                 │              │              │              │
検出             y[0]           y[1]           y[2]           y[3]     ← 周期の先頭（三角波では上アームのオフ期間の中央）
                 │              │              │              │
演算             └── u[0] ──┐   └── u[1] ──┐   └── u[2] ──┐
                 │          ▼   │          ▼   │          ▼   │
使う指令         │ reset() の値 │ u[0]         │ u[1]         │ u[2]   ← 検出から反映まで 1 制御周期（演算遅れ）
                 │              │              │              │
ゲート（三角波） │ ▁▁▁████▁▁▁   │ ▁▁▁████▁▁▁   │ ▁▁█████▁▁    │        ← 周期の先頭で取り込み、周期のあいだ保持
                 │              │              │              │          （零次ホールド。平均して 0.5 サンプルの遅れ）
```

小信号で見た遅れは、演算遅れの1サンプルと零次ホールド（保持）の 0.5 サンプルを合わせた 1.5 サンプル。安定余裕の計算には必ずこれを入れる（7章）。三角波のキャリアでは、この 0.5 サンプルがデューティによらず一定になる。のこぎり波では (0.5 − D) サンプルだけ動く（D-044）。
スイッチング周波数は制御周波数の整数倍にする（`buck_voltage_mode`）。こうすると、指令の変わる時刻とキャリアの周期の先頭がそろう。

### 6.4 モデルの切り替え（決まり6）

仕様の `simulation.fidelity` で選ぶ。統合前（E1b）。

| モデル | 回路 | 使いどころ | 状態 |
|---|---|---|---|
| スイッチングモデル（既定） | 上下のスイッチを、オン抵抗 `r_on` の理想スイッチと相補のゲートで計算する。リプルが出る | 最終の確認、リプルと入力電流を見る | 統合前（E1b） |
| 状態平均化モデル | レグを、電圧源「デューティ × 直流電圧」とオン抵抗の直列に置き換える（従属電圧源）。スイッチング周期の平均を計算する | ゲイン最適化の評価。ステップ数はスイッチングモデルの約 1/20 | 統合前（E1b） |
| 理想 | トルク源と、電流応答の1次遅れ | 機構の計算と組むとき | 予定（時期は未定） |

- 降圧コンバータは同期整流にしてある（D-038）。ダイオード整流は軽負荷で電流不連続モードになり、状態平均化モデルが成り立たない。同期整流なら、どの負荷でも両モデルの周期平均が一致する。
- 状態平均化モデルは、入力の電源にインピーダンスが無い前提。そうでない回路と入力電流はスイッチングモデルで見る、と注意に出す。
- スイッチングモデルの定常の周期平均は、指令値より ΔI·(1 + D)/(24·f·C) 低くなる（三角波のキャリアの検出の時刻が、コンデンサ電圧のリプルの山に当たるため。物理として正しい効果で、直さない。D-047。D-047 の ΔI/(16·f·C) は D = 0.5 の値。基準の回路で 7.98 mV、−0.066%。`accuracy-and-resolution.md` 2.5）。
- スイッチの無いテンプレートは、モデルを選べない。指定があれば使わず、注意に出す。

### 6.5 注意の判定

計算は、結果をそのまま信じてよいかに関わることを `notes` に書く（決まり4。黙って誤った波形を返さない）。

| 条件 | 中身 |
|---|---|
| 刻みが最も速い時定数の2倍を超える | その成分の変化は波形に現れない。見るための刻みを添える。スイッチを含む回路では、使ったスイッチング状態ごとに調べ、オフ抵抗が作る見かけの成分は除く |
| 回路の振動、または正弦波の電源の1周期が 10 点未満 | 周波数と減衰が正しく出ない。勧める刻みを添える |
| 台形則の位相のずれが、入力の 0.8% を超える見込み（`rc_lowpass`、`rlc_series`。刻みを指定したときも見る） | 精度が落ちることと、勧める刻みを添える |
| 電源のステップ時刻、終了時刻を格子に合わせた。負荷ステップの時刻をスイッチング周期の先頭に切り上げた | 元の値と、使った値 |
| インダクタ電流が、還流経路の無いまま切り替えで遮断された | 時刻、素子、その直後の電圧が見かけの値であること |
| 単位を換算した、使わない項目を無視した、省いた項目を既定で扱った（`C_esr`、`Tf`。D-045） | 何をどうしたか |

注意の出すぎと見逃しが、軽微なものとして残っている（予定（E1e））。

## 7. 制御とゲイン設計

### 7.1 離散 PID（`control/blocks.py`）。統合前（E1b）

並列形。1回の `update()` が1サンプル（周期 Ts）。

```
P[k] = Kp·e[k]
I[k] = I[k−1] + Ki·Ts·e[k]
D[k] = a·D[k−1] + b·(e[k] − e[k−1])        a = Tf/(Tf + Ts)、b = Kd/(Tf + Ts)
u[k] = clip(P[k] + I[k] + D[k], 下限, 上限)
```

- 微分は `Kd·s/(1 + s·Tf)` を後退差分で離散化したもの。最初のサンプルの微分の項は 0（起動で跳ねない）。
- アンチワインドアップ（条件付き積分。いまの画面とコードの説明の表記: 積分の飽和を防ぐ処理。`anti_windup="clamp"`）: 積分を進める前の出力が上下限で飽和していて、偏差が飽和を深める向きなら、積分を進めない。
- 微分は偏差に掛ける（既定）か、検出値に掛けるかを選べる（`derivative_on`）。帰還の経路は同じなので、一巡伝達関数と安定余裕は変わらない。テンプレートの項目には出していない。
- 偏差が V、出力がデューティなら、単位は Kp [1/V]、Ki [1/(V·s)]、Kd [s/V]。
- 微分フィルタの時定数 Tf（不完全微分）を省いたときは 0.25·Ts を入れ、Kd > 0 なら注意を出す（D-045）。
- `PidController` が制御器の口に合わせる。指令値は数値か、時刻で決まる区分一定の値（`Schedule`）。

### 7.2 初期ゲインの設計（`tuning/initial.py`）。統合前（E1b）

`buck_voltage_mode_pid(v_in, inductance, capacitance, r_load, f_ctrl, ...)` が、電圧モードの降圧コンバータの PID の初期値を解析式で決める。ゲイン最適化（E2）の出発点。

1. 状態平均化モデルの小信号の伝達関数 `Gvd(s) = Vin / (1 + s/(Q·ω0) + s²/ω0²)` を、零次ホールドで離散化する。演算遅れ 1 制御周期（z⁻¹）と、実装と同じ PID の差分方程式の z 変換を掛けて、一巡伝達関数（開ループ）にする。
2. PID の2つの零点を LC の共振の下に置く（ωz = κ·ω0、既定 κ = 0.5、減衰 ζz = 0.3）。Tf は 0.25·Ts。
3. ループの位相が −180° + 位相余裕（既定 55°）になる周波数を、共振の上で探してゲイン交差周波数にする。Ki は、そこでループのゲインが 1 になるように決める。
4. 返す前に確かめる。どれかが成り立たなければ `GainDesignError`（理由のコード、目標、最良の候補つき）。

| 確かめること | 決まり | 決定 |
|---|---|---|
| 位相余裕 | ゲインが 1 を横切るすべての点の余裕の最小が、目標 − 1e-6° 以上。位相は低い周波数から連続に取る（主値で取ると、不安定なゲインを大きな余裕と読む） | D-057 |
| 安定 | 離散時間の閉ループ極の絶対値の最大が 1 − 1e-9 以下のときだけ「安定」と言う。境目は `no_stability_margin` で断る。E1b の5回目の検証で、D-059 の範囲の端（Vin が大きい）では丸めがこの幅を超え、境目の設計を成功として返す例が見つかった（修正の最中） | D-057、D-062 |
| 引数の範囲 | 実用の範囲の外側に3桁以上の余裕を取った範囲で受ける。外、NaN、無限大は `invalid_argument`。D-062 で「受け付ける範囲 ＝ 検証で確かめた範囲」にそろえる（範囲は統合までに変わりうる） | D-059、D-062 |
| 零点の範囲 | 零点の比 κ は 1 以下、減衰 ζz は 2 以下（κ > 1 は条件つき安定の設計になる） | D-057 |
| 探索の上限 | ナイキスト周波数の手前に制限し、制限したことを結果と文に残す | D-057 |

「達成したか」の印を戻り値に持たせず、未達を例外にしてあるのは、印を見ずに不安定なゲインが使われるのを防ぐため（決まり4）。
基準の回路（24 V、47 µH、100 µF、6 Ω、100 kHz）での結果は、Kp 0.01174 1/V、Ki 147.1 1/(V·s)、Kd 2.736e-6 s/V、ゲイン交差周波数 3.58 kHz、位相余裕 55.0°、閉ループ極の絶対値の最大 0.967（2026-11-16 に E1b のコードで計算）。同梱の例の値（Kp 0.0117、Ki 147、Kd 2.74e-6）は、これを3桁に丸めた値と一致する。

### 7.3 ゲイン最適化。予定（E2）

方式は `architecture.md` 5章のとおり。コードはまだ無い。

1. 初期値は 7.2 の解析式。
2. 状態平均化モデルで評価関数を最小化する。評価関数 = ITAE + ペナルティ（オーバーシュート、整定時間、余裕の不足、操作量の飽和、電流制限）。設計目標の種類は部品として足せる形にする。
3. 線形化した一巡伝達関数から安定余裕を計算して制約にする（遅れ 1.5 サンプルを含める）。
4. スイッチングモデルで確認する。定常偏差は、D-047 のずれを含めて判定する。
5. 満たせない目標には、最良のゲインと「どの目標が、どれだけ未達か」を返す。未達を達成と表示しない（決まり4）。
6. 同じ仕様からは同じゲインが出る（乱数のシードを固定する）。

前提は、デューティの分解能の改善（E1f。D-036）と、検出と PWM の量子化を選べる部品にすること（E1h。D-063）。

```
├───────────────┴──────────────────────────────────┴───────────────────────────┤
│ お知らせ: エラー、不足、注意（何が起きたかと、どう直すかを対で）                 │
└──────────────────────────────────────────────────────────────────────────────┘
```

| 領域 | 役割 | 状態 |
|---|---|---|
| ヘッダー | 開いている仕様、ファイルの操作、実行と進み具合、言語とテーマ | 統合前（A0）。実行は予定（A1） |
| 起動直後の画面 | 仕様を開いていないときの入口（ファイルを選ぶ、ドロップ、サンプル） | 統合前（A0） |
| 仕様パネル | 値、単位、出典を一覧し、その場で直す。不足とエラーを行で示す | 枠は統合前（A0）。中身は予定（A1） |
| 回路図 | テンプレートごとの固定図に値を重ねる。測定点から信号を選ぶ | 予定（A1） |
| スコープ | 波形、拡大縮小、カーソル、前回との比較、CSV | 予定（A1） |
| お知らせ | 番号と差し込む値から、辞書の文を作って出す | 統合前（A0） |
| 設計目標と結果、レポート、取り込み | — | 予定（A2、A3） |

- 文言は直書きしない（決まり8）。辞書の元は画面仕様の文言の表だけで、`frontend/tools/strings_from_spec.py` が表から日英の辞書を作る。表と辞書の食い違いは試験が見つける。
- 画面は、テンプレートごとの「表示定義」（項目、信号、図、モデル）から、仕様パネルの行、回路図、スコープの信号を作る（`screens-v0.1.md` 付録A.1）。エンジンの側の定義は `templates/items.py` の `Item` と `SignalInfo`（統合前（E1b））。サーバーから画面へ渡す口は予定（E1g、A1）。
- 使えないものを先に置かない（`app-design.md` 3章）。

### 8.2 画面の状態遷移

```
 ページを開く
      │
      ▼
 ┌──────────┐ 401（クッキーが無い） ┌────────────────────────────────────┐
 │ 接続中    │─────────────────────►│ 合言葉が無い                        │
 └────┬─────┘                       │ 端末の URL から開き直すよう案内する  │
      │ /api/health が応答           └────────────────────────────────────┘
      ▼
 ┌──────────────┐ 開く、サンプル、ドロップ ┌──────────────┐  実行   ┌──────────┐
 │ 開いていない  │────────────────────────►│ 開いた        │────────►│ 実行中    │
 │（起動直後）   │◄──────（開けない）───────│（結果なし）    │◄────────│          │
 └──────────────┘  理由をお知らせに出す     └──────────────┘ 中断、失敗└────┬─────┘
                                                                            │ 完了
                                    ┌──────────────┐  値を変える       ┌────▼─────┐
                                    │ 古い結果      │◄─────────────────│ 結果あり  │
                                    │ 波形は残す    │──値を元に戻す───►│          │
                                    └──────┬───────┘                  └────┬─────┘
                                           └──────── 実行 ──► 実行中 ◄──────┘

 どの状態からも: 応答が無い ──► 接続が切れた（画面の中身は残す。開く、保存、実行、編集は使えない）
                 2 秒ごとにつなぎ直す ──► 応答があれば元の状態へ
 アプリ本体が起動し直されていたら: 画面が持つ仕様を送り直し、結果は消える（N-CONN-RESTART）
```

- **統合前（A0）にある状態**: 接続中、合言葉が無い、接続が切れた、開いていない、開いた。ブラウザを再読み込みしても、開いている仕様は戻る（サーバーが持つ）。「合言葉が無い」は、画面仕様 1.3 にまだ書かれていない（A1 で入れる。15.3）。
- **予定（A1。E1g の口が前提）の状態**: 実行中（進み具合と中断。計算中も画面は使える）、結果あり（結果は、計算を始めたときの仕様の写しを持つ）、古い結果（波形は薄くせず、帯で知らせる）。編集内容と結果の復元も A1。
- 中断や失敗のときは、その実行の波形を捨て、直前に完了した結果があればそれを残す。途中の結果は見せない（`screens-v0.1.md` 7.3）。

## 9. 外部インターフェース

### 9.1 コマンドライン

**計算: `python -m circuit_sim 仕様.json [--csv 出力.csv]`。実装済み。**

| 項目 | 内容 |
|---|---|
| 引数 | `spec`（仕様 JSON。必須）、`--csv`（波形の書き出し先） |
| 標準出力 | テンプレート名、終了時刻（いまの出力の表記: 計算時間）・時間刻み・ステップ数、`probes` の信号ごとの最終値・最大・最小、注意（展開の注意と計算の注意） |
| 標準エラー | 失敗の理由を1行（「計算できません。…」など） |
| 終了コード | 0 = 計算できた。2 = 計算できなかった（ファイルが読めない、仕様の形の誤り、値の不足、読めない単位、解けない回路、ステップ数の上限、引数の誤り） |
| 文字コード | 仕様は UTF-8（BOM は無視）。UTF-8 でない端末（日本語 Windows の cp932）では、表せない文字を置き換えて出す（`µ` → `u`、`Ω` → `ohm`） |

出力の例（`examples/rlc_series.json` の2行目）: `計算時間: 0.01 s / 刻み: 3.14169e-06 s / ステップ数: 3183`。

**起動: `circuit-sim [--port ポート] [--no-browser]`。統合前（A0）。**

| 項目 | 内容 |
|---|---|
| `--port` | 待ち受けるポートを決める。使えなければ、理由を出して終わる。省くと 28470 から順に試す（2.2） |
| `--no-browser` | ブラウザを開かず、開く場所の URL を表示する |
| `-h`、`--help` | 使い方を出して終わる |
| ファイルの引数 | 受け取らない（仕様 JSON は起動した後に画面で開く、と案内して終了コード 2） |
| 端末の表示 | 起動の URL（起動コードつき。5 分だけ使える）、新しい URL の出し方（Enter）、止め方。文言は OS の言語で日本語か英語 |
| 止め方 | Ctrl+C。保存していない変更があるときは、1回目では止めずに知らせ、10 秒以内にもう一度押すと止める。端末の窓を閉じたとき、SIGTERM のときは、知らせずに止まる |
| 終了コード | 0 = 止めた。2 = 起動できなかった（ポートが使えない、設定の場所に書けない、引数の誤り） |

### 9.2 HTTP API。統合前（A0）

経路は `app/server.py`。本文は JSON。合言葉のクッキーが要るのは `/api/` だけ。

| メソッド | 経路 | 要求 | 応答（200） | 個別のエラー |
|---|---|---|---|---|
| GET | `/api/health` | — | `{instance, version}`。`instance` は起動ごとに変わる（起動し直しを画面が知る） | — |
| GET | `/api/samples` | — | `{samples: [{id, file, template, name, desc}]}`。`name` と `desc` は辞書のキー。テンプレートの無いサンプルは出さない | — |
| POST | `/api/open` | `{sample}`、または `{file, text}`（`file` は表示に使う名前だけ） | 開けた: `{ok: true, doc: {file, template, text, sample}}`。開けない: `{ok: false, notice}` | 404（知らないサンプル）、422（欄の不足） |
| GET | `/api/session` | — | `{doc, dirty}`（開いている仕様と、保存していない変更の有無） | — |
| PUT | `/api/session` | `{doc, dirty}`（`doc` は `null` でもよい） | `{doc, dirty}` | 422 |
| GET | `/api/settings` | — | `{settings: {名前: 値}}` | — |
| PUT | `/api/settings` | `{settings: {名前: 値または null}}`（`null` は消す） | `{settings}` | 422（知らない名前、形の違う値）、500（設定の場所に書けない） |
| すべて | `/api/` の上記以外 | — | — | 404 |
| GET、HEAD | `/`、`/index.html` | `?k=起動コード`（省略できる） | 画面の入口の HTML。起動コードつきは `/` へ移し、その起動コードが使えるものなら合言葉のクッキーを付ける | — |
| GET、HEAD | 画面のファイル（`/assets/…` など） | — | ファイル | 404（無い、認めない形の名前） |

共通のエラー（要求の確かめ。11章）。本文は `{"detail": 内部の説明}`。

| 状態 | 条件 |
|---|---|
| 400 | Host がこの PC の名前（`127.0.0.1`、`localhost`、`[::1]`）でない |
| 403 | 書き込みの要求で、Origin がこのページと違う（Origin が無ければ Sec-Fetch-Site が `same-origin` 以外） |
| 401 | `/api/` で、合言葉のクッキーが無い、または違う |
| 415 | 書き込みの要求で、Content-Type が `application/json` でない |

仕様が開けないときは、エラーの状態ではなく 200 の `{ok: false, notice}` で返す。`notice` は `{code, params, details, items}`（文面ではなく、番号と差し込む値。10章）。サーバーが確かめるのは、JSON として読めるか、版、仕様の形、テンプレートの有無（`screens-v0.1.md` 4.2 の 5〜8。1〜4 は画面が確かめる）。

**予定（A1。E1g の口が前提）。** 表示定義、仕様の確かめ（計算の前に分かること）、実行と進み具合と中断、画面用に間引いた波形、カーソルの値、CSV、状態の復元（`screens-v0.1.md` 12章の D2〜D7、D9）。経路は ui-engineer が決める。波形は、サーバーの側で画面の横1列ごとの最小値と最大値に間引いて送る（`architecture.md` 7章）。

### 9.3 エンジンの Python の口

```python
from circuit_sim import Spec, expand, simulate

spec = Spec.model_validate_json(text)           # 層A の検証
ex = expand(spec)                               # 層A → 層B と計算の設定
res = simulate(ex.netlist, ex.t_end, ex.h)      # 実装済み（スイッチの無いテンプレート）
res = ex.run()                                  # 統合前（E1b）。ゲート信号と制御器も渡す
res["v(out)"], res.t, res.notes                 # 波形（NumPy の配列）、時刻、注意

simulate(netlist, t_end, h=None, *, gates=(), controllers=(),
         steps_per_period=None, damping_steps=2, max_steps=None) -> Result
```

- `h`: 時間刻み。スイッチの無い回路では必須。省くと、最も速いキャリアの周期を `steps_per_period`（既定 200）で割る。
- `gates`: PWM の並び（スイッチの `gate` から名前で引く）。`controllers`: 制御器の並び（`Controller` の口）。
- `damping_steps`、`max_steps`: 6.2。

例外はどれも `ValueError` の一種（10章）。制御器の形が口に合わないときだけ `TypeError`。
進み具合を知らせる口と中断の口は予定（E1g）。区切りは核の外に置き、区切っても結果がビット一致することを基準にする。

### 9.4 AI のプロバイダ層。予定（I2）

- 公開するのは2つだけ（決まり1）: `extract(共通テキスト, スキーマ) → 層A` と `explain(結果) → 説明文`。
- 最初の実装は、ローカルの CLI をヘッドレスで呼ぶ（D-008）。API キーやローカルモデルにも差し替えられる形にする。
- AI に元のファイルを読ませない。コードが「位置ラベルつきの共通テキスト」に変換してから渡す（予定（I1））。
- 送る内容は、送る前に画面で示す（決まり9）。決まり9 が認める例外は抽出の依頼だけで、`explain` で結果を AI に渡すことは、まだ決まっていない（PO の判断が要る。`requirements.md` 8.1 の P-5）。
- 同じ入力への応答はキャッシュする。試験は記録した応答で行い、本物の AI を呼ばない（決まり11）。
- AI が無くても、層A を手で書けば残りはすべて動く。

## 10. エラーと注意の設計

### 10.1 原則

- **推測で埋めない。未達を達成と表示しない**（決まり4）。足りない値は足りないと返す。満たせない目標は、最良の候補と不足の大きさを添えて未達と返す。
- **黙って誤った波形を返さない。** 計算はできるが信じてよいか怪しいときは注意、計算できないときはエラーにする。
- **エラーは原因と直し方を対で**（`app-design.md` 4章の原則9）。プログラムの内部の文は主文に出さず、「詳細」に入れる。
- **文面は画面の辞書が持つ**（決まり8）。サーバーと画面の間は、番号と差し込む値でやり取りする。

### 10.2 種類

| 種類 | いまの形 | 出す場所 | 状態 |
|---|---|---|---|
| 仕様の形の誤り | `pydantic.ValidationError` | `ir.py` | 実装済み |
| 値の不足 | `MissingValueError`（`names` に足りない名前） | `templates/` | 実装済み |
| 単位の誤り | `UnitError` | `units.py`、`templates/` | 実装済み |
| 値が範囲の外、未対応のテンプレート、周期が刻みの整数倍でない | `ValueError` | `templates/`、`simulate.py` | 実装済み |
| 解けない回路、ダイオードの状態が決まらない | `CircuitError` | `kernel.py`、`simulate.py` | 実装済み |
| 計算が大きすぎる | `StepLimitError` | `simulate.py` | 実装済み |
| ゲインの設計の未達、引数の誤り | `GainDesignError`（`reason`、`target_deg`、`best`） | `tuning/initial.py` | 統合前（E1b） |
| 展開の注意 | `Expanded.notes`（日本語の文） | `templates/` | 実装済み。`Result.notes` と CSV に入れるのは予定（E1g） |
| 計算の注意 | `Result.notes`（日本語の文） | `simulate.py` | 実装済み |
| 仕様が開けない | `notice`（`N-OPEN-*`） | `app/server.py`、画面 | 統合前（A0） |

### 10.3 番号の付け方。予定（E1g）

いまエンジンが返すのは日本語の文。E1g で、番号（例 `STEP_COARSE`）と差し込む値（数値は単位つき）の組に替える。

- 日本語と英語の文面は辞書から作る。いまの日本語の文面は、辞書の日本語として残す（受け入れ試験が見ている文面を変えない）。
- エンジンとテンプレートが出す注意とエラーのすべてに番号を付け、番号の無い文が出ないことを試験で確かめる。
- コマンドラインは同じ辞書で表示する。
- エンジンの番号と、画面のお知らせの番号（`screens-v0.1.md` 付録B）の対応表を作る。

### 10.4 画面のお知らせとの対応

画面のお知らせは `N-` で始まる番号を持ち、段階（エラー、不足、注意）と種類（出来事、状態）に分かれる（`frontend/src/notices.ts`。統合前（A0））。下の表は、エンジンのいまの条件と付録B の番号を突き合わせたもの。正式な対応表は E1g が作り、エンジンから番号で受け取れるようになるのも E1g から。

| エンジンの条件 | いまの形 | 画面のお知らせ（付録B） |
|---|---|---|
| JSON として読めない、版が読めない、形が合わない、テンプレートが無い | サーバーが判定（統合前（A0）） | N-OPEN-SYNTAX、N-OPEN-VERSION、N-OPEN-SCHEMA、N-OPEN-TEMPLATE |
| 値の不足、組で入れる値の片方だけ | `MissingValueError` | N-MISSING、N-MISSING-PAIR |
| 値が範囲の外 | `ValueError` | N-INVALID |
| 単位の次元が違う、読めない | `UnitError` | N-UNIT-WRONG |
| 単位を換算した | 展開の注意 | N-UNIT-CONVERTED |
| 使わない項目がある | 展開の注意 | N-UNUSED |
| 版 0.1 の `control` を数値で読んだ | 展開の注意（統合前（E1b）） | N-OPEN-LEGACY |
| ステップ数の上限 | `StepLimitError` | N-STEPS-LIMIT（実行の前）、N-RUN-STEPS（実行の後） |
| 刻みが粗い | 計算の注意 | N-STEP-COARSE（実行の前）、N-RUN-NOTE-STEP（結果） |
| 電源のステップ時刻を丸めた | 計算の注意 | N-RUN-NOTE-ROUND |
| 回路が解けない | `CircuitError` | N-RUN-CIRCUIT |
| ダイオードの状態が決まらない | `CircuitError` | N-RUN-SWITCH |
| 制御器の指令が有限値でない | `ValueError`。回路の変数そのものの発散を調べる処理は、いまは無い（予定（E1g の範囲11）。15.3） | N-RUN-DIVERGED |
| 番号の無い注意、上のどれでもない失敗 | — | N-RUN-NOTE-OTHER、N-RUN-INTERNAL（内部の文を「詳細」に入れる） |

`C_esr` と `Tf` を省いたときの注意は、画面ではお知らせに出さず、行の値と出典（既定値、自動）で示す（`screens-v0.1.md` 付録A.4）。
A0 のコードには、付録B に無い番号 N-PREFS-SAVE（画面の好みを設定ファイルに書けなかった）がある。画面仕様への追記は未了（A1 で入れる。15.3）。

## 11. 安全の設計

### 11.1 前提

利用者の設計書とデータは端末の外に出さない（決まり9）。アプリ本体は 127.0.0.1 だけで待ち受けるので、ほかの機械からは届かない。残る相手は、同じ PC のブラウザで開いた別のサイトのページと、同じ PC の別の利用者。依存の版の既定の動きに頼らず、サーバーが自分でも確かめる（D-051）。統合前（A0）。

### 11.2 脅威と対策

| 脅威 | 対策（仕組み） | 場所 | 決定 |
|---|---|---|---|
| 外のサイトのページが、DNS の付け替えでローカルサーバーに届く | **Host の確かめ。** Host が `127.0.0.1`、`localhost`、`[::1]` でなければ 400 | `server.py`（`TrustedHostMiddleware`） | D-051 |
| 別のサイトや、同じ PC の別のポートのページから書き込まれる | **Origin と Content-Type の確かめ。** 書き込みの要求（GET、HEAD、OPTIONS 以外）は、Origin がこのページと同じでなければ 403（Origin が無ければ Sec-Fetch-Site を見る）。`application/json` でなければ 415。クッキーの SameSite はポートを区別しないので、Origin で防ぐ | `server.request_problem` | D-051 |
| 同じ PC の別の利用者が、作業の状態を読み書きする | **合言葉。** `/api/` は、合言葉のクッキー（`circuit_sim_key`。HttpOnly、SameSite=Strict）が無ければ 401。合言葉は起動ごとに変えず、設定の場所に保存する。比べる時間は、どこまで合っているかによらない | `config.load_token`、`server.token_ok` | D-051、D-053 |
| 合言葉のファイルを別の利用者が読む | **設定の場所の権限。** POSIX は場所が 0700、ファイルが 0600。Windows は本人と SYSTEM だけの権限（ACL）を明示して付け、上の階層から受け継がない。権限が広い、持ち主が違う、形が違う合言葉は、漏れたものとみなして作り直す | `config.py` | D-053 |
| 合言葉が、ブラウザの起動の引数や履歴から別の利用者に読まれる | **起動コード。** URL（`/?k=…`）に載せるのは、合言葉ではなく、一度だけ・5 分だけ使える起動コード（同時に8個まで、メモリにだけ持つ）。サーバーが合言葉のクッキーと交換し、起動コードの無い URL へ移す。**転送用の HTML。** ブラウザには URL を渡さず、その URL へ移るだけの HTML（設定の場所に、本人だけが読める権限で書く）の場所を渡す。使われた、期限が切れた、止めたときに消す | `server.Launches`、`cli.LaunchPages` | D-056 |
| 画面のファイルの経路から、外のファイルを読む。Windows で UNC が外への接続になる | **名前の確かめ。** 英数字と `. _ -` だけ。絶対パス、UNC、バックスラッシュ、ドライブ名、`..`、Windows の装置名は、パスを組み立てる前に拒む | `server.safe_parts` | D-051 |
| 画面が外部のスクリプトや書体を読み込む、利用者のデータを外へ送る | 画面の部品は同梱物と端末の書体だけ。Content-Security-Policy（自分の場所のものだけ）、`nosniff`、`Referrer-Policy: no-referrer`。ネットワークを切っても動くことを受け入れ基準で確かめる（AC-1-7） | `server.py` | 決まり9 |
| 依存の版が下がって、安全の前提が崩れる | 依存の下限（fastapi ≥ 0.133、starlette ≥ 1.1）と、サーバー自身の確かめの両方 | `pyproject.toml` | D-051 |
| 試験のための抜け道が製品に残る | 合言葉を確かめない起動を持たない（`create_app` は合言葉が必須）。試験は製品と同じ手順を使う | `server.create_app` | D-054 |
| 設定ファイルで利用者のデータが外に出る | 設定の場所は端末の中だけ。置くのは合言葉と画面の好みで、仕様と結果は置かない | `config.py` | D-050 |
| 試験が、利用者の本物の設定や本物の `claude` に触れる | 試験は設定の場所を一時フォルダに向ける。PATH から `claude` を外し、見張り役を置く | `tests/conftest.py` | D-033、決まり11 |

**既知の制限（D-053）。** クッキーはポートを区別しない。同じ PC で別の利用者が動かす悪意あるサーバー（127.0.0.1 の別のポート）を本人がブラウザで開くと、クッキーが渡りうる。防ぐ手段がブラウザに無いため、v0.1 では受け入れる。

**AI への送信。予定（I2）。** 端末の外に出る唯一の例外。送る内容を、送る前に画面で示す（決まり9）。送信が増える変更は PO の判断が要る（結果の説明の扱いは 9.4）。

## 12. 拡張の設計

### 12.1 テンプレートを足す

テンプレートは、層A を層B と計算の設定に展開する関数。新しいテンプレートを足すときに触る場所（統合前（E1b）の形に沿う）。

1. `circuit_sim/templates/<名前>.py`: 項目の定義（`Item`: 名前、`plant` か `control` か、次元、必須か、組で入れる相手、図の素子）、展開の関数（`Spec` → `Expanded`）、表示する信号（`SignalInfo`）。値は `read_items` で読む（不足と単位の誤りをまとめて報告する）。
2. `circuit_sim/templates/__init__.py`: `TEMPLATES` と `TEMPLATE_ITEMS` に登録する。
3. 新しい次元の単位が要るなら `units.py` に足す。
4. スイッチのレグがあるなら `templates/legs.py` の `HalfBridgeLeg` を使う（モデルの切り替えが付いてくる）。
5. 制御があるなら `control/` のブロックを組み、制御器の口に合わせる。
6. 例を `examples/` に置く。アプリに同梱するなら `circuit_sim/app/samples/` と `server.py` の `SAMPLES` に足す（値は SI 単位（接頭語なし）で書く。`screens-v0.1.md` 付録A.5）。
7. 画面: 画面仕様の付録A に表示定義（項目、信号、図、文言の表）を書き、辞書を作り直し、画面をビルドし直す。
8. 検証: `model-validation` スキルの型で試験を付ける（13章）。信号の情報が画面仕様の表と1対1で合うことの試験も足す（`tests/test_e1b_signals.py` の形）。
9. 文書: この文書の3章・5章・14章、`accuracy-and-resolution.md`、`glossary.md`、`requirements.md`。

### 12.2 モーターの負荷の差し替え（決まり6）。予定

モーターは「トルクを出し、角度と速度を受け取る」口を持つ。最初の相手は固定の慣性と摩擦、将来は物理エンジン（`architecture.md` 4章）。コードはまだ無く、口の形も決まっていない。DC モーターのテンプレートが入る E3 の仕様（未着手）で決める必要がある。核の決まり（最内ループは配列と数値だけ）は、ここでも守る。

### 12.3 モデルの切り替え

6.4 のとおり、`simulation.fidelity` とレグ部品で切り替える。3つ目の「理想」は予定。画面は、モデルの行を2択ではなく選択欄にしてある（`screens-v0.1.md` 13章）。

### 12.4 `schema_version` による拡張

層A に欄を足すときは版を上げ、古い版も読めるようにする（5.1 の互換の形）。機構（外部の機構ファイルへの参照、関節とモーターの対応）は、版を上げて層A に足す（`architecture.md` 3章）。予定（X1〜）。

### 12.5 物理エンジンとの連成。予定（X1〜）

3次元の物理は自作せず、既存の物理エンジン（第一候補 MuJoCo）と連成する（D-011）。このツールが持つのは、アクチュエータ（モーター、減速機、駆動回路、制御）とそのゲイン設計。備えは 12.2 と 12.4。

### 12.6 速度の改善の順番（D-001、決まり10）

測ってから手を入れる。順番は、計算量を減らす → 最適化の評価を並列に走らせる → 核を Numba でコンパイル → それでも足りなければ C / C++ / Rust。核の最内ループを配列と数値だけにしてあるのは、この載せ替えのため。いまは Python と NumPy、SciPy だけで、Numba は入れていない。

## 13. 品質と試験の方針

### 13.1 数値モデルの検証の型（決まり5）

数値モデルは、検証なしに統合しない。型は `model-validation` スキル。

| 型 | 確かめること | 例 |
|---|---|---|
| 解析解 | 手で解ける場合と一致する | RC・RLC のステップ応答、降圧コンバータの定常値とリプル |
| 収束次数 | 刻みを半分にしたとき、誤差が理論どおり減る | 台形則なら約 1/4 |
| モデル間の一致 | 精度の違うモデルが、同じ条件で同じ答えに近づく | スイッチングモデルの周期平均と状態平均化モデル |
| 保存則と整合、極限と角 | 切り替え点で状態変数が連続、極端な条件で壊れない | — |
| 再現性（必須） | 同じ入力から同じ結果 | 2回実行して完全一致 |
| 速度（記録） | 桁で遅くなっていない | `benchmarks/` |

許容差は先に決めてから測る。期待値は実装と独立に作る（解析解は試験の中に式で書く）。

### 13.2 独立検証とゲート

- 作業単位は、仕様 → 実装 → レビュー → 独立検証 → UX 確認 → 統合 の順に進める（`milestone-cycle` スキル）。
- 実装した本人は、その成果の検証役を兼ねない。検証担当は `tests/acceptance/` に受け入れ試験を足し、`docs/verification/` に記録を残す。
- 「完了」と報告するのは、独立検証を通った後（D-022）。
- ゲートの記録と統合は `scripts/cycle.py` が担い、条件を満たさない統合を拒む（D-014。`harness.md` 2章）。ゲートの結果は、そのとき見ていた内容と一緒に記録し、後で内容が変わったら無効になる。
- `main` は常に `python scripts/check.py`（ruff と pytest）が通る状態にする。
- 文書だけの作業単位は、仕様の見出しでゲートを絞れる（S1 は implement と check）。

### 13.3 Windows での確認

- 動作環境は Windows も対象（D-026）。OS の違いが出やすい作業（`scripts/`、ファイルの読み書き、文字コード、プロセスの起動、画面）には、仕様の見出しに `needs_windows: true` を付ける（D-032）。数値計算だけの作業には付けない。
- 確認は、PO の PC で `python scripts\local_ci.py --ref origin/<ブランチ>` を実行し、結果のファイルを `cycle.py record-ci` で取り込む（D-031）。
- GitHub 上の自動テストは、手で起動したときだけ走る。

### 13.4 再現性と、試験の安全

- 計算の経路は決定的（決まり1）。乱数を使うところ（予定の最適化）はシードを固定する。
- 試験から本物の `claude` を起動しない（決まり11、D-033）。`tests/conftest.py` が PATH から `claude` を外し、見張り役を置く。
- 画面のビルド結果とソースの食い違いは、Node.js のある環境の確認で調べる。無い環境では、調べなかったことを記録に残す（D-041）。
- 画面の文言と色の直書きが無いこと、依存のライセンスが一覧にあることを、自動の試験で確かめる（統合前（A0））。
