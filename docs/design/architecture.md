# 全体設計

最終更新: 2026-11-14

## 1. データの流れ

```
設計書（Word / PDF / Excel / テキスト）
   │ 取り込み（コード）            ingest/
   ▼
共通テキスト（位置ラベルつき）
   │ 仕様抽出（AI）                ai/
   ▼
仕様JSON 層A ─► 検証（コード） ─► 人が確認・修正      app/（確認画面）
   │ テンプレート展開（コード）    templates/
   ▼
ネットリスト 層B ＋ 制御ブロック
   │
   ├─► 平均モデル ─► ゲイン最適化                     tuning/
   └─► スイッチングモデルで最終確認                   エンジン
   ▼
結果 ─► スコープ表示、レポート、説明文（AI）          app/ ai/
```

AIが関わるのは「仕様抽出」と「説明文」だけ。それ以外は決定的なコードで、同じ入力なら同じ結果になる。
AIが無くても、層Aを手で書けば残りはすべて動く。

## 2. パッケージ構成（目標の形）

```
circuit_sim/
  ir.py               層A（Spec）と層B（Netlist）のスキーマと検証
  mna.py              ネットリスト → 回路方程式 E x' + G x = B u
  kernel.py           時間ステップ核（配列と数値だけ）
  simulate.py         計算の入口と結果
  control/            制御ブロック、PWM、制御器の型            [E1a, E1b]
  templates/          層A → 層B の展開と平均モデル（T0〜T3）
  tuning/             評価関数、線形化、安定余裕、最適化        [E2]
  ingest/             各形式 → 共通テキスト、正規化            [I1]
  ai/                 プロバイダ層、抽出、説明、応答キャッシュ  [I2]
  app/                ローカルサーバー（API）、同梱する画面、起動コマンド [A0〜]
frontend/             画面のソース（React + TypeScript）。ビルド結果を app/static/ に入れる
tests/                単体テスト、解析解との照合
tests/acceptance/     受け入れ試験（検証担当が追加）
benchmarks/           速度の計測
docs/                 計画、設計、決定、検証の記録
```

依存の向き: `app` → `tuning` / `templates` / `ingest` / `ai` → エンジン（`simulate` → `kernel` / `mna` → `ir`）。
エンジンは上の層を知らない。`ai` はエンジンを呼ばない。

## 3. 仕様の2層

- **層A（Spec）**: テンプレート名、パラメータ、目標値。AIが出力するのはここだけ。どの値も `null` を許し、出どころ（`source`）を持つ。足りない値は `missing` に並べ、人に聞く。
- **層B（Netlist）**: 素子と接続。層Aからコードが展開する。エンジンが読むのはここ。

将来、機構（外部の機構ファイルへの参照、関節とモーターの対応）は `schema_version` を上げて層Aに足す。

## 4. エンジン

- 方式: 理想スイッチによる区分線形モデル。修正節点解析＋固定刻みの台形則。
- 回路方程式は `E x' + G x = B u`。回路状態（スイッチの組）ごとに行列を一度だけ用意して使い回す。
- 不連続点（計算の先頭、電源のステップ、スイッチの切り替え）では、状態量（コンデンサ電圧、インダクタ電流）を連続に保つ。その直後は、細かく分割した後退オイラーを既定で2回入れて硬い成分を減衰させる。スイッチの無い回路では、刻みが最速の時定数の半分を超えるときだけ入れる（それ以下では台形則だけで誤差が1%未満。注意は時定数の2倍を超えるときに出す）。τ/2 < h ≤ 2τ の範囲では、減衰ステップが入るかどうかが刻みで変わるため、刻みを半分にしたときの誤差の減り方が台形則の2次（約1/4）どおりにならないことがある（誤差そのものは RC のステップ応答で 0.5% 以下）。
- 記録の決まり: スイッチやダイオードが切り替わる格子点では切り替わる前の値、電源がステップする格子点では変わった後の値を記録する。ゲート・指令・導通の信号は区間 [t[k], t[k+1]) の値。
- 刻みが粗いとき（最速の時定数や振動の周期を解像しない）は、結果の `notes` に注意を出す。スイッチを含む回路では、計算で使った回路状態ごとに調べ、オフ抵抗が作る見かけの成分は除く。インダクタ電流が行き場の無いまま遮断された点も注意に出す。ステップ数には上限があり、超えるときは計算の前にエラーにする。
- 層Aの単位は `units.py` が読む（接頭語は換算、次元違いと読めない単位はエラー）。核には単位の処理を入れない。
- 解けない回路（浮いた部分、電圧源ループなど）は、計算の前に検出してエラーにする。
- 核の決まり: 最内ループは配列と数値だけ。回路の解釈は核の外。こうしておけば Numba や C / C++ / Rust に載せ替えられる。
- **指令で値が決まる電源**（`ir.Command`）: 値 = gain × 指令（lower〜upper で止める）の電圧源。指令は制御器の出力の名前で引き、制御周期の頭で変わって次まで一定（区分一定）。`simulate` は制御周期ごとに電源の配列（`u_start`、`u_mid`、`u_end`）を埋め、値が変わる点を電源の不連続点（`event`）にする。核から見ると、時刻で決まる電源と同じ配列と数値で、指令の考えは核に入らない。値が変わった点の数は `stats["command_changes"]` に、回路状態の変化（`state_changes`）と分けて数える。
- **ブリッジのレグ**（`templates/legs.py` の `HalfBridgeLeg`）: 上下のスイッチの組を1つの部品として、精度を選んで層Bに展開する。
  - スイッチング: 上下のスイッチと、相補のゲート（`Pwm` の `complement`。デッドタイム0）。上のスイッチのデューティが指令。
  - 平均: 電圧源 `d × Vdc`（指令は 0〜1 で止める）とオン抵抗 r_on の直列。相補のゲートでは、どちらのスイッチが導通していても出力の経路にオン抵抗が1つ入るので、周期平均は `v(出力) = d·Vdc − r_on·i_out`。直流電圧は仕様の値で、電源が硬い（インピーダンスが無い）前提。入力側にインピーダンスがある回路と入力の電流は、スイッチングモデルで見る。
  - 両者の周期平均は、同期整流（電流が負になれる）なので、どの負荷でも一致する。オン抵抗を平均モデルに入れないと、Q の高い過渡で減衰が r_on/(2L) 遅く、基準の降圧（Q = 8.75、デューティ 0.5 固定の起動）で周期平均が Vref の 0.46% 違った。入れると 0.065%（残りは平均化そのものの誤差）。閉ループの差（受け入れ基準4）は 0.10〜0.12% のまま。
- **精度の切り替え**: 仕様の `simulation.fidelity`（`switching` / `average`。省略するとテンプレートの既定）。降圧コンバータの刻みの既定は、スイッチングがスイッチング周期の 1/200、平均が 1/10（ステップ数は約 1/20）。スイッチの無いテンプレート（`rc_lowpass`、`rlc_series`）はモデルを選べないので、指定を使わず、そのことを注意に出す。理想（トルク源＋電流応答の一次遅れ）は将来。
- **搬送波の既定は三角波**（オンの区間が周期の中央）。オンの区間の重心が周期の中央に来るので、周期の中で一定の電圧を出す平均モデルと時間がそろい、デューティの小さな変化の遅れもどのデューティでも保持の 0.5 サンプルになる（ゲインの設計の前提と同じ）。のこぎり波（周期の頭でオン）では重心が (1 − D)·T/2 早く、固定デューティ 0.5 の起動で周期平均が平均モデルより約 3% 先に進む。
- **三角波の測定点のずれ**（物理として正しい効果。直さない）: 制御器は周期の頭、三角波ではオフの区間の中央で測る。そこではインダクタ電流が周期平均に等しく、コンデンサ電圧はリプルの山の頂点にある。積分のある制御では頂点が指令値に合うので、スイッチングモデルの定常の周期平均は指令値より `ΔI·(1 + D)/(24·f·C)` 低い（ΔI = (Vin − Vo)·D/(L·f)。D = 0.5 では ΔI/(16·f·C) = ΔV/2）。基準の回路で式 7.98 mV、実測 7.96 mV。Vref 6 V（D = 0.25）で式 4.99 mV、実測 5.09 mV（刻み T/800 で 4.99 mV。差はデューティの分解能による）。平均モデルにはリプルが無いので、ずれない。両モデルの差（受け入れ基準4）の大半はこの分。
- モーターの負荷は差し替え式: モーターは「トルクを出し、角度と速度を受け取る」口を持つ。最初の相手は固定の慣性と摩擦、将来は物理エンジン。

## 5. 制御とゲイン最適化

- 制御器は離散時間。制御周期ごとに測定して演算し、次の周期の頭で反映する（1サンプル遅れ）。PWM はデューティを搬送波の周期の頭で取り込んで周期のあいだ保持する（零次ホールド。0.5 サンプル）。余裕の計算には、この 1.5 サンプルを必ず入れる。
- PID（`control/blocks.py`）: 並列形 `u = Kp·e + Ki·Ts·Σe + D`。微分は `Kd·s/(1 + Tf·s)` の後退差分。出力の上下限と、積分の飽和を防ぐ処理（積分を進める前の出力が上下限に張り付き、偏差がさらに張り付く向きなら積分しない）。微分は偏差に掛ける（既定）か、測定値に掛けるかを選べる（`derivative_on`）。測定値に掛けると、指令値の段差で出力が跳ねない（基準の回路の 12 → 10 V の段差で、デューティの変化が 0.465 から 0.026 になる）。帰還の経路は同じなので、開ループと余裕は変わらない。テンプレートの項目には出していない（E2 で決める）。
- ゲインの初期値（`tuning/initial.py`）: 平均モデルの小信号の伝達関数を零次ホールドで離散化し、z⁻¹ と PID の差分方程式の z 変換を掛けた開ループで設計する。位相は低い周波数から連続に取る（開ループの根ごとの偏角の和で計算し、格子の細かさによらない）。主値の atan2 を 180° に足すと、−180° を下回った位相が折り返して大きな正の余裕に見え、不安定なゲインを「目標以上」と読む（以前の不具合。20 kHz で真の余裕 −106°、極の半径 1.44 のゲインを 254° として返していた）。返す前に、ゲインが 1 を横切るすべての点（設計した点を含む）の余裕の最小が目標以上（目標 − 1e-6° まで。二分法の丸めの分。最良の候補の文言の「満たす」も同じ判定 `meets_target`）、離散時間の閉ループの極の半径が 1 − ε 以下（ε = 1e-9。固有値の丸めは 60 桁の照合との差で最大 1.1e-11 なので、その約 100 倍。1 との差が ε 未満は丸めで安定か不安定かが変わるので、理由 `no_stability_margin`「安定の余裕が無い」で断る）、交差周波数が探索の範囲の端でないことを確かめる。ゲインが 1 を横切る点は、格子の符号の変わり目で探さず、囲い込みで求める: 区間ごとに、遠い根の項は傾き Σ 1/距離 と曲がり Σ|r|/距離² で、区間の半幅の2倍より近い根の項は値の上下限 log(距離の下限)〜log(距離の上限) で抑え、|log|L|| が 0 になりえない区間を捨てる。傾きが区間の中で 0 にならない（単調な）区間は、端の符号で交差の有無を決めて二分法で詰める。どちらとも言えない区間を幅が θ の 1e-12 倍になるまで二分する（近い2つの交差を格子の1区間で見落とさない。|L| が 1 に接するだけの点も余裕を小さく見る側で数える）。θ の 1e-9 倍より近い交差は、余裕が最小の1つにまとめる（丸めで符号が揺れる点を数えない）。単位円にごく近い根（負荷抵抗がとても大きいときの植物の零点 z ≈ −1 や極）を値で抑えないと、その区間が残り、|L| が 1 から遠い点を交差と読む（以前の不具合。R = 1e11 Ω で余裕 −267.7° と読んで断っていた）。開ループは因子の形（極は積分・フィルタ・Δ = Ad − I の固有値・遅れ、零点は PID と植物の分子の根）で計算し、根は z = 1 からのずれで持つ（PID の分子も z − 1 の多項式で解く。z の多項式の根では、零点が重根に近いと誤差 √u ≈ 1e-8 が 1 との差を超え、低い周波数の交差を落とした）。根ごとの |r|² − 1（単位円の内外で連続な位相の数え方が変わり、単位円までの距離は囲い込みの下限に使う）は、複素数の組なら積から与える: 植物の極は det Ad − 1 = expm1(−Ts/(R·C))、PID の零点は −Ts·(Kp + Ki·g)/a2。2·Re x + |x|² で作ると、負荷抵抗がとても大きい（Q ≳ 1e16）とき真の値 −Ts/(RC) が固有値の丸め（約 1e-17）に埋もれ、安定な植物の極を外側と読んで位相が 360° ずれた（以前の不具合。不安定な候補を「満たす」と書き、成功する設計を断った）。閉ループの極は状態遷移行列の固有値で求める。|N(z)|² = |D(z)|² を多項式にして単位円の上の根を取るやり方も試したが、LC の共振が制御周波数よりずっと低いと根が z = 1 の近くに集まって精度が落ち、乱数で選んだ 1,059 通りのうち 16 通りで交差を落とした（囲い込みでは 0 通り）。設計の引数は `ARGUMENT_RANGES` の範囲（両端を含む）で確かめ、外、NaN、inf、数でない値、倍精度にできない値（10**400）、倍精度で 0 になる値は計算せずに invalid_argument で断る（numpy の数は受け、倍精度に直してから比べる）。範囲は実用の値の外側に3桁ほどの余裕を取った、物理として意味のある範囲: Vin 1 µV〜1 GV、L 1 pH〜10 kH、C 1 fF〜1 MF、R 1 µΩ〜1e30 Ω（1e30 Ω は無負荷を表す値）、制御周波数 1 mHz〜1 THz、零点の比 1e-9 ≤ κ ≤ 1、減衰 0 < ζz ≤ 2、微分のフィルタの比 0〜1000、目標 0° < PM < 180°、探索の上端は正の有限値。κ > 1 は零点が共振の上に来て、共振と零点の間で |L| > 1 のまま位相が −180° を下回る（条件つき安定）ので断る。探索の上端はナイキスト周波数の手前までに制限し、制限したことを結果（`PidGains.f_cross_max_limited_from`）と失敗の文に残す。満たせなければ `GainDesignError`（`ValueError` の一種。理由のコード、目標、最良の候補とその余裕・極の半径）を出す。最良の候補を「目標を満たす」と書くのは、受け入れと同じ判定 `meets_target`（余裕が有限で、目標 − 1e-6° 以上）のときだけ。交差周波数の探索の「余裕が目標以上の区間」も同じ判定で決める。本文の「取れるのは最大 …°」と閉ループの極の半径は、判定と食い違わない桁で書く（目標に届かない最大を目標以上に丸めない。安定と判定した半径を「1.0000」と書かない）。戻り値に「達成したか」の印を持たせる形にしなかったのは、印を見ずにゲインを使うと不安定なゲインがそのまま使われるため（決まり4）。
- 最適化の手順: 解析式で初期値 → 平均モデルで評価関数を最小化 → 線形化した開ループから安定余裕を計算して制約にする（遅れ1.5サンプルを含める）→ スイッチングモデルで確認。
- 評価関数 = ITAE ＋ ペナルティ（オーバーシュート、整定時間、余裕不足、操作量の飽和、電流制限）。目標値の種類は部品として足せる形にする。
- 満たせない目標には、最良のゲインと「どの目標がどれだけ未達か」を返す。
- 同じ仕様からは同じゲインが出る（乱数のシードを固定）。

## 6. 取り込みとAI

- どの形式も、コードで「位置ラベルつきの共通テキスト」に変換してからAIに渡す。AIに元ファイルを読ませない。
- 読めないページ（スキャンPDF、図）は「読めなかったもの」として確認画面に出す。
- プロバイダ層は `extract(共通テキスト, スキーマ) → 層A` と `explain(結果) → 説明文` の2つだけを公開する。最初の実装はローカルのCLIをヘッドレスで呼ぶ方式。APIキーやローカルモデルにも差し替えられる。
- 同じ入力への応答はキャッシュする。テストは記録した応答で行い、本物のAIを呼ばない。

## 7. アプリ

- 形: 利用者のPCでローカルサーバーを起動し、ブラウザで操作する。コマンド1つで起動してブラウザが開く。オフラインで動く。
- サーバー: FastAPI。画面: React + TypeScript（Vite）。波形: uPlot を自前の Scope 部品で包み、後で差し替えられるようにする。
- 画面のビルド結果をPythonパッケージに同梱する。利用者に Node.js は要らない。
- 波形は、サーバー側で画面の横1列ごとに最小値と最大値に間引いて送る。拡大・縮小のたびに表示範囲だけ間引き直す。
- 利用者のデータは端末の外に出さない。例外はAIへの抽出依頼だけで、送る内容を事前に画面で示す。
- 詳細は `app-design.md`。

## 8. 速度の目安（簡易モデルでの実測）

| 項目 | 値 |
|---|---|
| 20万ステップ、Pythonのみ | 69 ms |
| 同、Numba | 2 ms |
| 2000万点 → 画面2000列への間引き | 23 ms |

改善の順番: 計算量を減らす → 最適化の評価を並列に走らせる → 核を Numba でコンパイル → それでも足りなければ C / C++ / Rust。

## 9. 将来（機構・ロボット）

3次元の物理は自作せず、既存の物理エンジン（第一候補 MuJoCo）に任せる。このツールはアクチュエータ（モーター＋減速機＋駆動回路＋制御）とそのゲイン設計を持つ。
そのための備えは 3章（層Aの拡張）と 4章（負荷の差し替え、精度の切り替え）に入れてある。
